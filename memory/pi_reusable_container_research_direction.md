# 物理互联网下循环 pi 容器论文方向备忘

## 背景判断

当前项目主线是 2E-VRPTW-PDD：中央仓、卫星站、顾客的两级路径优化，包含配送与回收任务。此前为了贴合物理互联网思想，引入了可循环容器和客户间中转机制；但大量实验显示，客户级中转的收益很差，甚至容易干扰 ALNS 收敛。

后续如果继续围绕物理互联网展开，不建议把研究重点放在客户间中转。更合理的方向是把 pi 容器视为可复用、标准化、可追踪的物流资产，研究其在两级城市物流网络中的周转、库存、补给、回收和再平衡。

核心转向：

> 从“车辆路径最短”转向“路径优化 + 容器池周转 + 前置仓库存平衡”的联合优化。

## 推荐论文题目

中文题目候选：

- 物理互联网下考虑循环 pi 容器周转的两级城市物流路径优化研究
- 考虑循环容器池周转的两级库存路径联合优化及学习增强 ALNS 算法研究
- 基于物理互联网的城市生鲜循环容器配送与回收协同优化研究

英文题目候选：

- Two-Echelon Vehicle Routing with Time Windows and Reusable pi-Container Circulation in Physical Internet City Logistics
- Joint Routing and Inventory Optimization for Reusable pi-Container Circulation in a Two-Echelon Physical Internet Network

## 核心研究问题

在物理互联网城市物流网络中，如何联合优化 pi 容器的补给、配送、回收、清洗再投放、前置仓库存平衡与车辆路径，从而降低总运营成本并提高容器周转效率？

可以拆成几个子问题：

- 每个前置仓初始应配置多少清洁 pi 容器？
- 中央仓应在什么时间向各前置仓补给多少容器？
- E2 车辆如何同时完成门店配送和空容器回收？
- 回收容器是否需要返回中央仓清洗，清洗后何时重新进入系统？
- 当前置仓缺箱时，是补给、调拨，还是使用一次性包装替代？
- 容器池规模、缺箱率、运输成本和服务水平之间如何权衡？

## 建议模型结构

### Model A：传统两级配送模型

作为 baseline。

- 只考虑配送任务
- 不考虑容器回收
- 不考虑循环容器成本
- 对比一次性包装场景

### Model B：两级循环容器取送货模型

接近当前 Model 3。

- 顾客接收装载商品的可循环容器
- 顾客产生空容器回收任务
- E2 车辆同时服务 delivery 和 pickup
- E1 车辆负责中央仓与前置仓之间的配送和回收汇集

### Model C：考虑 pi 容器池周转的多周期模型

作为真正的论文核心。

新增内容：

- 前置仓清洁容器库存
- 前置仓待回收容器库存
- 中央仓清洗/分拣能力
- 容器清洗与再投放延迟
- 容器池总规模约束
- 缺箱惩罚或一次性包装替代成本
- 多周期库存平衡约束

### 可选 Model D：前置仓间空容器再平衡

该方向不同于此前的客户间中转。

客户间中转是低层级的路线操作，实际收益差、执行复杂；前置仓间空容器再平衡则更符合物理互联网 hub 网络思想。

典型场景：

- 前置仓 A 回收容器多，但配送需求少
- 前置仓 B 配送需求多，但清洁容器不足
- 系统允许通过 E1 或再平衡车辆在前置仓之间调拨空容器

对比策略：

- 不允许再平衡
- 只允许中央仓统一补给
- 允许前置仓间空容器调拨
- 允许动态补给与调拨

## AI / 强化学习切入点

不建议端到端用深度学习直接生成路线。对当前代码和硕士论文风险而言，更稳妥的是分层求解：

- 高层 RL：决定每个周期各前置仓补多少箱、是否调拨、调拨方向
- 底层 ALNS：给定补给/调拨方案后求车辆路径

状态可以包括：

- 各前置仓清洁容器库存
- 待回收容器库存
- 当期配送需求
- 预测回收量
- 缺箱次数
- 上一周期车辆成本
- 容器池利用率

动作可以包括：

- 中央仓向各前置仓补给数量
- 前置仓间是否调拨
- 调拨方向和数量
- ALNS 算子或参数选择

奖励可以包括：

- 负总成本
- 缺箱惩罚
- 车辆行驶成本
- 容器闲置成本
- 服务失败惩罚
- 碳排放成本

更稳妥的 AI 版本：

> RL 只做 ALNS 算子选择或高层补给策略，路线仍由 ALNS 负责。

## 推荐应用场景

最推荐场景：

> 城市连锁生鲜零售网络中的标准化循环周转筐配送与回收。

网络结构：

- 中央仓：农产品批发市场或中央冷库
- 前置仓：城区分拨仓、冷链前置仓、社区配送站
- 顾客：生鲜超市、社区团购点、农贸市场、便利店
- 容器：蔬菜周转筐、冷链保温箱、标准化可循环箱

该场景的优势：

- 生鲜配送天然使用周转筐
- 门店收货有明确时间窗
- 空筐回收具有现实意义
- 前置仓作为 PI-hub 容易解释
- 可以做路径成本、容器成本、清洗成本、丢失率和碳排放分析

备选场景：

- 医药冷链循环保温箱配送
- 连锁餐饮中央厨房配送
- 校园或社区共享循环快递箱
- 商超 B2B 周转箱配送与回收

推荐北京案例：

## 论文贡献可以这样写

1. 构建物理互联网场景下的循环 pi 容器两级配送与回收路径优化模型。
2. 引入容器池规模、前置仓库存平衡、清洗分拣延迟和缺箱惩罚，刻画循环容器周转机制。
3. 设计 ALNS 或 RL-ALNS 求解算法，提高大规模算例下的求解质量和稳定性。
4. 基于真实 POI 空间分布构建城市生鲜仿真案例，分析不同容器池规模、丢失率、清洗成本和包装价格下的经济性。

## 重要判断

如果只做“配送 + 回收 + 经济性分析”，论文会显得偏简单。

要让这个方向有深度，必须至少加入以下一个核心机制：

- 多周期容器库存平衡
- 容器池规模决策
- 清洗/再投放延迟
- 缺箱惩罚或一次性包装替代
- 前置仓间空容器再平衡
- RL 高层补给/调拨策略

最稳妥的主线是：

> 物理互联网下 pi 容器池周转与两级配送回收路径的联合优化。
