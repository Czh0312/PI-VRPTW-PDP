# M6–M8 共享二级任务状态的等价重构

每个订单的配送任务和回收任务都由唯一一个行程访问。记二元访问变量为 v[r,i]，并有 sum_r v[r,i] = 1。

对客户任务之间的弧增加全局二元变量 X[i,j] = sum_r x[r,i,j]。原模型每个任务的入度/出度均等于对应行程访问变量，所以任一合法整数解中这个和只能为 0 或 1。共享的时间、载重和因果顺序约束仅在 X=1 时激活。卫星出发和返回弧仍保留逐行程的时间、载重初始化和终止约束。

进一步把内部弧的逐行程副本 x 放宽为 [0,1] 连续变量仍保持整数解集：任务 i 只属于唯一行程 r*，其他行程的出度为 0，因此它们的所有出弧均为 0；于是 x[r*,i,j] = X[i,j]。这依赖访问变量和 X 仍为二元，且保留逐行程流平衡及全局任务唯一覆盖。

每个任务的服务后载重也只存在一份物理状态，因而可由所有行程共享。行程间不会传播载重；每个行程第一项任务的载重，仍由该行程所有配送任务的总装载量独立初始化。

对分批连接，以二元 s[r,b] 表示行程配送批次。保留 sum_b s <= used，并添加 sum_b s <= sum_配送任务 v，以及 s[r,b] >= v[r,i] + y[i,b] - 1。若行程含配送任务，它的实际批次必然被选中；两个不同配送批次会违反最多选择一个批次。若只有回收任务，所有 s 必须为 0。这消除了逐行程、逐订单、逐批次的辅助 AND 变量，但不改变合法分批方案。

M7 的延迟装载变量及库存释放时间使用原模型语义。三个编号各自保留本地实现，无交叉编号导入。

默认根据输入估算二级内部弧副本数：sum_s [n_s (n_s-1) min(T,n_s) V_s]，n_s 为该卫星的配送与回收任务数。估计超过 4,000 时启用压缩形式；否则保留展开形式。这是工程策略选择，不是可行域限制或复杂度定理。软提示随压缩形式启用，较小模型保留既有部分初解搜索。
