## 二、发现并修复的实际问题

### 1. 原固定参考日历有两例不可行

原M5使用三批、每批260分钟、75%配送分界，最后回库和清洗只剩65分钟。原M03/M5经Gurobi精确后端判为INFEASIBLE；M03和L09在30秒、seed=42/43的四次ALNS补试中也都未找到解。L09的45秒精确调用是TIME_LIMIT，不能把它写成精确求解器已证明不可行。

另做独立的末轮回库下界检查：先识别必定来不及在上一批回库的仓点，枚举末批一级车辆的乐观回库覆盖。该松弛忽略容量、竞争、额外回收及配送路径限制，允许车辆在有配送的末端仓或总仓等候分界。因此它给出的是**回库加清洗时间的下界**：

| 原算例 | 乐观回库清洗下界 | 原可用时间 | 结论 |
| --- | ---: | ---: | --- |
| M03/M5 | 67.65分钟 | 65分钟 | 即使松弛也来不及 |
| L09/M5 | 66.97分钟 | 65分钟 | 即使松弛也来不及 |

这为两例固定日历不可行提供了不依赖ALNS成败的解释。详见[54项新旧下界核验](last_recovery_certificates.json)及[检查程序](../../../tools/audit/check_last_recovery.py)。下界检查通过本身仍不是整体可行证明。

修订统一应用于全部27例：参考分界从75%改为70%，每批配送阶段182分钟、回库阶段78分钟。三批起点保持08:00、12:20、16:40，截点为11:02、15:22、19:42，周期仍为08:00–21:00。M1–M4同步保留相同最终截点19:42。M6–M8的参考日历同步更新，其分界仍是优化变量。

需求、原订单参考分批、车队、网络、费用、送取窗及清洗时长均未改变。修改是一次公开的可行性修复，不是最优分界标定。没有尝试筛选“哪个比例让新模型赢得最多”。[逐例输入差异核验](revision_diff.json)确认公共物理输入未改，原数据完整保存在dataset_before_revision2.zip。

### 2. 原K=1…390包含大量可证明无效的候选

保留共同数学允许域，先从输入证明两类上界：

- 每个实际配送批次至少包含一个不可拆分订单，所以K不超过订单数。
- M6/M7等长批次的第一批必须完成至少一次当前周期的回库。令H为周期长度、R为忽略竞争和容量后的最早可能回库耗时，则H/K≥R，故K≤floor(H/R)。行驶下界使用最短路径，保留原有物理时间舍入；不依赖求解结果。

M8的首批长度可变，不能套用等长上界；对它保留订单数和阶段长度给出的上界。最终M6/M7每例保留3–5个K，M8每例保留7–100个K。81份联合模型配置的候选总数从31,590降至1,243，约减少96.1%。**被去掉的K已有不可行性证明，留下的K不因此保证可行或最优。**

每例shared/batch_count_certificate.json记录逐单下界、假设和候选范围，审计重新计算并拒绝未经证明的截断。没有把历史的K={1,2,3}直接当作完整域。

### 3. 从“能加载”升级为“有可重放的可行调度”

发布数据包含[validation](../../../data/formal_benchmark27_v1/validation/README.md)：216份显式调度，全部通过独立重放，检查订单覆盖、车辆资源、时间窗、使用时长、箱量守恒、回库清洗及周期闭合。

M1/M3/M5由确定性构造生成；M2/M4采用允许的原分仓选择；M6–M8将M3的可行单批调度映射进各自完整约束后重新审计。这些是**存在性见证**，不是最优解或算法胜率；联合模型见证采用K=1、N=Q，也不证明循环收益。主求解器不会自动读取它们作为初始解。

## 四、“低箱池费用”到底是什么

当前主数据使用合成费用，不能把数值理解成元或真实公里费用。

| 项目 | 当前计费 | 对减少实体箱数N的影响 |
| --- | --- | --- |
| 箱池占用费 | 5×N／运营周期 | N减少才直接节省这一项 |
| 箱子磨损／按次折旧 | Q×购买价10／寿命50，即0.2×Q | 同一需求Q下相同，不随本次N改变 |
| 初始箱池购买投入 | 10×N，单独报告 | 不再重复加入当前周期总目标 |
| 清洗、跟踪 | 回库箱次×0.2、使用箱次×0.1 | 完整闭合且Q相同，通常是相同常数 |
| 距离、占用车辆工时、车辆与趟次 | 按实际调度计费 | 多批可能增加，也可能通过安排改变 |

因此“低”是指**每只箱每周期的占用费相对于额外运输和作业成本低**，不是仅说购买价低，也不是全部费用低。

修订后27例的M6–M8三秒试跑，以及9例的20秒试跑，均选择K=1、N=Q。S01三个联合模型的精确结果进一步证明：当前费率5下，K=1、N=12、成本546.414是各自允许域中的最优值。因此至少S01的单批结果不能归咎于搜索时间不够。

为了诊断机制，仅对相同三例做运行时费用覆盖，主数据不改、不新增基础算例：费率20时9次仍选单批；费率100时9次都选多批且N<Q。例如10秒诊断的M6：S01由12只变为7只，M01由32只变为19只，L01由78只变为53只。

S01在费率100下的精确诊断：M6为K=2、N=7、最优成本1341.901；M7为K=2、N=7、最优成本1331.519；M8本次仅得到可行成本1352.885，不能据此说M8的模型可行域更差。原费率5的最优单批路线在费率100下计费为1686.414，显示运输与占用费之间确有权衡。

费率100是人工压力测试值，没有市场依据，也没有据此替换主参数。当前费用不应只因为“新模型优势不明显”而被调高。若后续需要把价格档位纳入主实验，应先确定业务计费口径或公开的合成设计，再冻结全部27例的配对规则。

## 五、这套数据的意义和边界

| 检查 | 结果 | 含义 |
| --- | --- | --- |
| 重复网络 | 27例27套网络 | 没有把同网络不同参数另算新基础例 |
| 来源相关性 | 14来源块，25对嵌套 | 必须保留source_block，不能按216独立样本推断 |
| 固定分仓已是最近仓 | 958/1017条订单记录 | M2/M4未必大幅改善；也可能只是安排与共享车辆收益 |
| 有多个宽松可行仓 | 1001/1017条记录 | 分仓决策没有被全部时间窗锁死；宽松可行不保证整体可行 |
| 最短使用时间被窗口自动覆盖 | 0/1017条 | 使用时间约束并非全部冗余；不等于每个最优解都紧约束 |
| 参考分界可影响回库批次 | 小38、中82、大227条记录 | 回库分界具有区分作用；这是逐单乐观指标 |
| 一级总需求／单车容量 | 约0.68–0.86 | 一级容量宽松，主要研究时序与循环，不是容量紧缺压力测试 |
| 晚释放订单 | 0 | 静态全信息场景，不能据此证明晚释放机制收益 |
| 预约窗口 | 统一90分钟送窗、105分钟取窗 | 控制了重复情景，但代表性有限 |

还必须区分两项模型差异：

1. M1–M5原生目标是距离，M6–M8是成本。统一成本重算有用，但不能替代“固定同一策略、只改变优化目标”的成本对照。一次性模型缺少对应包装价格，不能直接套循环箱池费用。
2. M5固定配送时段允许某个时段零回库，M6–M8则要求每个计数批次配送和回库均为正。19/27个确定性M5见证可直接映射成合法的K=3减池联合方案；其余8个见证有空回库时段，不能直接照搬。这个失败不证明那些案例没有其他可行多批方案。消融研究必须对齐批次业务定义，不能自动宣称M5就是M6的严格子集。

结论边界：现有27例足以检验共享输入、规模变化、分仓选择、静态时序和箱池—运输权衡。它不能替代真实成本标定、稀缺一级容量、晚释放订单和最终多种子模型比较。这些边界已写入正式数据的comparison_protocol.json。
