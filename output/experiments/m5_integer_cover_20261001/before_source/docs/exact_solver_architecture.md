# 精确求解范围

正式入口将 `multi_batch_cutoff_v1` 分发到各编号目录的 `exact/solver.py`。
M1/M3 为单批固定分仓；M2/M4 为单批自由分仓；M5 为多批固定分仓。
各模型的 MILP 建模入口位于 `exact/model.py`，共用实现位于 `models/routing/solvers/exact/`。
M2/M4 根据删弧及对称性处理后的实际展开规模选择联合分仓 MILP 或分仓域树；
联合模型直接覆盖全部合法顾客分仓，域树通过互不重叠的完整分支覆盖这些分仓。
完整分仓枚举保留为显式 `strategy='enumeration'` 对照。
求解器遵守输入的整数时间刻度及二级趟次上限；ALNS 位于独立 `alns/` 目录。

固定分仓只有完整 MILP 返回最优并且独立审计通过，才能报告 `proven_optimal=true`。
自由分仓要求联合 MILP 取得全局证明，或全部分仓域子树/枚举组合被最优、不可行证明或有效成本下界闭合。`BOUND_PRUNED` 仅表示不能改善
现有已审计可行解，不表示该组合不可行。限时可行解、未找到解与已证明不可行必须区分。

B=1 专门化将回收量固定为各仓全部订单箱数，直接约束带箱二级趟次在唯一截止前卸回，保留清洗末态。
另有基于安全时间界的弧删除、同质车辆对称性、分仓距离界剪枝、未闭合分区重访和经过独立审计的
MIP 初始解。详见 [2026-09-30 检查与对照](single_batch_solver_audit_20260930.md)。

第二轮在 B=1 下进一步共享二级任务的时间/载荷与内部弧传播约束，减少车辆、趟次之间的重复。
精确法内部的 `primal.py` 独立构造并审计初解，构造失败不证明不可行；建模或求解限时也保留已审计方案。
初解进入 MILP 前会重映射同质车辆编号，以满足对称性约束。算法不依赖 ALNS。
实验显示可行解覆盖率提高，但较大实例 gap 仍可能很大，详见
[第二轮优化与稳定性报告](solver_stability_optimization_20260930.md)。

第三轮将顾客级分仓变量、一级补货/回收量和二级任务覆盖纳入同一个线性整数模型。
同一顾客的全部订单共用分仓变量；每项二级任务仍只执行一次。较大实例保留完整枚举，
先做必要条件域删除，再按初始、近仓和单客户迁移顺序搜索，最后完整覆盖其余组合。
安全全局距离界覆盖尚未访问的分仓，不把某一固定分仓的下界当作自由分仓下界。
固定分仓热启动只提供已审计上界，其局部最优/不可行证明不传递给联合模型。
自动规模阈值、限时局限和同预算实验见 [第三轮联合求解报告](free_assignment_joint_optimization_20260930.md)。

M5 现已增加独立多批次初解：按实际二级卸箱确定截止回收量，安排一级回运与清洗，再独立审计整个周期。
二级任务时间、载荷和内部弧传播共享也已扩展到多批次，并增加基于放宽网络最短路径的安全时间界。
初解构造失败不证明不可行；完整 MILP 仍允许跨趟次、跨批回收。实现、等价性回归及同预算结果见
[M5 初解与紧凑建模报告](m5_exact_optimization_20260930.md)。

M5 后续将回收截止归属压缩为订单级状态，并增加容量启用关联、载荷界、合法弧筛选和
按需分离的订单子集容量割；完整业务约束仍保留。候选割及实际提交数量分别记录，
回调异常不能产生最优性证明。见 [M5 第三步强化报告](m5_exact_strengthening_20260930.md)。

M5 初解进一步扩展二层配送/回收插入，并在重建供货、卸箱和清洗时间后合并一层路线。
额外搜索计入原预算，只保留完整审计通过的改进，不改变 MILP 的可行域。
实现及初解策略消融见 [M5 可行上界优化报告](m5_exact_primal_quality_20261001.md)。

M5 二层时间、载荷、截止归属连接和因果关系进一步使用有效界直接线性表达，
同质车辆按整周期趟数排序后删除必然冗余的趟位副本。原可行时间表可通过车辆重编号进入新模型。
数学依据与验证见 [M5 预处理与根节点优化](m5_exact_root_20261001.md)。

M5 较大模型进一步将二层内部弧共享为全局二进制变量，以任务所属趟次和唯一入出度重建路线。
原因果序位仍排除零时间子环，边界弧、跨批回收及完整容器循环约束保留。
默认按预计内部弧副本数选择表达，数学对应与同预算对照见
[M5 内部弧压缩报告](m5_exact_routes_20261001.md)。

M5 默认增加基于有向距离闭包巡回和必需任务弧的独立距离下界，计算计入原预算。
结果分别记录 Gurobi 原始界、独立证书及最终有效界；证书不触发最优或不可行证明。
出仓载荷表达提取实验保持显式可选，默认不改 MILP 约束。见
[M5 距离下界与根节点诊断](m5_exact_bound_certificate_20261001.md)。

M5 的距离证书也可按一层批次、二层仓转成有效 MILP 约束，原目标的每条弧只累计一次。
默认仍仅报告证书，显式 `distance_cuts='components'` 开启分项距离行。
回归、有限预算的收益和退步见 [M5 距离证书约束](m5_exact_certificate_cuts_20261001.md)。

M5 另提供可选的 `route_cover_certificate`：以每仓二层路线覆盖 LP 和整数定价计算松弛下界，
保留任务覆盖、有限总趟数和完整趟内时间/载荷，放松实际一级同步、跨趟使用时长与清洗库存耦合。
按配送批次及纯回收分组的定价始终保留全部批次回收任务；限时使用有效对偶修正，合并原一级距离界。
它不产生完整周期方案或整数最优性标志，也不替换默认 MILP，见
[M5 列生成下界原型](m5_route_cg_20261001.md)。

M5 的 CG 证书可通过 `e1_time_limit` 显式增加一级路线与库存松弛，费用界取新旧一级界的最大值，
再与各仓二层证书相加。四个以内实际服务仓使用完整一级路线枚举，数量、供货必要时间、回收截止
及清洗库存留在整数主问题；更多仓使用一级弧模型。一级与二层计算共享原有总预算，
松弛最优不产生完整 M5 的整数证明，见 [一级整路线下界](m5_e1_inventory_20261001.md)。

M5 另提供已审计初解的 `reoptimize_e1`：固定二层访问序列，可联合调整一级路线和实际二层时刻，
保留同趟回仓、车辆准备/串行、截止数量及清洗库存。输出是完整可行上界，受限模型的界不用于
完整 M5 证明。`solve_exact` 的可选 `e1_polish_time` 在原总预算内生成热启动，后续仍求解完整模型。
同预算上下界口径与验证见 [一级与二级日程重优化](m5_e1_polish_20261001.md)。

M5 的 `reoptimize_route_pool` 进一步用整数主问题选择二层重排与跨趟转移候选，和一级路线、
真实车辆日程及容器库存共同优化。内部任务弧传播复用，因果序位排除零时间跨趟环，车辆串行
跨越未使用的中间趟位。有限候选池只输出审计合格的上界；可选 `route_pool_time` 热启动
计入完整 MILP 原预算，见 [二层路线池与同预算验证](m5_route_pool_20261001.md)。

M5 的路线覆盖证书可显式使用 `pricing_backend='hybrid'`，在原预算内完整枚举二层任务路径，
按任务集合保留最低成本路线，直接求解包含全部列的连续覆盖主问题。
只有完整路线域可以提供枚举定价证书；枚举达到状态/时间上限时回退到原完整 MILP 定价。
该选项默认关闭，LP 收敛不产生完整 M5 整数证明，见 [完整二层枚举与定价收敛](m5_enumerated_pricing_20261001.md)。

历史 M1–M4 的 indexed 和 commodity_flow 后端保存在 `models/routing/baselines/`，需要 `--baseline` 或 `allow_baseline=True`。这些证明只针对历史业务规则，不能作为新版四模型的证明。

第四轮将 B=1 建模隔离到 `single_batch_formulation.py`。`strengthening.py` 提供一级供货截止的
反向传播、实际载荷界、因果序位界和按趟数排序后的车辆槽位界；Gurobi 初解也按同样规则重编号。
联合模型阈值采用实际稀疏弧数 120,000；大模型进入 `assignment_tree.py`，对分仓子树整体
求解或剪枝，未解决子树始终保留在全局下界中。限额内的初解候选不会限制精确搜索域。
数学依据、回归及同预算结果见 [单批精确优化记录](single_batch_exact_strengthening_20260930.md)。

第五轮增加 `single_batch_primal.py`：配送可跨多趟，回收可插入配送趟次之间或兼容的现有路线。
插入时重算同车后续趟次，保留供货、准备、周转、使用时长、时间窗、载荷及回仓截止。
先固定配送日程再插入回收是初解构造范围，完整 MILP 不受此限制；只有独立审计合格的
完整方案才作为上界。分仓初解先作便宜的广度探测，再细化少量候选，均计入原有预算。
详见 [第五轮初解改进与对照](single_batch_exact_primal_20261001.md)。

第六轮在 `single_batch_formulation.py` 中按规模选择二级内部弧的表达：较大的模型将每项
任务的唯一入弧、出弧与唯一车辆/趟次归属分开表示，选中的内部弧要求两端任务属于同一路线。
每趟起终弧仍独立，原因果序位排除所有断开的环，保留物理车辆串行约束。
Gurobi热启动按全局弧统一设置，解提取时按任务所属路线筛选这些弧。
这一变换压缩变量，不能保证每个案例均更快；数学对应与完整对照见
[第六轮路线弧压缩](single_batch_exact_route_compression_20261001.md)。

第七轮在 `single_batch_cuts.py` 中对单批订单子集分别计算配送、回收所需路线数，并约束子集内部弧总数。
回调仅在根节点分离违反的有效不等式；默认用于含回收的压缩模型，小型索引与纯配送模型保持原路径。
这些割不假设度量距离，也不禁止跨趟回收。数学证明、同初解/同工作量对照与限时退步见
[第七轮容量割](single_batch_exact_capacity_20261001.md)。

第八轮在单批专用模型中以有效上下界表达二级时间、载荷、归属、因果序位及准备/截止连接。
压缩模型新增每趟两个出发载荷辅助变量，通过等式复用配送载荷求和，减少重复展开的系数。
固定分仓含回收的索引模型只切换连接表达；其余索引模型保留原路径。
保留组件对照与关闭选项，不改变整数可行域、有限车队和最优性标准。
详见 [第八轮有界连接与载荷复用](single_batch_exact_linear_20261001.md)。

第九轮按任务的实际路线成员集合收紧连续归属的上下界，并据此推导两侧内部弧失活系数；
不新增变量、约束或整数限制。建模阶段缓存每项任务在各仓点的访问求和，保持原有求和次序。
`single_batch_site_flow.py` 提供显式仓库流诊断：全局二元弧按仓点分解为连续流，仓点任务度数等于顾客分仓变量。
该表达保留全部整数可行解，但限时和多种子结果出现退步，因此最终默认关闭。
详见 [路线编号界、建模缓存与仓库流诊断](single_batch_exact_domains_20261001.md)。
