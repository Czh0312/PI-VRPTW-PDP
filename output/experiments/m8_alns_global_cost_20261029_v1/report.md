# 模型八 ALNS：必要分批域与完整费用修复

九例、根种子42、每次5秒预算的配对冷启动实验已完成，采用 `bounded` 候选。平均 GAP 从 **6.0756% 降到 3.6220%**，下降 2.4537 个百分点；最差 GAP 从 **14.3230% 降到 10.1902%**。5例改善、2例持平、2例退步，双方均为9/9可行并通过两周期审计，最优值命中均为 **0/9**。

这是单种子、墙钟预算下的结果，不代表多种子稳定性。完整费用精修可保持传入解不变或改进，但整段搜索重新分配了时间和提案，因此个别算例仍会退步。

## 已采用的改动

1. 不超过9单时，从时间窗、最短路行驶下界、最早回仓和最晚装载推导必要分批域，结合前序回收箱量、非空批次匹配和箱池下界。仅有必要条件证书才终止对应K；原始K=1…7和原始实例均保留，最终用原始物理域复核。固定日历证书不会排除整个可变日历K。
2. 在原有精修时间内，试完整订单D/P重插及整趟合并，直接按箱池、E1和E2完整总费用接受下降；每个被评价状态均保有完整任务覆盖。复杂修复不替换每轮随机pair算子，以免压低正常搜索吞吐。
3. 联合提议整组回收截点、E1配送前缀和E2返回等待，跳过单点移动难以跨越的回收时序障碍。候选遵守日历决策网格，并由原完整评价器决定可行性。
4. 候选次数及改进次数写入 `chain_candidates`、`chain_improvements`，汇总内部热启动及所有K访问；逐次保留 `domain_certificate`。超过9单保持原有提案路径。

数学必要条件作为本模型本地纯函数实现；ALNS运行不导入exact模块或gurobipy，不读取历史最优方案，也不把达到已知最优值用作停止条件。精确端的参考求解器未修改。

## 过程与证据

先以已记录ALNS解做输入驱动的定工作量探针（`probe.json`，用于判断修复是否有效，不计入冷启动命中率），再对S01–S03做原型配对（`pilot_plan.json`）。较昂贵的原型替换pair算子后收益混合，未采用；最终候选把重修复限制到预留精修窗口，再运行完整九例配对（`final_plan.json`）。所有阶段根种子均为42，没有增加实验种子。

最终运行共18次，串行执行，各算例交替原版/候选先后顺序，所有K共用5秒而不是每K5秒；迭代上限10^9，避免旧的小迭代上限提前结束。输入读取与模块预导入在计时前，构造、搜索、内部审计和精修均计入求解时间；无外部初解。跨K重访沿用算法既有的子种子派生，不是新的实验根种子。

冻结了原版和候选源文件、81个物理输入文件的SHA256及实验驱动SHA256；搜索结束复核均未改变。每例保留 `result.json`、原始域 `audit.json` 和 `summary.json`。候选推广到正式代码前逐个检查基线，防止覆盖并行改动；只推广六个M8 ALNS文件。
