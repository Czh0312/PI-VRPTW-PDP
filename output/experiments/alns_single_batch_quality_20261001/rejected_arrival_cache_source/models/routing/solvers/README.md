# 当前模型的求解实现

M1–M5 的公开入口仍位于 `../variants/model_n/`，由 `../service.py` 按编号与方法分流。
这里按求解方法存放底层实现，两种方法互不导入。

| 目录 | 文件 | 职责 |
| --- | --- | --- |
| `exact/` | `formulation.py`、`single_batch_formulation.py` | 分发单批专用模型与多批模型；B=1 使用收紧后的车辆索引 MILP |
| `exact/` | `solver.py` | 调用 Gurobi、提取时间表和最优性证明信息 |
| `exact/` | `assignment.py`、`assignment_tree.py` | M2/M4 稀疏联合模型/分仓域树选择、热启动、全局证明汇总；完整枚举保留为显式对照 |
| `exact/` | `strengthening.py` | 安全供货/载荷/序位界、同质车辆趟数上界、实际稀疏弧规模估计 |
| `exact/` | `single_batch_cuts.py` | 单批根节点订单子集容量割；配送/回收分别取整，默认强化含回收的压缩模型 |
| `exact/` | `domains.py` | 顾客可选仓点的必要条件筛选与安全时间界 |
| `exact/` | `bounds.py` | 非度量距离也适用的保守必访弧下界 |
| `exact/` | `primal.py` | 独立构造并审计 B=1 可行初解，不提供最优/不可行证明 |
| `alns/` | `solver.py` | 路线与跨批修复搜索 |
| `alns/` | `single_batch.py` | M1–M4 单批次连续搜索、统一预算和可行最优解轨迹 |
| `alns/` | `single_batch_descent.py` | 单批次有界距离下降候选、纯配送订单交换及仓点候选缓存 |
| `alns/` | `single_batch_scoring.py` | 固定 B=1 搜索上下文内复用任务属性和有界距离/时间缓存，保持原评分算术 |
| `alns/` | `single_batch_cache.py` | 单批上下文、解码任务预处理和有界路线距离缓存；时序与可行性逐候选计算 |
| `alns/` | `construction.py` | 构造初始解 |
| `alns/` | `evaluator.py` | 候选解的日程解码和全周期评价 |
| `alns/` | `cycle_cache.py` | 求解内、固定分仓问题的一级回收方案缓存，单批和多批的二级时序与库存仍重算 |
| `alns/` | `assignment.py` | M4 连续搜索中的顾客迁仓/交换、有界分仓评价缓存；M2 分流 |
| `alns/` | `partitioned_assignment.py` | M2 纯配送的分仓探索与路线热启动 |
| `alns/` | `neighborhoods.py` | 多请求破坏/插入修复、有界评价缓存及可行解热启动转换 |
| `alns/` | `intensification.py` | M5 的两级距离下降候选、整笔送取请求迁移/交换、一级仓点交换 |

M5 的一级解码复用及分仓邻域缓存见 [第二轮优化记录](../../../docs/model5_alns_round2_20261001.md)。
M5 的停滞重启、固定迭代退火周期和探索分支下降见
[第三轮优化记录](../../../docs/model5_alns_round3_20261001.md)。

`../common/cycle/` 只提供输入、业务规则、结果格式、分仓转换和独立审计。
ALNS 不导入精确求解或 Gurobi；精确求解不导入 ALNS；共同审计不调用任一求解器的评价结论。
各模型的公共 API 按需导入选定的方法，结果通过 `solver` 和 `solver_module` 记录求解方法与实现位置。

M2/M4 只有联合模型取得全局证明，或分仓域树全部子树获得足够证明后才能报告全局最优。
显式完整枚举仍要求全部分仓闭合。分仓树中尚未访问或未证最优的子树必须计入全局下界。
ALNS 的可行方案不带最优性证明；精确求解遇到时间上限也不能直接视为已证明最优。

独立加载和实际求解的回归测试：`tests/routing/test_solver_isolation.py`。
2026-09-29 的目录分离本身未改变数学约束或搜索函数逻辑。详见 [模型布局](../../../docs/model_layout.md)。

2026-09-30 增加了 B=1 等价简化、时间窗稀疏弧、车辆对称性、分仓界剪枝与未闭合分区再求解。
ALNS 新增破坏/修复、反转、缓存、双预算降温和分仓热启动，并修复非度量矩阵下临时回程的误判。
`BOUND_PRUNED` 表示该分仓不能改善已审计 incumbent，不表示不可行。
诊断实验的改进与退步均见 [详细检查报告](../../../docs/single_batch_solver_audit_20260930.md)。

同日第二轮：B=1 共享二级任务状态与内部弧约束；精确法增加独立构造初解、对称编号与限时保留。
ALNS 增加局部插入距离下界筛选、跨分仓路线投影、定期继续优化当前分仓及更充足的初始分仓预算。
最短路下界只在同一次求解内共享，避免跨求解编辑输入后的陈旧缓存。
全部对照结果及随机波动限制见 [第二轮优化报告](../../../docs/solver_stability_optimization_20260930.md)。

同日第三轮：M2/M4 在估计二级索引弧数量不超过 60,000 时使用联合分仓 MILP，
超过时保留完整枚举。新增覆盖全部合法分仓的全局距离界，单客户迁移优先顺序不改变枚举完整性。
联合模型估计弧数超过 5,000 时，先用最多总预算的 20% 求初始固定分仓，以提供较好的可行上界。
这些阈值是工程策略，不是理论最优参数。详见 [第三轮报告](../../../docs/free_assignment_joint_optimization_20260930.md)。

同日单批大规模 ALNS 优化：修复阶段只重算目标仓的路线，并按路线内容与车辆可用时间复用局部评分。
M4 在同一连续搜索中迁仓，保留当前路线、温度和算子权重；M2 保留分仓子搜索并使用共同的评分加速。
输入分仓不可行不代表自由分仓不可行。结果增加 `initial_objective`、`incumbent_history`；
M4 另有 `assignment_accepted` 和 `assignment_improvements`。M2 的历史粒度由 `history_scope` 显式说明。
M1/M3 的 `solver.py` 调用转发到 `single_batch.py`，M5 继续原多批分支；公共入口与独立审计不变。
实测范围、退步记录与限制见 [单批大规模优化报告](../../../docs/alns_large_optimization_20260930.md)。

2026-10-01 单批 ALNS 增加末段局部改进：M1–M3 在时间或迭代预算进入最后 20% 时，
尝试改进已审计最好解；M2 每个分仓子搜索使用同一规则，所有子搜索继续共用外层预算。
纯配送增加订单交换及按仓点缓存，M3 使用全局候选枚举；M4 保留已有连续迁仓策略。
完整解码与独立审计不变。M2 的算子统计按全部子搜索累加，由 `operator_statistics_scope` 标明。
被否决的早期集中改进方案及最终配对验证见 [末段局部改进报告](../../../docs/alns_single_batch_descent_20261001.md)。

同日继续提速：B=1 的修复评分预处理订单属性，并在单次修复内缓存有向距离和行驶时间。
`fast_scores=False` 可切回参考评分，原有评分缓存对照开关继续保留。单批求解接入既有一级回收方案缓存，
固定分仓最多 128 项、M4 每个分仓最多 32 项；二级时序、截止量和完整库存检查仍逐候选执行。
搜索算子、排序、接受规则与预算策略不变。固定迭代等价性及等时间结果见
[单批评分与解码提速报告](../../../docs/alns_single_batch_score_20261001.md)。

随后将任务预处理与弧缓存延长到同一个固定分仓搜索上下文；M2 的迁仓投影与子搜索共享上下文，
M4 的不同分仓保持独立。完整解码器复用任务属性和最多 512 项路线距离，仍重新计算车辆复用、

同日第四轮更新替代上述默认枚举策略：按实际时间可行弧与同质车辆趟数上界估计规模，
不超过 120,000 条二级索引弧时使用联合模型，超过时使用完整覆盖的分仓域树。
先做最多 64 个、总计不超过 0.2 秒且不超过总预算 5% 的独立可行初解探测，
仅用于热启动；未探测的分仓仍属于精确模型。固定分仓热启动最多占总预算 20%。
