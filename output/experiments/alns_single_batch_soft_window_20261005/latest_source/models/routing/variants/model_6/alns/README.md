均匀周期基础版：`schedule_mode=uniform_cycle` 逐一探索配置K，重建等长日历，各批共用相对分界时长。shift_cutoff、align_cutoff和polish_cutoff同步改变全部批次截点；缓存包含完整共同截点，重新计算回运、清洗与可用箱池。各K共享一次调用的总时间和迭代上限。支持同一均匀允许域的已审计可行起点，保留其成本并清除精确求解证明。全程不导入Gurobi或精确后端，不宣称最优。

状态：2026-10-04 已实现。完整业务与成本定义见 [模型6设计](../../../../../docs/model6_joint_batch_cost_design.md)。无需 gurobipy 或精确求解许可证。

solver.py 独立实现联合分批 ALNS，不导入精确求解器或 Gurobi。共享公共物理调度传播、初解构造与路线修复工具；两算法共用成本定义及独立审计，不共享彼此的搜索代码。

状态包含订单分批、两级路线、二级物理车/趟次顺序和时间调度选择。配送启用由分批派生。在当前无损失且清洗资源不随 N 变化的模型下，完整时刻表决定最小所需池；据此计算 N、检查池上限和计价，不能用订单总箱次冒充实体池规模。

算子覆盖跨批订单迁移、配送批次合并/拆分/关闭/启用、路线任务重组、车辆复用和可行等待。回收保留原订单身份与配送先行关系，可以进入后续固定回收轮次。关闭配送不能隐藏纯取任务。

每次候选变动重建各仓需求、供货日程、二级送取和卸箱、截止回收量、一级回运、清洗释放、容器峰值及成本。修复同时考虑空间插入成本和及时释放容器的作用；单一最早时刻解码器遗漏其他可行等待的限制需记录。缓存键含分批、时序、成本配置哈希。

搜索罚项与经济成本分开，最终只输出独立审计通过的完全可行解。多种子报告全部尝试、可行率、最佳与平均成本、变异、耗时及相对精确参考的误差。未找到解不构成不可行证明，不报告 proven_optimal。

2026-10-05 增加 shift_cutoff 和 align_cutoff：移动截点或对齐实际前置仓卸箱完成事件/一级供货完成事件，重算完整回运和清洗供箱。缓存键包含全部截点；状态复制、路线破坏修复和重启均保留截点。候选初始化覆盖原截点和几个合法分界比例。

同日求解检查补充：共同分界的事件候选收集所有批次的实际卸箱时刻，再转为同一相对时长；同时搜索一级回运赶上批次结束、回运加清洗赶上后续领箱及周期结束的临界点，包含临界点前后一个时间刻度。polish_cutoff每次至多试算16个候选，以完整解码和成本比较保留改进；临界点由当前路线估计，路线变化后仍须重新核验，不代表完整连续时间优化。每个K预留10%搜索时间用于结束时细化当前最好方案，不将这种多候选细化放入普通自适应算子轮盘，以限制其对路线/分批搜索的预算挤占。10%是算法预算设定，并非成本参数；单次解码不能中断，因此实际耗时可能略有越界。初始化增加90%、95%及最晚必要回收边界，改善较晚回收窗口下原25/50/75%种子均不可行的问题。各K的算子尝试、改进、评价次数与缓存命中在外层汇总，细化调用/改进/评价/耗时单独记录为cutoff_polish_*，费用进展history只属于最终选中的K。

可传 initial_result（CLI: --initial-joint-result），按当前原始业务输入重放物理时间表并重算成本后保留。初始解的证明状态被清除；搜索返回成本不会高于该已验证起点。物理路网和时间精度不变时复用已验证距离/时间缓存，避免每次截点移动重新扫描整个路网。

算子包括随机/相关订单跨批迁移、关闭/拆分批次、路线破坏修复、任务或送取对迁移、趟次拆并、车辆与执行顺序、一级配送/回收顺序、任务逆序、截止等待。用分段自适应权重、模拟退火接受和最优解重启，记录全部算子尝试、改进、缓存命中、费用进展与实际运行时间。

对已解码客户事件和卸回时刻，二级出发可推迟到第一服务前恰好能到达，将可避免途中等待转为仓内等待；库存和截止归属不变。其余时刻用最早因果传播及显式出发/回仓等待搜索，不能宣称覆盖所有可行时间表。短预算至少构造一次方案，实际耗时可略超指定时间。
