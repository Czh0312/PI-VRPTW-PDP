# 模型八 ALNS 为什么仍找不到已知最优值

本轮只做离线诊断，使用已有的最优方案和根种子42，没有重新整批延长 ALNS 时间，也没有增加实验根种子。诊断明确给定最优方案或其部分决策，因此不能计入“ALNS自行找到最优解”的成绩。

## 已验证的具体问题

三个算例的完整最优方案都能转成现有 ALNS 状态，经其完整评价和审计得到相同费用。因此，这三例的差距不是因为 ALNS 状态无法表示最优方案，也不是两种算法最终费用口径不同。

但固定最优分批、日历边界和回收截点，让现有三种初解构造器重新生成路线后，结果明显变差：

| 算例 | 已知最优费用 | 给定最优分批/日历/截点后，现有路线构造费用 | 上轮冷启动 ALNS 费用 |
| --- | ---: | ---: | ---: |
| S02 | 52.515975 | 61.000229 | 55.488670 |
| S03 | 47.760970 | 52.067326 | 52.141990 |
| S05 | 54.022523 | 61.250863 | 56.617267 |

这只是三种现有构造器在种子42下的输出，不是重新运行完整 ALNS 搜索。每例给构造器最多2秒，实际约0.05—0.06秒完成。最优费用仅用于诊断对照，没有用于这些重构候选的筛选和停止。

1. **初始化偏向均衡分批，遗漏有用结构。** S02 最优方案为5/2分批，当前16个均衡初解全部为4/3；S03最优为4/2/1，当前全部为3/2/2。它们仍可由后续算子改变得到，不能把“初解未出现”说成整个搜索域被删除，但搜索起点确实不利。
2. **正确分批会被粗糙路线费用掩盖。** S05最优分批已经在初解候选中，但给定正确日历和截点时，路线构造费用仍达到61.251，远高于最优54.023。当前流程需要先优化这一结构中的路线，才能看见其优势。
3. **日历、等待、回收与路线需要配套改变。** 保留S02最优路线而仅清除E2显式等待，就出现E1回程截止和车辆重叠错误。S03清除等待后仍可行，但费用由47.761增加到48.361。三例若仅把最优回收截点换成日历中点，都变成不可行。单个决策的改动可能被判坏，导致搜索难以形成更便宜的联合方案。
4. **前期成本排名把时间留给了错误的K。** 上轮名义总预算20秒，S02真正最优K=2只获得约4.10秒，S03最优K=3约4.05秒，S05最优K=2约4.00秒。它们当时返回的费用仍高，后续精修分别转向K=1、K=4、K=1。给总预算更多时间，不保证时间会用在正确结构上。

## 对上一轮优化的判断

上一轮预算调整在单种子配对中改善了平均结果，但没有修复上述构造和联动搜索问题，不能把它当成已经解决小规模求解质量。系统负载会影响墙钟预算内的迭代量，也不足以单独解释这些结构性损失。

后续应优先改造能保留路线质量的分批/日历联合修复，处理回收等待与E1路序的配套变动，并保留多个有潜力的K和结构进行比较。仅增加完整审计速度、随机种子或总运行时间，不足以验证这些缺陷已经消除。

精确算法能够利用全局约束、路线列和界进行筛选；现有ALNS的粗糙构造与逐步移动没有对应的全局引导。这说明当前ALNS实现仍需改进，不能据此认定启发式方法天然就应在这些小例上保持这么大的费用差距。

此前九例精确验证的快速计时复用了经审计的历史可行上界，因此不应直接当作“精确算法完全冷启动”的计时与ALNS比较。这一口径差异不改变上述ALNS自身缺陷的诊断。

原始结果和逐K记录见 `diagnosis.json`；重构方案见 `S02_reconstructed.json`、`S03_reconstructed.json`、`S05_reconstructed.json`。诊断脚本记录源码和引用文件SHA-256，运行前项目预检通过。本轮未修改生产算法源码，也未将任何参考最优方案注入正式冷启动对照。
