# 模型八 ALNS：单次完整评价审计优化

**发布范围：新快评默认仅用于不超过9单的小实例，正式质量验证覆盖七单算例；超过9单保留原评价路径。**以下62次对照考察的是最初全规模候选。M01两组、L01一组出现成本回退，因此发布时加入规模保护，并将发布版再次对全部8,366次冻结候选逐项回放验证；没有把中大例回退结果隐藏或改写。

2026-10-29。候选版先根据实际总仓清洗完成时间推算候选箱池，然后在该箱池下运行完整物理、费用和两周期审计。正常可行且没有命中评价缓存的候选从两次完整物理审计变为一次。推算不成立、完整审计失败或超过箱池上限时，回退原评价路径，保留原有错误码及罚分。业务规则、费用、搜索算子、K 域和参考最优值的使用方式未改。

## 正确性与固定候选计算

五个来源 S02/S03/S09/M01/L01 共 8,366 次真实候选评价回放：原版与候选版的分数、完整返回方案及错误信息的规范化 SHA256 逐项相同。另以专项测试检查库存同时刻边界、错误数量、候选失败回退、原九例方案与完整两周期审计仍执行。

交替回放中，五例 CPU 中位数合计从 9.812500 秒降到 7.421875 秒，减少 24.36%。这是同一批固定候选的评价计算，不能等同于整个 ALNS 的加速倍数。其中三组小例固定候选的 CPU 中位数合计减少 20.92%。最初墙钟样本有明显波动，其完整数据保存在 paired_replay_wall_only.json；后续同时记录 CPU 与墙钟。这些计时属于探索性定位，保留全部轮次，不把其中最好的一轮当作最终性能。

## 测试、默认入口和证据

测试计数、所选范围和默认替换状态另见 validation.json 与 promotion.json；没有运行全仓库测试。原版和候选版的 297 个 Python 源文件都已冻结，基线哈希见 baseline_source_hashes.json，正式顺序和输入信息约定见 confirmatory_plan.json。试跑使用旧 driver 的确切副本 pilot_driver.py，仅探索阶段使用种子 42；正式种子在冻结后执行。

本次改动目标是降低候选评价成本。对每个算例、每个种子的同预算质量不作逐次改善保证；后续可继续针对路线、分批与截点的联合邻域改进搜索质量。

本轮专项候选验证 **22 passed**，生产入口及相关回归所选范围 **74 passed**；合计 96 个所选测试通过，0 失败、0 错误、0 跳过，未运行全仓库测试。运行器预检 READY，实际 Gurobi 11.0.3 整数优化通过。
