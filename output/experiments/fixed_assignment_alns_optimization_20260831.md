# M3/M6 ALNS 修复加速与 M6/M7 转运复现修复

日期：2026-08-31。本轮在 `final_freeze_20260830` 后继续优化；旧冻结结果未覆盖。新增实验全部位于 `output/results/m6_optimization_20260831/`。

## 结论

保留三项实现改动：固定分配 regret 插入缓存、固定分配局部搜索的成本短路检查、转运采样顺序及交换剩余预算修复。另外补齐 M6 分阶段诊断。没有改变数学约束、候选位置全集或精确模型 formulation，没有调整阶段预算比例。

- 固定 100 次迭代，3 个实例 × 3 seeds：M3 最终路线、M6 转运前路线各 9/9 完全一致。
- M3 平均墙钟 4.1055 → 3.1313 秒（1.31×）；M6 基础搜索平均 5.5083 → 4.0236 秒（1.37×）。
- 同为 10 秒：M3/M6 平均迭代数分别增加 38.49% / 53.35%，配对目标改善均值分别为 0.448% / 1.617%。两模型均为 7 组更好、2 组更差。
- 36 条最终版配对结果全部可行，最大路线成本复算误差 `7.73e-12`，M6 继承初解支配零违规。18 条计时结果最大墙钟 10.0158 秒。
- 这是代表算例验证，不足以宣称上一轮 85 对 M6 的平均质量回退已完全消除，也不是六模型全量实验的新替代版。

## 1. 热点及实现

### 固定分配 regret 缓存

新增 `models/routing/alns/fixed_repair.py`，接入 M3/M6 的 E2 regret 插入。一次修复内，E1 路线、任务分配、任务位置和载量不变；只有被插入的那条 E2 路线需要重新枚举。缓存保留原有位置顺序、可行性判断、完整路线成本及浮点计算顺序，插入后立即使受影响路线缓存失效。缓存仅在当前修复调用内有效，不用于自由分配算子。异常时也恢复被试插的原始路线。

单元测试覆盖：与禁用缓存的穷举路径比较、路线变化失效、发车时刻变化、无可行位置的空结果、异常恢复。

`Set2_100-5-1 / seed=11 / M6 / 固定40迭代` 的剖析：

| 指标 | 改动前 | 最终版 |
|---|---:|---:|
| 总 profile 墙钟 | 8.2236 s | 5.9019 s |
| regret 累计时间 | 3.188 s | 0.707 s |
| E2 可行性检查调用 | 54,334 | 20,309 |
| E2 路线仿真调用 | 72,530 | 39,109 |
| 最终目标 | 2280.549501 | 2280.549501 |

计数下降是独立于墙钟波动的直接证据；profile 本身有额外开销，不当作正常生产运行时间。

### 局部搜索成本短路

公共引擎之前的统一评估改动，使固定分配局部搜索对不降成本的邻域也执行完整可行性审计。现恢复“先比较成本，仅对降成本候选审计”。提供组合 `evaluate()` 的自由分配评估器继续使用一次组合评估，不引入重复重建，也不接受未经审计的改进解。

### 转运顺序与预算

M6/M7 共用转运后处理中的位置列表原来来自 `list(set(...))`。Python 集合次序受进程哈希随机化影响，即使 `random.seed` 相同，抽到的位置仍可能不同。这解释了本轮某些固定迭代转运前一致、转运后不一致的现象，不能只归因于墙钟。

现对物理位置去重后排序。最终版在 `PYTHONHASHSEED=17` 与 `991` 两个进程中，9/9 固定迭代案例的最终目标、E1/E2 路线全部一致。此结论仅针对这些固定迭代案例；墙钟停止、基于时间的降温及算子奖励仍会影响常规限时 ALNS 的复现。

同时修复：一次 relocation 扫描无收益后，exchange 必须使用重新计算的剩余时间，不能继续使用扫描前的旧额度。预算耗尽即跳过 exchange；已有针对性时钟模拟测试。

### 阶段诊断

M6 `phase_diagnostics` 单独保存初次基础搜索目标与迭代数、转运目标/收益/数量、补时搜索目标/迭代数/算子诊断，以及最终选用阶段。统一实验 runner 保留该结构、补时迭代数、实际转运搜索时间。原 `stage1_objective` 和第一阶段 `alns_diagnostics` 保持兼容，不把补时结果错误解释为初次阶段的表现。

## 2. 对照协议与结果

实例为 `Set2_100-10-1`、`Set2_100-5-1`、`Set2_200-10-1`；seeds 为 11/23/42。M6 读取预先保存的同一 M3 初解（100 次固定迭代生成），前后 SHA-256 校验一致，从而隔离上游 M3 改变的影响。

固定迭代阶段关闭按时间的降温、权重更新时间触发、时间收益加权和停滞强化；迭代上限 100，宽松总时间上限 600 秒。转运仍保留最多 2 秒预算，因此基础阶段与最终转运结果分别比较。计时实验保持正常默认自适应设置、10 秒总预算和统一 runner 的 M6 80% 阶段比例。

| 指标（每模型 9 对） | M3 改动前 → 最终版 | M6 改动前 → 最终版 |
|---|---:|---:|
| 固定100迭代总墙钟均值 | 4.1055 → 3.1313 s | 5.8578 → 4.2108 s |
| 固定100迭代基础搜索均值 | 同上（含初始化） | 5.5083 → 4.0236 s |
| 基础路线逐项一致 | 9/9 | 9/9 |
| 最终路线逐项一致 | 9/9 | 5/9 |
| 10秒迭代均值 | 465.67 → 644.89 | 230.78 → 353.89 |
| 10秒配对目标改善均值 | +0.448% | +1.617% |
| 10秒更好 / 持平 / 更差 | 7 / 0 / 2 | 7 / 0 / 2 |

正改善率表示目标下降。M6 固定迭代最终目标均值按配对比例略差 0.0452%，是稳定位置采样与旧进程随机集合次序的区别；基础搜索目标及路线完全一致。稳定排序不是承诺转运目标在每个种子上都更优。

这些墙钟值是本机顺序批次的描述性结果，没有统计显著性或专用性能机保证。基线批次中有一次约 11 秒的针对性单元测试与求解重叠，可能影响少量计时记录，因此不把墙钟比值解释为严格隔离条件下的普适提速。固定路线一致性与剖析调用数下降不依赖这一时间比较。

正式配对汇总明确选择 `cached` 批次的 M3 与 `final_m6` 批次的 M6，未混入尚未修正集合次序的中间版 M6。

## 3. 六模型回归

- 常规 `python -m pytest -q`：49 passed，3 skipped。
- 本机许可环境显式运行 M1–M4、M6 精确测试及 M7 分区逻辑测试：13 passed。沙箱初次执行因许可证用户名不匹配失败，换到本机许可环境后通过，不计为数学模型错误。
- `Set1_7-2-1b` 六模型各 2 秒 ALNS 继承回归：全部可行、全部匹配该实例精确目标（浮点容差内），所有继承支配检查通过。
- 同实例六模型精确求解回归：6/6 `OPTIMAL`。M6/M7 本例通过现有松弛证书证明；本轮没有修改精确求解核心，也没有验证其难例证明速度提高。M1–M4 有显式路线审计字段，M6/M7 该字段仍为 null，不宣称六条均通过独立路径审计。

## 4. 保留的瓶颈

下一步主要是 M3/M6 的成对插入：最终版上述 profile 中，`paired_insertion` 仍消耗约 4.071 秒，已经成为更突出的热点，主要包含候选解复制、受影响路线仿真和整解成本复算。应继续以同路线/同目标的固定迭代测试为门槛优化。

M7 精确求解的难分区下界证明仍未解决；上一轮 120 秒全量仅 11/22 证明最优的结论继续有效。本轮的小算例 smoke 不改变这一结论。暂无证据支持继续缩小搜索候选集或修改模型约束来换速度。
