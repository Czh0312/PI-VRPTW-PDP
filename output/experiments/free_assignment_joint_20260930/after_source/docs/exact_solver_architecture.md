# 精确求解范围

正式入口将 `multi_batch_cutoff_v1` 分发到各编号目录的 `exact/solver.py`。
M1/M3 为单批固定分仓；M2/M4 为单批自由分仓；M5 为多批固定分仓。
各模型的 MILP 建模入口位于 `exact/model.py`，共用实现位于 `models/routing/solvers/exact/`。
M2/M4 根据展开规模选择联合分仓 MILP 或完整分仓枚举；联合模型直接覆盖全部合法顾客分仓。
求解器遵守输入的整数时间刻度及二级趟次上限；ALNS 位于独立 `alns/` 目录。

固定分仓只有完整 MILP 返回最优并且独立审计通过，才能报告 `proven_optimal=true`。
自由分仓要求联合 MILP 取得全局证明，或全部枚举组合被最优、不可行证明或有效成本下界闭合。`BOUND_PRUNED` 仅表示不能改善
现有已审计可行解，不表示该组合不可行。限时可行解、未找到解与已证明不可行必须区分。

B=1 专门化将回收量固定为各仓全部订单箱数，直接约束带箱二级趟次在唯一截止前卸回，保留清洗末态。
另有基于安全时间界的弧删除、同质车辆对称性、分仓距离界剪枝、未闭合分区重访和经过独立审计的
MIP 初始解。详见 [2026-09-30 检查与对照](single_batch_solver_audit_20260930.md)。

第二轮在 B=1 下进一步共享二级任务的时间/载荷与内部弧传播约束，减少车辆、趟次之间的重复。
精确法内部的 `primal.py` 独立构造并审计初解，构造失败不证明不可行；建模或求解限时也保留已审计方案。
初解进入 MILP 前会重映射同质车辆编号，以满足对称性约束。算法不依赖 ALNS。
实验显示可行解覆盖率提高，但较大实例 gap 仍可能很大，详见
[第二轮优化与稳定性报告](solver_stability_optimization_20260930.md)。

第三轮将顾客级分仓变量、一级补货/回收量和二级任务覆盖纳入同一个线性整数模型。
同一顾客的全部订单共用分仓变量；每项二级任务仍只执行一次。较大实例保留完整枚举，
先做必要条件域删除，再按初始、近仓和单客户迁移顺序搜索，最后完整覆盖其余组合。
安全全局距离界覆盖尚未访问的分仓，不把某一固定分仓的下界当作自由分仓下界。
固定分仓热启动只提供已审计上界，其局部最优/不可行证明不传递给联合模型。
自动规模阈值、限时局限和同预算实验见 [第三轮联合求解报告](free_assignment_joint_optimization_20260930.md)。

历史 M1–M4 的 indexed 和 commodity_flow 后端保存在 `models/routing/baselines/`，需要 `--baseline` 或 `allow_baseline=True`。这些证明只针对历史业务规则，不能作为新版四模型的证明。
