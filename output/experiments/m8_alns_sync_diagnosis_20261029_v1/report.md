# 模型八 ALNS 与精确加速的关系：初步检查

2026-10-29。仅检查现有实现并运行三个每例 10 秒的剖析样本，未修改 ALNS 或生产默认参数。

新增精确主问题约束并未改变业务问题：完整模型原本已要求同一趟回库的空箱同批回收。ALNS 解码器也将同一 E2 trip 的全部回收量，按共同 return_complete 对应的第一个 cutoff 归批；有配送的车次从实际供货后发车。因此需要同步核对语义，但无需简单复制主问题割。

累计调用时间相互包含，不能把 JointEvaluator、解码、审计的时间再相加。cProfile 本身会降低迭代速度，这三个短样本只用于定位热点，不能作为正式求解质量或加速倍数。原分析工具使用 POSIX 分隔符过滤函数名，其 Windows decoder_calls/physical_audits 字段不适用；本报告直接从原始 solve.prof 归一化路径后重新统计。

三个最终方案均在原始 K=1…7 实例上重新审计、费用复算和两周期回放通过。没有运行 pytest；不把三次方案审计称为测试套件通过。

## 后续优化应验证的内容

1. 评价成本：针对相同固定分批/截点和相同车次输入复用可证明等价的解码、投影与中间计算；保留最终独立业务审计，验证缓存隔离、失效及结果一致性。
2. 搜索质量：联合调整分批、车次与截点，增加清洗后空箱能在下一批装载前释放的机会；在真实总成本下评估箱池节省与新增运输的取舍。
3. 验收：在相同总预算、多个新种子下配对比较原版与候选，记录首次可行、达到给定误差或参考最优的时间、最终误差和可行率。原小例精确最优值仅用于事后评分，不作为 ALNS 初解、下界或停止条件。

ALNS 达到已知最优成本表示本次命中最优方案；全局最优性的证明仍来自独立精确证书。本次尚未实现或验证候选加速版本，不宣称已经提高 ALNS 效率。
