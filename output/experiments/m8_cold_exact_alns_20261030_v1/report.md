# 模型八：ALNS 与 Gurobi 同条件冷启动对照

2026-10-30。S01–S09全部九个小规模算例；唯一根种子42，5秒和30秒两档，36个独立进程串行执行。两种方法均只读取原始输入，完全不读取历史可行方案；每个预算重新从头开始，也不复用上一档的结果。ALNS会根据总预算分配构造与跨K搜索时间，因此独立30秒运行不保证逐例优于独立5秒运行。

“命中最优费用”由实验结束后与已证明的最优值比较；ALNS不提供全局最优性证明。Gurobi的“原生证明”须同时有独立业务审计通过的最终方案和覆盖全原始K域的OPTIMAL状态。没有找到可行方案时，GAP不可定义，不能写成0或只取容易算例后称为九例平均。

在本轮短预算冷启动中，ALNS更快提供可执行方案。此前依据几秒证书耗时推断Gurobi冷启动更快，缺少同口径依据；这轮数据不支持该推断。

这只是单根种子、每条件一次的当前九例结果，不能外推为所有种子、预算或规模的速度排序。

## 同条件与冷启动约束

- 同一批原始数据、费用、资源、原始K=1…7、整数物理时钟与未额外收紧的决策网格。
- Gurobi使用当前公开 `solve_exact` 直接统一MILP：`compact`、`physical_time`、`preprocessing=True`、`vehicle_symmetry=True`、单线程、种子42；所有优化前模型 `NumStart=0`。
- ALNS使用当前公开 `solve_alns`，`adaptive`调度、迭代上限10^9、外部 `initial_result=None`；内部热启动及跨K复用仅使用本轮从原始输入新生成的方案，所有工作共用本轮总预算。
- 每次运行新进程；各例交替两方法的先后顺序，30秒档再反转顺序；不并发运行两种求解任务。系统负载和墙钟截止仍会影响单次结果。
- 使用工作区文件读取白名单：只允许已冻结原始输入及源代码读取，禁止历史结果和证书内容进入工作进程。每个工作进程实际读取的输入路径保存在summary.json；读取历史结果会直接使运行失败。
- Gurobi增加的MIPSOL回调只向内存记录时间与目标值，不提交解、不加割、不修改变量界或参数。ALNS沿用已有历史记录；未改变两种算法的搜索实现。
- 所有36次搜索结束后，单独的analyze.py才读取历史summary.json中的最优费用和证明元数据，仅作GAP及命中统计；本轮没有读取历史路线JSON。

本次测的是当前正式直接Gurobi模型，并启用了已验证的输入推导优化；此前约2–14秒的研究程序主要将新下界与历史可行方案闭合，不是本次冷启动求解入口，不能混用耗时。
