# 模型9自由选仓多批次：首次精确小算例

2026-10-30。已完成 M9 的数学模型、直接 Gurobi 实现和一个人工小算例。
M9 在 M8 的不等长多批次结构上加入 M4 的顾客级自由选仓，
同一顾客的全部订单保持同仓，配送、回收、分批、日历和箱池共同决策。
数学定义见[模型9](../../../docs/model9_free_multibatch.md)。

## 输入与求解范围

使用[小算例配置](../../../config/experiments/examples/model9_demo.json)，一个总仓、两个前置仓、
两个顾客、两笔各需一箱的订单；全部输入位于
[示例数据](../../../data/examples/model9_demo/README.md)。
这是人工位置与人工费率的机制验证，不代表真实经营成本。

- 两模型共用物理网络、订单、释放时刻、绝对服务窗、车辆、箱池上下界与费率。
- 周期90分钟，清洗3分钟，各阶段最短15分钟，完整批次数域为 K∈{1,2,3}。
  15分钟是本示例显式参数；不以子集代替该参数下的完整 K 域。
- M8 固定参考分仓 C1→S2、C2→S1；M9 联合选择服务仓。
- 两模型各运行一次，均为 seed=42、单线程、expanded、总求解预算60秒，MIPGap=0。
- 每个完整模型只调用一次 optimize，批次数与所有业务决策由 Gurobi 联合优化；
  没有外层分仓枚举、K 枚举求解或 ALNS 初解。枚举仅用于独立回归对照。
- 项目预检验证了实际 Gurobi 11.0.3 接口、许可证初始化及整数优化。

## 最优结果

| 项目 | M8 固定分仓 | M9 自由选仓 |
| --- | ---: | ---: |
| 最优成本 / 人工费用单位 | 57.0 | 37.0 |
| Gurobi 全局下界 | 57.0 | 37.0 |
| MIP gap | 0% | 0% |
| 实际配送/回运批次数 | 2 / 2 | 2 / 2 |
| 实体箱池 | 1 | 1 |
| 一级距离 | 20 | 20 |
| 二级距离 | 24 | 4 |
| 全部 K 候选已建模 | 是 | 是 |
| 独立路线、成本审计 | 通过 | 通过 |
| 连续两个周期重放 | 通过 | 通过 |

M9 成本减少20，即相对本例 M8 下降35.0877%。这次改善来自分仓后的二级距离下降；
两模型都已实现两批周转及一箱复用，M9 没有在本例中进一步减少箱池。

| 顾客 | M8 固定仓 | M9 选定仓 |
| --- | --- | --- |
| C1 | S2 | S1 |
| C2 | S1 | S2 |

M9 的完整成本为：箱池30 + 一级距离2 + 二级距离4 + 清洗0.4 + 追踪0.2 + 磨损0.4 = 37。
本例工时、车辆与趟次费率显式为0；模型仍保留这些成本项，其他费用配置可启用。
这不是长期累计回本计算。

## M9 的批次与箱池复用

| 批次 | 开始 / 分钟 | 回运截点 / 分钟 | 结束 / 分钟 | 订单 | 所选仓 |
| --- | ---: | ---: | ---: | --- | --- |
| b1 | 0 | 25 | 40 | o1 | S1 |
| b2 | 40 | 75 | 90 | o2 | S2 |

选定批长40、50分钟，边界及截点都是模型的决策。目标不计工时的这个示例可能存在多个同成本时刻方案，
这里记录的是实际保存的最优日程，不宣称日历唯一。
每批装货前恰有1个清洁箱，装货后为0；首趟一级车在第37分钟卸回总仓，
清洗至第40分钟完成，恰可供第二批装货。末趟第87分钟卸回，至第90分钟清洗完成。
终态为1个清洁箱在总仓，顾客、在途、前置仓和脏箱状态全部清零。

K=1 无法在第0分钟装载第40分钟才释放的 o2；K=3 无法让两笔不可拆订单覆盖三个非空配送批。
这些候选在统一模型中仍建立完整业务块，并由模型排除。

## 验证范围

选定的10个测试模块共320项通过、0失败、0跳过，耗时86.25秒；不是全套测试。
具体模块清单见[结构化验证结果](verification.json)的 `targeted_regression.scope`。
M9 专项包含23项，覆盖：

- 固定顾客选仓后与 M8 的最优值一致；自由选仓与全部分仓的 M8 独立对照一致。
- 一个完整模型、一次 optimize，无外部初解；完整候选域和超时证明边界。
- 同一顾客重复订单送取同仓，未知/缺失/篡改分仓被独立审计拒绝。
- 原参考仓不可达时仍能选择可行其他仓，避免把参考仓当作固定决策剪枝。
- expanded/compact、不同有效界配置、非整除时钟与独立单订单日程穷举。
- 清洗后领箱、周期末闭合及连续两周期重放。

原有 CLI 全 K 测试曾写死旧130分钟例的上界65，而当前入口已指向780分钟数据；
已改为按实际输入周期和最短阶段推导期望值，未改变业务参数。
上述320项是修正后的最终检查结果。

两个保存结果随后又用当前原始输入独立复核，目标值与下界相同，路线、成本和双周期审计均通过。
本次只运行一个种子，未据此声称多种子稳定性、正式基准性能或普遍35%的改善。
