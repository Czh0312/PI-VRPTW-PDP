# 补充实验的受限问题与延后装货定义

## E2：分批与箱池 2×2 消融

四组使用同一固定候选日历、固定截点、订单允许批次、分仓、车队和完整成本。采用 `JointBatchInstance` 的既有固定日历 M6 入口，不将其称为全 K 域 M6。

基准订单批次必须来自独立审计通过的共同保存日程。A/C 用 `fixed_assignment` 限定每个订单的允许批次，A/B 用 `pool_min=pool_max=N0` 固定实体箱池，C/D 在同一 `[1,Q]` 内优化。四组都重新优化路线和作业时刻，不向 D 单独注入其他组的好解。初次配置取 `N0=Q`，另报告基准保存日程的 `minimum_pool_for_schedule`，不能将后者解释为重新优化的全局最小池。

独立审计重新投影订单批次，并检查池上下界、路线、费用和连续双周期箱流。实验层另外核对组别对应的固定值；不能仅修改导出标签。

## E3：等长日历的延后装货精确基线

新增配置为 M7 `joint_batch_options.loading_mode="optimized"`。标准 M7 仍采用 `batch_start`，且其求解行为不变。此扩展目前只支持精确入口，ALNS 显式拒绝，避免将尚未实现的启发式当成此基线。

对每批 b，保持等长区间 `[s_b,e_b]` 和独立截点 `c_b`，新增整数装货开始时刻 `l_b`。所有承运该批的一级车辆同时装货，约束为：

- `s_b <= l_b <= c_b`；有配送需求时 `l_b + 一级装货时长 <= c_b`；无配送需求时令 `l_b=s_b`，对应零数量扣减。
- 订单 i 分到 b 则 `release_i <= l_b`。货物在装货时已备好，而非仅在顾客服务时备好。
- 每辆有配送任务的一级车在 `l_b+装货时长` 发车，车辆占用自 `l_b` 起计。前一趟返场和周转必须完成后才能开始装货。
- 批量净箱在 `l_b` 从中心仓库存扣减。此前（含等号）已返场并清洗完成的空箱可以复用；未清洗完成的不能提前计入。每次扣减的累计库存约束与独立事件账本都使用真实 `l_b`。
- 一级供货须在 `c_b` 前完成；二级配送和回收时间窗、最短使用时长、按截点划分回运资格、批末一级返场、期末全部净箱回仓和跨周期车辆约束保持原定义。

结果明确保存 `loading_mode`、所有 `batch_loading_starts` 及日历/截点。审计从原始实例验证时刻、释放约束和固定日历，再用实际装货时点重放库存、重算车辆占用与费用，不接受结果自行改变允许域。

在相同 K、整数时钟和其他参数下，标准 M7 的装货时点是此扩展的一个合法选择。与标准 M8 的可行域关系另行分析：M8 仍在其优化后的批起点装货，此扩展在固定等长区间内延后装货；不预设二者包含关系或费用排序。

## E4 与 E5

E4 冻结共同日历、截点、订单批次和分仓，设置固定 `N` 后重新求解路线和时刻。固定原日程缩池仅作参考，使用审计计算的日程最小池。初始候选为适用下界和 `ceil(Q×{0.50,0.65,0.80,1.00})`，阈值附近补整数点；未找到解不作为不可行证明。

E5 采用基准箱池与运输费率的 0.5/1/2 倍情景网格，各价格点重新求解；将固定方案重计价单列。这些是合成费用情景，不作为人民币市场价格。
