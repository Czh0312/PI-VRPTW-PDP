# 模型3：连通、容量与时间联系的统一加强

所有规则来自当前输入，适用于不同订单规模；没有M03专用判断或顾客数阈值。
业务时间窗、费用、箱池、车辆数及一秒整数时钟保持原定义。

## 配送与回收双向载荷流

在每条二级任务弧上，分别定义剩余配送量D与累计回收量P，重量和体积各一组。
配送节点消耗其配送量，回收节点产生其回收量；出发时回收流为零、回仓时配送流为零。
每条弧满足D+P不超过原容量乘以弧启用值。流量按容量归一化，改善系数尺度。
任务后的原载荷等于其所有出弧的D+P之和。

原整数路线可唯一地投影为沿路线逐步消耗配送、累加回收的非负流量。
反过来，原覆盖、车辆、路线归属及因果约束保留；整数选弧仍分解为原物理路线，
沿路径的守恒及端点零流量确定其真实载荷。因此可用此表达替代二级出发及内部的大M载荷传播，
不改变业务可行域与目标。一级载荷、二级逐趟总配送/回收容量、时间及库存约束保留。

原模型的服务后载荷及弧前后关系还给出更紧上界：
弧从配送节点i出发时，其载荷不超过C-q_i；弧进入回收节点j前，不超过C-q_j。
进入配送节点的配送流至少为该节点需求乘以选弧值，离开回收节点的回收流同理。

`resource_flows`是可复现的等价表达开关，用于对照，不需要随规模调整。
公开求解入口仍保留`route_strengthening=False`作为全部加强前的冷启动入口。

## 原因果关系导出的弧冲突与时间提升

原模型对每单有严格因果顺序d_i→p_i；每条选中的任务弧也严格推进因果序位。
若两条候选弧与这些必选先后关系合起来构成环，原整数解不可能同时选择它们，
故直接加入y_e+y_f≤1。包括普通双向小环以及p_i→d_j和p_j→d_i这类跨订单冲突。
生成过程只查原先后关系，不以距离、时间预算或算例名称决定有效性。

订单还必有t_p≥t_d+服务时长+最小使用时长。把它与条件弧时间联系相加，
可得以配送时刻为起点或以回收时刻为终点的提升联系。
条件不成立时所需系数用提升后起终节点的原窗口计算，
仅保留比原系数更小且非零的行。这样收紧分数松弛，仍保留整数物理调度。

## 输入型容量/连通切割

对任意非空任务子集S，令r(S)为1、配送重量/容量、配送体积/容量、回收重量/容量、
回收体积/容量各向上取整的最大值。至少r(S)条原趟次服务S，每条这样的趟次至少离开S一次，
故全体选弧满足δ⁺(S)≥r(S)。这对混合配送/回收、非度量距离也有效。

辅助弧覆盖LP在统一准备预算内迭代：用最小割发现弱连接子集，
用空间邻域和窗口前缀发现舍入容量违反，再加入上述有效行。
这不声称完整分离了所有容量切割。完成的原生LP最优值可贡献下界；
后续LP中断时仅保留之前已最优LP的值，不使用中断时的可行原目标。
已生成的有效子集行可同时加入完整主模型，即使分离没有完成也不影响正确性。

## 从当前输入生成更好的初解

在原种子车次上做确定性的任务重定位、交换、路线内顺序改进和路线尾部交换。
每个候选检查容量、窗口及跨路线的配送→回收时序，且保持所有任务恰好出现一次。
这些是有预算的启发式候选，不提供全局最优证明，也不限制主模型选择。
候选仍需经过完整调度模型副本，副本找到原业务可行解后才传入主模型作为MIP初解。

LP、切割和初解改进仍共享原有准备预算，全部从总求解预算扣除。
最终最优证明仍来自完整业务MILP的原生最优状态与独立成本、两周期审计。
没有自定义主求解回调、列生成或Benders，也不读取历史方案或最优值指导求解。
