## 同一算例共享的输入

八模型使用相同的顾客与订单身份、坐标、货重、需求箱次、绝对配送窗、货物释放时间、服务时间、网络与行驶时间、候选仓、车队及容量、周期起止。循环模型另共享原回收窗、使用时间、清洗及物理箱参数。M1/M2 不启用循环回收和清洗义务；不删除原始公共记录。

分仓、订单分批、箱池及日历的参考值由同一规则产生。模型适配只改变该模型固定或允许优化的内容，不能平移顾客窗口、减少需求或扩车来使某个模型可行。M2/M4 自由分仓时，原固定仓是参照而不是必须执行的订单约束。

箱次 Q 是所有模型共同的需求量；实体箱数 N 是资源参数或决策，不能用 N 的变化替代需求变化。

## 对比与统计

- 包装比较：M1/M3、M2/M4；分仓比较：M1/M2、M3/M4；单批／固定多批比较：M3/M5；联合分批比较：M5/M6；日历柔性比较：M6/M7/M8。
- 同一配对共用来源、需求和外部条件，按实例给出费用、距离、N、K、车辆／趟次、可行状态、上下界及时间；循环指标对一次性模型记为不适用。
- 当前 M1–M5 距离目标与 M6–M8 成本目标不同。比较统一总费用时，应按同一费用口径评价方案，并保留固定策略成本优化对照（作为消融配置，不增加基础算例数），区分目标变化和决策自由度变化；不擅自改写模型定义。
- 同一规模的匹配对照使用相同算法预算、种子集合及运行环境；种子属于重复运行。精确与 ALNS 的预算分别明示。
- 以全部计划运行为可行率分母。保留不可行证明、限时无解、审计失败及未完成状态，不筛掉不利算例。选例已按名称确定，后续不因某模型失败而更换来源。
- 三个规模分别报告，每组九例；按原始来源块保留配对关系，参数敏感性结果另表，不合并为新增独立样本。

## 审查后的修订2

原M03/M5和L09/M5末批回库存在时间冲突：即使忽略竞争、容量和非强制回库，回库加清洗分别至少需要67.65和66.97分钟，原参考日历只留65分钟。M03另经精确求解判为不可行。统一将27例固定参考分界从75%改为70%，回库阶段延长至78分钟；单批同步使用相同末次分界19:42。订单需求、车队、成本和绝对送取窗未改。

批次数从共同名义域K=1…390出发，仅剔除数据可证明不可能的取值：K不能超过订单数；M6/M7的等长首批必须容纳最早的实际回库。逐例证明保存在shared/batch_count_certificate.json。M6/M7保留3–5个候选，M8保留7–100个；不能把这个等价预处理称为任意受限域实验。

M5原生模型不要求每个固定时段均有正回库量，而M6–M8有这一要求。因此除了目标不同，批次业务规则也必须在消融对照中对齐，不能把所有M5/M6差异仅归因于“释放变量”。
