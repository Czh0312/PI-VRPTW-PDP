# 六模型求解器优化分析（2026-09-13）

本轮覆盖 M1、M2、M3、M4、M6、M7 的正式求解入口。历史未提交的改动原样保留为基线快照；新实验保存源代码、输入文件哈希、随机种子、完整路线、目标值、下界、耗时和审计结果。最终数字见 [本轮结果总表](../output/experiments/solver_optimization_20260913/report.md)。

## 1. 问题定位

| 模型 | 精确求解的主要瓶颈 | ALNS 的主要瓶颈 | 本轮处理 |
| --- | --- | --- | --- |
| M1 固定分仓纯配送 | 小规模已经很快；替换模型的建模和热启动开销可能反而更大 | 距离、路线成本重复计算；大规模路线局部最优 | 保留原精确默认入口；提供紧凑流对照；静态和路线缓存 |
| M2 自由分仓纯配送 | 按车辆复制路由、时间和分仓联动变量，增加对称性 | 重复重建相同分仓任务，完整评估成本高；大实例初始路线较差 | 紧凑流精确入口；分仓任务复用、静态缓存、初始固定分仓路线预搜索 |
| M3 固定分仓取送 | 配送/回收任务翻倍，车辆索引时间与载荷 Big-M 松弛较弱 | 同一固定任务集下反复模拟不变路线 | 紧凑货物流模型；缓存路线时刻表与距离 |
| M4 自由分仓取送 | 每仓、每车都复制全部客户任务；分仓、时序、载荷弱松弛互相放大 | 80% 固定分仓移动每次重新生成评估器；分仓与路线搜索竞争预算 | 紧凑流；复用分仓评估器与路线缓存；小实例候选初始分仓预搜索 |
| M6 固定分仓接力 | 无接力上界和松弛下界重复调用昂贵 M3；证书不闭合后才进入完整交接 MIP | 路线搜索与接力阶段分配时间；接力未必能弥补较差的基础路线 | 加速两次 M3 求解；限制热启动补全时间；继承固定路线缓存 |
| M7 自由分仓接力 | 原逐个处理 S^n 个分仓，许多分仓只是为了证明不能改善；全局松弛弱 | 比 M4 多出分仓池和交接搜索；缺少 M4 的末段交换优化 | 更强全局松弛与筛选分仓枚举；继承 M4 缓存；阶段一交换检查 |

既有小规模数据中，M1 ALNS 原来已是 66/66 命中最优，不能再宣称它的最优值质量有提升。相对地，M4 的困难实例在 15 秒精确预算下存在没有可行解或明显偏离最优的情况；这是需要优先解决的实现问题。M6/M7 的机制更宽松，并不保证独立、限时、不同搜索轨迹的 ALNS 每次都优于 M3/M4。

本轮首轮精确结果中，22 个 M6 实例都通过无交接上界与严格下界闭合完成证明，目标值与对应 M3 一致。这说明在这组小规模参数下，交接机制本身没有进一步降低最优距离的空间，不是“程序没有找到交接”就必然算差。相反，大规模 ALNS 即使找到有收益的交接，也可能因为阶段一基础路线偏差更大而最终输给 M3/M4；应分别检查基础路线成本、交接净收益和总目标。

大规模固定分仓还存在数据本身的不可行情形。例如既有审计已经给出 Set2_200-10-3 中 C93 的直接到达下界晚于截止时间的证据。这种情况无法靠增加 ALNS 迭代消除，结果中须与“构造器未找到可行解”分开解释。

## 2. 新精确模型及等价性

实现位于 `models/routing/common/commodity_flow.py`。M2/M3/M4 默认使用此模型；`backend="indexed"` 可以调用原车辆索引完整 MIP。M1 默认保留原方法，可显式使用 `backend="commodity_flow"` 做交叉验证。原 `model.py` 均保留，历史实验仍可复现。

### 2.1 消除同质车辆编号

每条 E1 弧设置二元变量 x；每仓的 E2 弧设置二元变量 z，但不再为同质车辆编号复制。每个服务任务入度等于出度，固定分仓时等于 1，自由分仓时等于对应 w[c,s]。仓库出弧数等于入弧数，且不超过车辆数。

整数可行解因此可分解为若干仓库出发并返回的路线，每条路线任意分配一个车辆编号即可。原模型的任意可行车队解也可删除车辆编号映射回此模型。独立顺序变量排除客户子环，包括距离与服务时间都为零时的子环；不能只依赖时间推进消除它们。

### 2.2 用四类货物流替代载荷 Big-M

对每条弧分别记录尚未配送的重量 D^w、体积 D^v，以及已回收的重量 P^w、体积 P^v，并施加：

```
D^w_ij + P^w_ij <= Q * z_ij
D^v_ij + P^v_ij <= V * z_ij
```

在配送任务，D 的流入减流出等于配送量；在回收任务，P 的流出减流入等于回收量。仓库出发弧没有回收货，返回弧没有待配送货。这准确重建了“初始装载全部配送货物，沿路配送卸货、回收加货”的载荷过程，包含重量和体积两种约束。

这些流是连续变量，但不会允许整数路线上的货物随意分流：每个已服务任务只有一条入弧和一条出弧。每条路线上的流守恒唯一确定实际货量。不需要按车辆重复整套时间、载重传播约束，也减少了与容量相关的 Big-M。

### 2.3 使用绝对任务时间

任务时间满足自身时间窗、弧上的行驶及服务时间。E2 首任务不得早于 E1 送达该仓并完成服务后的到达时间；该仓 E1 回收任务等待所有 E2 路线返回。每个客户的回收时间不早于配送完成时间，两个任务分属不同车辆时同样成立。保留 TFp 的启用语义。

时间 Big-M 按源节点最晚时间和目标节点最早时间计算，时间上界由实例窗口、任务总数、最大行驶时间和服务时间构造。路线容量、车辆数、分仓、先送后取、两级同步、目标距离都没有近似化。

### 2.4 上界与计时

建模后给 ALNS 一个很短的初始解预算，按 M1/M2/M3/M4 分别最多 0.05/0.1/0.2/0.5 秒；总预算很小时进一步缩减。只将找到的可行路线作为离散 MIP Start，连续时刻和货物流交给求解器重建。该时间以及建模时间均从新后端的总墙钟预算扣除，输出分别记录 build_time、warm_start_time、mip_runtime。

### 2.5 模型规模与具体困难实例

在同一 `Set1_12-2-4` 上，M2二元变量从1020降至264，约减少74%；M4从4924降至854，约减少83%。M4约束从25050降至3626。连续货物流仍需要变量，因此总变量的下降比例没有二元变量那么大；主要收益来自减少离散对称性、去除载荷Big-M并强化容量传播。这些计数来自同预算对照记录，而非只比较运行时。

该实例原M4在15秒求解预算下没有incumbent；新模型在第一轮对照返回395.182的可行解，在全量15秒批次中以383.522完成最优证明，墙钟11.598秒。两次新运行的差别也说明短时MIP搜索和热启动受运行时环境影响，不能保证重复运行耗时相同。

同一实例原M7返回462.356、下界346.156，尚未证明；最终M7在15秒预算下以383.522闭合证明，实际墙钟7.318秒。M6则原本已经得到441.304的正确上界，但下界只有298.694；改进后同一上下界闭合。这区分了两种收益：M7提高了限时可行解质量，M6主要缩短证明时间，不能把后者写成最优目标值变好。

## 3. M6/M7 的证明机制

M6 保留完整异步同质空箱交接模型。首先求无交接 M3 可行上界，再求去除 E2 回收载荷后的严格松弛下界。新 M3 后端加快这两步；只有上下界闭合才停止，否则继续完整交接 MIP。热启动连续子问题的时间不再独立固定占用 10 秒，而受剩余预算限制。

完整 M6 还增加了服务访问与单纯会合访问的条件时间界，并利用“第一次正量交接不能早于第一次回收”剪除不可能的弧。车辆对称性仅使用一个由初始配送重量和首事件顺序组成的组合排序键，避免同时施加两种不兼容排序而误删可行路线。无交接可行上界始终保留；完整模型限时无解或返回更差 incumbent 时仍能返回该上界，同时保留有效下界。

M7 的全局松弛保留配送货物与容器的重量、体积，以及 E1 回收量，仅放松 E2 已回收空箱的载荷。在距离满足既有度量检验时，可以从任意接力路线删除额外会合访问并捷径化，得到不更贵的松弛路线。因此松弛提供有效下界，但松弛路线不能自动当作 M7 可行解。

这里还必须检查行驶时间的三角不等式：仅距离满足条件，无法保证捷径路线仍满足时间窗。共享证书检查现同时验证距离和时间，并预先读取矩阵以减少重复对象查询；不满足条件时禁用捷径证书。标准实例的时间由欧氏距离和固定速度生成，因此本轮标准实例的证书适用范围不受这一补充检查影响。

对于不能立即闭合的小规模 M7，使用全局松弛筛选完整分仓：

1. 在当前可行上界以下寻找尚未处理、可能改善的分仓；
2. 对该分仓调用完整 M6，保存可行解及有效下界；
3. 在下一次筛选中排除已处理分仓；
4. 时间未耗尽时继续处理未闭合的 M6 子问题。

这是完整分仓枚举的筛选方式，不依赖启发式路线池，也不添加未经证明的子问题成本割。全局下界是“剩余分仓松弛下界”与“已排除但未闭合分仓下界”的最小值。主筛选模型证明不存在其他改善分仓，仍不足以独立证明全局最优；任何低下界未闭合子问题都必须保留。对此加入了专门回归测试。

最终复核又消除了三处浪费。首先，全局松弛给出的路线会按原始回收载荷重新独立审计；审计通过时才允许将其作为M7可行上界，不能因为路线来自松弛就直接接受。其次，松弛已找到的完整分仓直接交给第一个M6子问题，不重建主筛选模型去找同一分仓。最后，未闭合分仓的追加时间只在尚未重试的分仓之间分配，最后一个得到全部剩余时间，避免时间预算尚余很多却结束。对应增加了真实Gurobi路线复核、首分仓复用和尾部时间分配测试。

度量检查也覆盖输入中尚未预分仓的客户，防止自由分仓问题在初始任务表缺少客户时漏查。若不能满足证书前提，则回退完整精确模型，不能用本批次欧氏距离实例的特性替代一般输入检查。

## 4. ALNS 改动与作用范围

`evaluation_cache.py` 缓存不变的物理距离、行驶时间和服务时间。路线距离键是 `(仓库, 完整节点序列)`；路线时刻表键还包含卫星仓和绝对发车时间。更改路线或发车时间会命中新键。缓存有容量上限。

M1/M3 固定评估器、M2/M4 无接力评估器使用缓存；M6 只在无接力的 M3 搜索阶段继承缓存。接力阶段的虚拟节点位置和载荷会改变，不能使用这套静态缓存。M4/M7 的固定分仓邻域最多保留 8 个分仓评估器，E1 汇总需求来自完整分仓，且每次仍检查新路线的全局同步。

共同引擎按“破坏—修复”算子对更新权重，利用模拟退火接受部分较差候选，并始终保存最佳可行解。缓存保留相同路线的计算结果，不缩减候选集合；但在时间退火中，每次移动发生的时间、重启点和算子权重更新时刻会随速度改变。因此即使评估语义完全相同，某个种子的最终目标也可能变差，必须以多种子配对结果验证质量。

M2/M4 的自由分仓修复同时比较插入位置和服务仓，计算量大于 M1/M3。M6/M7 还要把预算分给交接候选、分仓池及剩余时间补搜。实验中的交接候选抽样与固定路线搜索属于启发式范围，不能提供原问题下界，也不能保证自由分仓或允许接力的 ALNS 每次支配对应基础模型。完整精确模型则不采用这些启发式候选上限。

M7 阶段一在自己的预算内预留至多 0.05 秒做与 M4 一致的整客户交换与尾段交换，不向搜索提供已知最优值。

参数筛选与后续全量复核区分两个不同的M2策略。随机混入固定分仓移动（`fixed_route_probability`）没有显示稳定收益，仍默认0；先优化已有分仓的初始路线（`route_seed_fraction`）则在大实例上效果更稳定。后者仅在客户数>20且预算≥5秒时自动分配总预算的20%，先在同一分仓下调用M1路线邻域，再回到完整自由分仓搜索。整个过程保留最佳可行解，预搜索的时间和迭代数从主搜索额度扣除。

M4/M7 的 `seed_search_fraction` 仅在10–20客户且预算≥5秒时自动设为0.2。所有候选初始分仓共享至多 `min(1秒, 20%总时间)` 的路线预搜索预算及相应迭代额度，然后选择路线成本更好的分仓开始主搜索。这样减少“分仓本身不错，但初始贪心路线较差，导致过早丢弃它”的情况。3秒对照和其他规模保留原设置。完整迭代上限测试覆盖预搜索、主搜索和补搜之和，避免新增阶段悄悄增加计算额度。

M7客户数≥10且预算≥5秒时将阶段一比例设为0.9，否则为0.75；在所有大实例和小实例三种子上重新验证。M6从0.8提高至0.9在三例探针中表现较好，但全量初次验证出现退步，因此追加全部18例、两个种子、正反区块顺序的配对验证。34组有效配对中0.9有15胜、19负，平均改善0.342%，中位数为−0.075%，最差退步8.315%；按事先写下的选择规则，最终保留0.8。两个共同不可行样本仍完整保留。全部证据见总表和 `final_policy.json`。连续段反转（`ALNSConfig.segment_reversal`）仍默认关闭。选择按整套参数的整批结果进行，不按个别种子挑最小值。

命令行还有会掩盖算法能力的配置问题：默认 `alns_iter=1000` 可能早于时间预算终止，现提高至100万次；M7专属阶段一比例原来会被后续通用0.95覆盖，现仅赋值一次。配置与服务默认使用 `None/null`，由模型按上述规模和预算选择；显式比例仍优先。切换到精确入口时，缺失 `exact_time` 使用明确的300秒预算。精确入口有合法incumbent但尚未证明时，CLI打印 `[FEASIBLE]` 及上下界，不再显示成 `[FAILED]`。正式算法对照直接调用求解入口并统一100万次迭代，所以表中的收益没有混入这些CLI修复。

## 5. 实验解释与停止条件

采用同实例、同随机种子、同时间预算的配对对照，同时报告解质量与搜索次数。当前改动会改变单位时间内经历的搜索轨迹，所以不能要求每个随机种子都单调改善，也不能把每秒迭代数直接写成达到同等质量的加速比。

完整交叉模型回归、路线独立审计、所有新结果原始记录、以及大规模代表样本的验证都完成后，才采用最终版本。若继续增加邻域未能改善同预算结果，则撤回该改动，而不是通过增加预算把它包装为算法收益。历史结果保留；新总表以新批次为准，明确标注未证明最优的 M7 和大规模 ALNS 结果。

正式数据包含22个小实例、18个大实例；小规模ALNS每模型每实例运行42/43/44三个种子，大规模全量运行Seed 42，另外在代表样本与M6全量时间比例复核中增加Seed 43。精确全量先统一15秒，M7未证明者再独立运行90秒。对不同阶段不把预算累加后的结果称为“15秒证明”，也不把两阶段的平均百分比相加。出现两条因环境长时间中断而达到数万秒的记录时，原样保留并单独重跑，替代来源与阈值写入汇总；普通慢样本和普通失败不剔除。

最新合并记录为 `latest_exact_runs.jsonl`、`latest_small_alns.jsonl`、`latest_large_alns.jsonl`。每条记录有 `record_source`；精确记录还包含 `aggregate_result`，分别保留被选单次运行的路线/状态与跨独立运行累计的有效上下界。原始批次不会被覆盖。

评价顺序是：先检查输出路线是否可行，再检查精确证书是否属于完整问题，最后比较时间和质量。MIP 的有效 incumbent 是上界，不是“求解失败”；没有 incumbent、数据不可行和仅未证明最优是三种不同情况。ALNS 的 gap 只相对于同一模型已证明的最优值计算；没有精确参考时只报告距离及配对变化，不用 M4 的最优值冒充 M7 的最优值。
