# 模型3：不依赖顾客数门槛的通用加强

同一算法处理不同订单规模；没有按总订单数或每仓顾客数切换的开关。
业务可行域、固定归属、单批日历、箱池、费用与整数时钟由原模型保留。
下面的有效联系与松弛只改变求解表达和准备方法，不改变最优解的定义。

## 完整主模型的有效加强

每个任务恰好服务一次，因此内部相邻任务弧可以共享。具体车辆和趟次仍通过访问变量、
路线归属标识、边界弧及时间/载荷/因果序位联系确定。共享表达默认用于所有规模，
不用订单数阈值选择；显式 expanded 请求仍被尊重。

设趟次启用为二元变量 u_r，重量容量为 C_w。每趟的全部配送货物在出发时装载，
回收箱在回仓前不会卸下。因此，原可行路线必定满足：

    sum_{配送任务 i} w_i visit_ir <= C_w u_r
    sum_{回收任务 i} w_i visit_ir <= C_w u_r

体积同理。对整数路线，这些联系不排除原方案；对分数松弛，防止少量启用承担整趟载荷。
各仓的必要趟数为配送重量、配送体积、回收重量、回收体积与对应容量之比向上取整的最大值。
至少需要这么多非空趟次，故可以直接加入主模型。以上规则不含规模分类。

## 按仓组合输入型下界

每仓先建立合法弧的连续流覆盖松弛：每个任务一个入流、一个出流，满足必要出发/返回次数，
释放整条路线的连通、载荷传播、车辆日程及跨趟同步。任何原整数路线均可投影到该LP，
故LP的最优值是该仓二级距离的下界。LP未达到最优时，不使用其可行原目标值作下界，
保留入弧/出弧最小费用之和的解析下界。必要时还可退到非负距离下界0。

剩余准备时间自动在仓间分配。可完成枚举的仓使用完整放松车次任务集合的整数划分下界；
未完成仓保留上述有效下界，其他仓已完成的工作不会被丢弃。

一级运输使用所有活跃仓与中心仓的无向最小生成树下界，其边权为两方向距离的较小值。
原多车回路的并集连通并覆盖全部节点，成本不小于该树。预算允许时再计算最短距离闭包上的
访问回路下界；动态规划未完成时不使用部分状态的目标值。单仓直接往返的必要距离也保留。

原总运输距离分别不小于各个独立下界，非负费率下可按原费率相加；固定箱池及恒定费用只计一次。
非负工时、车辆和趟次等费用在下界中释放。完整主模型仍按全部原费用优化。

## 不完整枚举与初解

不完整车次库的最小值可能高于真正的路线最小值，不能用于提高主模型下界。
部分车次只参与候选生成；只有完整仓库的划分模型才允许贡献下界。

确定性的时间排序合并法在原容量与时间窗下生成候选车次。完整调度模型副本先尝试生成的车辆、
趟位和访问顺序，若失败且仍有预算则解除这些固定，再尝试候选分组。
副本中的任何限制都不写回原主模型。只有副本找到完整原业务可行调度时才供应内部初解；
最终还需原完整主模型的原生最优状态和独立成本/两周期审计，才能发布最优证明。

## 资源控制与结果口径

下界准备与初解准备各最多占当时剩余预算的25%，且各不超过5秒；枚举另受50万搜索前缀限制。
这些是对准备工作量的统一保护，不是对业务规模或路线长度的限制。所有准备从总预算扣除。
数学有效性不依赖准备能否完成，通用优化也不保证所有规模、所有实例都同样快。

`route_strengthening` 记录各仓LP、完整性、划分证据与组合下界；`internal_start` 记录副本各次尝试。
`proof_scope`、最终原生状态与 `gurobi_best_bound` 仍属于完整主模型。
`route_strengthening=False` 恢复原expanded冷启动入口，便于同输入、同预算对照。
