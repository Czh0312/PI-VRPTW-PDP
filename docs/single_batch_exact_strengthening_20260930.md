# 单批次 M1–M4 精确求解：安全收紧与分仓域树

## Material Passport

- Origin Skill：academic-research-suite / experiment-agent。
- Mode：run / validate；连续实施用户授权的单批次精确算法优化。
- 范围：当前 B=1、固定整数时间刻度、有限物理车队和每车趟次限制、两级距离目标。
- 原始证据：`output/experiments/single_batch_strengthening_20260930/`。
- 验证状态及性能结论以本文末尾的实际执行结果为准；不承诺任意规模均能证明最优。

## 实现

`formulation.py` 保留共同建模入口，在 B=1 时分发至 `single_batch_formulation.py`。
这样可以独立优化单批次模型，保留共享文件中正在开发的多批次逻辑。
四个编号模型的公开 API、输入格式、目标、车辆资源、顾客窗、箱池、tick 和零 MIPGap 要求不变。

### 一级时间界

令 `A_s` 为仓 s 完成卸货的时刻，`l(i,j)` 为包含所有网络节点的松弛最短行驶时间，
`u_o` 为顾客 o 的最迟配送服务开始，`P` 为二级出车准备时间，则任何为 o 供货的仓满足：

```text
A_s >= 批次开始 + 一级装货 + l(总仓,s) + 仓服务
A_s <= min(u_o, 本批截止 - 顾客服务) - P - l(s,o)
```

固定分仓取该仓全部订单上界的最小值；自由分仓按对应分仓变量条件化，
仓级无条件上界仅取所有候选订单上界的最大值。未激活仓的 A_s 固定为零。
一级访问时间与访问二元变量用显式上下界绑定，并保留回总仓、卸货、清洗、整备的必要时间。
所有间接行驶时间下界均使用松弛最短路，不假设直接距离满足三角不等式。

### 载荷与因果序位

载荷有效上界不超过额定容量、全体箱的最大可能载荷，以及体积容量乘最重单位体积载荷。
配送服务后的载荷上界再减去本次配送数量；回收服务后的载荷下界至少为本次回收数量。
体积为零或容器重量为零时分别处理，不作除零或遗漏货物重量的推导。

T 个必服务任务最多使用 T 条非空二级路线；其任务节点加各路线起终点不超过 3T 个。
任何可行因果图均可用 0 至 3T−1 的拓扑序位表示，故将辅助序位上界收紧至该值。
时间仍保持原来的整数 tick；此处没有把时间约束改成连续近似。

### 趟数排序与路线槽

同一仓的同质车辆可按使用趟数从多到少重编号。若按 1 开始编号，第 v 辆使用 k 趟，
则前 v 辆合计至少使用 vk 趟；每趟至少服务一个不同任务，因此：

```text
k <= floor(候选任务数 / v)
建模槽数 = min(业务规定的每车趟次上限, floor(候选任务数 / v))
```

模型同时施加相邻车辆趟数非增约束；可行初解按同样顺序重编号并压紧趟次编号。
这删除等价的车辆标签表示，保留所有原有可行方案的等价代表。
自由分仓使用该仓可能接收的全部候选任务数作为安全上界。
同仓各车辆/趟次共用已经筛选的弧集合，避免重复做相同的时间可行性判断。

## 自由分仓算法

联合模型规模按实际时间可行弧数和上述槽位数量计算；默认不超过 120,000 条二级索引弧时联合求解。
阈值是避免大规模一次建模的工程选择，不是业务约束，也不是已证明最优的调参值。

更大模型采用分仓域树：每个节点代表顾客可选仓集合的笛卡尔积；选一个顾客按其各仓拆分，
子树之间不重叠，且完整覆盖父树。过大的节点继续拆分，可控节点求解其联合模型；
单一分仓叶节点调用固定分仓模型。固定到同仓的需求已超一级容量时，可用必要条件整体排除该树。

节点只有在被证明最优、被证明不可行，或其安全下界不能改善已审计 incumbent 时才能闭合。
每次分支继承父节点下界，未访问与未闭合节点必须继续计入全局下界。
实现校验“已闭合分仓数 + 开放子树覆盖的分仓数 = 域过滤后的全部分仓数”。
`assignments_closed` 按子树覆盖数量累计，不能将树节点数误当分仓数。
限时结束会保留 incumbent、开放域数量及全局 Gap；完整枚举仍可显式指定为对照。

大模型先对初始、近仓与单顾客迁移等最多64个分仓构造可行初解，总时间上限为
`min(0.2秒, 总预算×5%)`。这些候选只提供可行上界，不限制联合模型或域树的搜索范围。
固定分仓热启动最多占总预算20%；其最优或不可行状态不传递为自由分仓全局证明。

## 实验协议与限制

固定6个Zhou案例：7顾客两例、10/12/20/30顾客各一例；每例运行M1–M4，共24项。
每项10秒（包含求解入口内的建模和搜索）、seed=42、Gurobi单线程；每项外层硬超时为额外20秒。
输入在全部运行前统一冻结，每个候选版本分别保存源码快照。失败、无解和退步均保留。
这是单次短预算诊断，不是全93例正式评测，也不作统计显著性或普遍加速结论。

`before/` 是修改前基线，`candidate1/` 保留首次结构调整结果；它暴露了联合模型缺少初解的退步。
因此增加了有界分仓初解探测。`after/`保留初解探测版本；随后保留原始分仓作为固定分仓热启动入口，避免用构造解质量替代其潜在最优值判断。最终版本在`verified/`，不能逐项挑选候选版本的最好值。

## 验证结果

- 全库回归：**438 passed**，14 条绘图库弃用警告；执行约42秒。新增测试覆盖独立枚举、完整分仓树、限时下界、不同趟数的车辆重编号、零容器维度、非度量矩阵和初解限时保留。
- 额外差分检查：24个案例（4模型×6个非对称/非度量随机种子），改为2辆一级车、每仓3辆二级车、每车3趟，与冻结的修改前MILP逐项比较；24/24最优值或不可行结论一致，所得方案均通过独立审计。
- 正式对照采用 `before/` 与 `verified/`：两版均为 **16/24 已证明最优、22/24 有审计合格方案**。其余两项均为20/30顾客M3在10秒内未找到解，不能标记为不可行。
- 22组有方案的配对中：**3组距离改善、18组一致、1组退步**。没有挑选中间候选版本的最好值。
- 稳定的结构变化：10顾客M1变量787→615，M3为3912→2998，M4为12307→11091；M4二级路线槽48→43。
- 7顾客首例M4整次运行耗时2.15→1.08秒，10顾客M4为7.34→5.48秒，12顾客M2为9.86→8.53秒；这是单次观测，不能解释为普遍或统计显著的加速。
- 20顾客M4由枚举改为联合模型，距离1194.724→1126.358；30顾客M2由枚举改为联合模型，距离1027.822→1016.264；30顾客M4采用分仓域树，距离1156.134→1074.521。大规模Gap仍大，未解决大规模全局最优问题。
- 退步完整保留：30顾客M1距离783.503→871.431（约11.2%变差），但其下界改善，Gap从23.94%降到18.55%。这说明更强的模型在有限预算内仍可能得到较差incumbent。
- 开发中观察到其他Python求解进程同时消耗CPU；`after/`阶段的小例耗时整体波动明显。性能结论保持诊断性；新版输出增加求解工作量和节点数，便于后续资源一致的比较。
- `final/`保留一次导入失败批次：共享文件并行改动后出现重复`mip_work`关键字。已修正，重新通过语法及全库检查，再冻结`verified/`源码完整执行24项。
