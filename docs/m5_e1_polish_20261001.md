# M5 第十一步：一级路线与二级时刻联合改进

日期：2026-10-01。

本轮增加一级路线重优化和二级时刻联合调整。50 顾客完整可行目标从 **2724.7144 降到 2386.7494**，减少 337.9650，约 12.40%。同一 60 秒总预算下，与上一轮一级/二级列生成证书合并后，gap 从 **25.0039% 降至 14.3844%**。完整 MILP 使用该方案作为热启动后，其自身 gap 从 44.6261% 降到 36.7851%。

这次改善来自可行上界，下界没有提高。一级子问题最优不意味着完整 M5 最优；生成的完整方案都经过周期、载荷、时间和容器守恒独立审计。

## 1. 入口和求解范围

```python
from models.routing.variants.model_5.exact import reoptimize_e1, solve_exact

improved = reoptimize_e1(
    problem,
    audited_result,
    time_limit=5,
    retime_e2=True,
)

# 可选的完整 MILP 热启动：重优化计入原 60 秒总预算。
result = solve_exact(
    problem,
    time_limit=60,
    initial_result=audited_result,
    e1_polish_time=5,
    distance_cuts='components',
)
```

`retime_e2=False` 默认固定整个二层日程，只重优化一级。设为 `True` 保留每趟二层任务访问顺序、仓点、车辆及趟位，允许联合调整出发、服务和回仓时刻。二层距离及其固定访问序列下的载荷曲线不变。

完整 MILP 入口的 `e1_polish_time` 默认仍为 0。开启后，一级重优化最多使用指定上限和当时剩余预算的三分之一，剩余时间进入原完整 MILP。没有提供初解时，先在原预算内构造已审计初解。该选项只改变热启动，不固定完整 MILP 的二层路线或时刻。

实现见 [`multibatch_e1_polish.py`](../models/routing/solvers/exact/multibatch_e1_polish.py)、[M5 重优化入口](../models/routing/variants/model_5/exact/primal.py)、[M5 完整求解入口](../models/routing/variants/model_5/exact/solver.py)。

## 2. 为什么需要调整二层时刻

先固定二层实际时刻，按实际二层卸箱完成时刻固定每个订单的回收截止归属，按实际二层发车时刻收紧一级供货期限。三个中大型案例都完成了这个一级子问题，均未改善现有最佳起始方案。

将二层过早发车的约束固定，会限制一级合并路线；回仓时刻固定也限制了截止回收数量的重新安排。因此第二种模式保留二层访问顺序，同时引入实际二层出发、服务和回仓时刻变量，让一级与二层同步关系共同决定日程。

与上一轮下界模型的区别是：这里不允许独立虚构各订单回仓时刻。同一二层趟次的全部回收任务共享该趟真实卸箱完成时刻，并以此计算各仓、各批必须全部回运的容器数量。

## 3. 保留的完整可行性条件

一级使用上一轮的完整配送后回收路线枚举，并保留整数回收量、有限车队、批次返回期限、清洗期限及累计干净箱库存。

二层每条固定路线保留原始逐弧行驶时间、服务时间、任务时间窗、同订单最短使用时长、一级供货与二层准备同步、回仓卸箱、最后回收截止和周期末周转。同车趟次按原趟位顺序串行；下一趟的准备时间也占用车辆，不能只检查出发时刻晚于上一趟返回。

最多四个实际服务仓且一级周转为零时，采用完整一级路线主问题。批次不重叠，各批选中路线数不超过车数，故可分配给真实车辆。一级有正周转或实际服务仓更多时，使用保留跨批物理车辆连接的一级弧模型，不把用于下界的车辆身份松弛直接当作可行方案。

路线成本不依赖度量距离。同一仓可在一级配送阶段和回收阶段各访问一次；二层物理位置可重复访问，但任务序列和既有因果关系保持不变。

候选方案重建一级实际事件，并按求解结果重建二层全部时刻。只有完整独立审计合格、目标严格改善的方案才替换初解；限时或没有改善时保留原方案，输入对象不被修改。衍生库存和账本重新审计生成。

## 4. 证明字段

重优化结果是完整可行上界。`best_bound` 和 `mip_gap` 不从这个受限子问题生成，完整 M5 的 `proven_optimal`、`proven_infeasible` 均为 `False`。

`e1_subproblem_optimal` 和 `e1_subproblem_lower_bound` 仅描述固定二层序列的一级/时刻子问题。它们不能当作全局 M5 的最优标志或全局下界。若继续完整 MILP，其最终证明和全局界由完整模型独立产生；若结合列生成证书，gap 使用独立的完整目标下界。

## 5. 可行上界验证

三个案例使用上一轮完整 MILP 输出作为起始方案，因此 30 顾客的起始值已为 1665.7022，而非上一轮固定上界比较表中的 1689.5352。不能把这项已有改善归因于本轮算法。

每个案例对「固定时刻」「允许重排时刻」分别运行种子 42、43、44，预算 5 秒，共 18 次，所有输出均通过完整独立审计。

| 顾客数 | 已有起始可行值 | 固定时刻后 | 联合重排后 | 本轮改善 |
|---:|---:|---:|---:|---:|
| 20 | 1437.4738 | 1437.4738 | 1437.4738 | 无 |
| 30 | 1665.7022 | 1665.7022 | 1665.7022 | 无 |
| 50 | 2724.7144 | 2724.7144 | **2386.7494** | **337.9650** |

50 顾客的三个种子都得到相同目标。种子 42 的一级趟数从 9 趟降至 6 趟，27 趟二层中有 14 趟的出发时刻改变，访问顺序及车辆不变。一级距离从 1388.2530 降到 1050.2881，二层距离保持 1336.4613。本次联合日程子问题约 0.25 秒完成。小样本不支持通用求解加速结论。

见 [独立重优化多种子记录](../output/experiments/m5_e1_polish_20261001/final_standalone_5s/summary.json)。另对 7 个已知精确小例分别运行两种模式，共 14 次；均保持原已知最优目标和完整可行性，没有产生新的全局证明，见 [小例记录](../output/experiments/m5_e1_polish_20261001/final_small_5s/summary.json)。

50 顾客另作完整 MILP 同预算热启动对照，均开启分项距离证书约束：

本轮 40 次正式运行均成功，保存冻结输入、源码、初解、参数、日志和完整结果。执行脚本见 [run_formal.py](../output/experiments/m5_e1_polish_20261001/run_formal.py)，通用工具为 [`benchmark_multibatch_e1_polish.py`](../tools/audit/benchmark_multibatch_e1_polish.py)。
