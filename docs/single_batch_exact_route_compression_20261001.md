## 模型变换

上一版本已经共享任务的时间、载荷与内部弧传播约束，但内部弧的二元变量仍在每个
“仓—车辆—趟次”组合中重复。现在保留两种表达，默认根据原内部索引弧数量选择：
小于10,000条继续使用原结构；达到10,000条时使用共享内部弧与路线归属。
该阈值是本次诊断后的工程选择，不是业务上限，也没有被证明是最佳阈值。

令任务 i 表示一笔订单的配送或回收，r 表示唯一编号的物理路线槽：

```text
v[i,r] = 1：任务 i 属于路线 r（保留原访问二元变量）
R[i] = Σ r·v[i,r]：任务 i 的路线编号
z[i,j] = 1：任务 i 与 j 在同一路线上相邻
z[i,j] = 1 ⇒ R[i] = R[j]
```

每项任务仍在全局恰好访问一次，因此整数解中 R[i] 自然是某个实际路线编号，不需要额外整数变量。
每项任务的全局入度、出度均为1；其起终弧仍按车辆和趟次分别建模，并要求端点被该路线访问。
每条使用的路线仍恰好有一个起弧和一个终弧，未使用路线不允许访问任务。
原来的全局因果序位沿每条选中弧严格增加，也保留配送先于回收、同车下一趟晚于上一趟的关系。

**可行方案的双向对应：**

1. 任意原模型可行方案中，每项任务只访问一次，因此每一对相邻任务至多对应一个真实路线。
   将原来的内部索引弧合并为 z，按实际路线赋 R，可得到新模型的可行方案，目标不变。
2. 任意新模型整数解中，度约束将任务分成路径或环；严格因果序位排除所有环。
   选中内部弧的两端路线编号相同，路径的起终弧又绑定到该路线访问变量，因此每条路径属于
   唯一物理路线。每个启用路线恰好有一个起终弧，所以不会产生同一路线下的多条断开路径。
   把路径上的共享弧放回对应索引，即恢复原模型的可行方案，距离不变。

保留原始起终点时间、初始载荷、内部载荷传播、准备/卸货/周转、容量、回收截止、库存清洗等约束。
非度量距离、同地点多任务、零时间和跨趟回收没有额外假设。共同内部弧的成本只计一次。

## 求解流程与工程处理

- `single_batch_formulation.py` 缓存同仓任务与安全弧集合，按规模选择压缩；
  `compress_routes=True/False` 可显式指定表达用于对照，`share_e2=False` 仍使用原逐路线任务状态。
- `solver.py` 先把共享弧初始值统一清零，再汇总所有初始路线的选中弧，避免被其他路线的零值覆盖。
  提取日程时，只读取两端任务属于当前路线的共享弧，并保留连通性检查和独立审计。
- `strengthening.py` 按实际不同二元弧数量估计联合模型规模，超过120,000条时仍进入完整分仓域树。
  30客户M4因此能够采用较小的完整联合模型；全部合法分仓仍被覆盖。
- 压缩后数量减少不等于问题容易，初解探测及固定分仓热启动的5,000条触发阈值仍使用原索引规模。
  新增诊断字段 `estimated_indexed_e2_arcs`；`estimated_joint_e2_arcs` 表示实际表达下的二元弧数量。

数学约束、车队数量、每车趟数、整数tick、距离目标和零MIPGap要求保持不变。
取得可行解与证明最优仍严格区分。M5建模与ALNS不使用本轮压缩逻辑。

## 协议与保留记录

相同6个已冻结的 Zhou 案例 × M1–M4，每项总求解预算10秒、seed=42、Gurobi单线程，
外层硬超时增加20秒。每阶段单独冻结源码、阶段内串行执行，全部中间结果保留：

- `before/`：本轮修改前基线。
- `compressed/`：全部规模启用压缩，小案例出现证明最优退步。
- `final/`：按4,000条原内部弧分流，但压缩估计意外关闭了一部分既有热启动。
- `verified/`：修复热启动触发口径，仍使用4,000条切换阈值。
- `work_comparison.json`：相同审计初解、15个Gurobi工作单位的成对诊断；20客户M3的退步仍存在。
- `selected/`：交付版本，提高切换阈值至10,000条，保留中小模型的原结构；整批结果用于正式前后比较。

这些样本参与了实现选择，不能作为独立泛化验证集。限时结果受机器负载影响，未做统计显著性检验，
不声称普遍加速。特别是变量减少并不保证线性松弛更强或所有案例的证明速度更快。
初次测试中“每个微型案例变量必然减少”这一断言不成立，已改为仅验证最优性等价；
预检查直接判不可行的结果没有audit字段，测试已正确处理。测试脚本的一次缩进错误也保留在日志中。

## 最终10秒对照与限制

`before/` 对 `selected/`：24/24均有审计合格方案，无运行错误。
**1项目标改善、20项持平、3项退步；证明最优从16/24变为15/24。**
因此交付结论是大模型规模降低、部分下界和解质量改善，不能声称整体证明速度提高。

- 30客户M3：距离1114.311 → 979.877，Gap32.48% → 21.94%。
- 20客户M4：Gap76.50% → 52.38%，但距离986.142 → 1082.987，属于上界退步。
- 30客户M2：Gap72.39% → 52.52%，但距离940.051 → 950.524。
- 20客户M3：距离804.610 → 860.669，交付模型保持原结构，仍如实计入退步。
- 12客户M2：取得相同最优目标280.921，但10秒内未完成证明，报告限时及4.92%的Gap。

相同墙钟预算内的工作量明显变化，记录在 `wall_budget_diagnostics.json`。
这说明运行环境/时间截断是混杂因素，不能把所有墙钟结果差异直接归因于模型改动；
也不能据此排除真实的搜索性能退步。本文保留最终整批结果，不跨版本选取每例最好值。
