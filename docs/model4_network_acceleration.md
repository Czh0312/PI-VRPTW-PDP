# M4自由选仓网络表达加速

2026-10-30。迁移M3载荷流和送取先后强化，并参考M8车辆对称处理。
优化目标仍为原两级总距离；分仓、顾客集合、车辆、时钟、送取窗口、同车串行和循环闭合规则保持。
不读取历史方案、最优值或M3/M8的实验输出来指导求解。

## 与固定分仓的区别

M3的分仓路线下界和整数划分以订单已经固定到各仓为前提，不能直接当成M4下界。
M4改为一张跨候选仓的任务图：内部弧每条计一次，离仓和返仓弧仍保留物理车辆与趟次编号。
顾客到仓的分配变量、每仓服务覆盖和完整原路线身份约束继续生效。

每条二级弧同时携带未配送货物与已回收空箱，分别对重量、体积设连续流并按容量归一化。
两种流之和不超过弧启用量乘容量。离仓时回收流为0，返仓时配送流为0；每个配送任务消耗
对应的货物流，每个回收任务产生对应的空箱流。各趟离仓货物流和返仓空箱流分别等于该趟
服务的配送量和回收量。所有候选仓共享任务守恒式，不把未选仓错误地当成仍有强制需求的仓。

任何原合法整数路线都能以其真实车载物投影到这些流；反过来，在选中的整数路径上，
守恒和零边界条件唯一确定每段未配送量及已回收量，恢复原车载重量、体积。
因此可替代二级条件载荷传播，保持原整数可行域。原时间和人工因果顺序继续排除零时间环；
不以净载荷抵消作为连通证明。一级载荷传播保持原表达。

## 先后关系与车辆重新编号

原模型的每单配送在回收之前、每条所选弧上的因果顺序严格增加。
若两条弧与这些必要先后关系形成环，它们不能同时选择，显式加入二元冲突不等式。
选中回收出弧或配送入弧时，还可将同单送取最小使用间隔合并到时间联系中；
未选弧的松弛系数按原任务窗口计算，保证不施加额外物理限制。

M4已有按每辆车非空趟数递减排序，不能再无条件套用M8的首任务编号递增排序。
这里按趟数为第一排序键，仅在相邻车趟数相同时按首趟首任务编号递增；
趟数不同时显式松弛第二排序键。相同趟数的同型车辆可整体交换日程，故不丢失物理方案。

## 接口与验证范围

公开 `solve_exact` 默认启用 `network_strengthening=True` 并选择compact表达；
显式expanded表达仍受尊重。关闭该选项恢复原默认expanded冷启动。
独立 `build_model` 默认关闭该项，原有 `strengthening` 配置仍可单独选择。

首轮性能实验仅选当前 `formal_benchmark27_uniform_7_20_50_v1` 的S02：7顾客，
两版均单线程、种子42、总预算300秒，串行运行。保留输入、两版源码、完整结果和独立两周期审计。
总时间包括加载、建模、优化、提取和独立审计，解释器启动及环境预检另计。
原版与新版同时改变了压缩表达、载荷流、静态冲突和对称约束，该单例不能拆分各组件贡献，
也不能据此断言全部小规模、其他规模或多种子的稳定收益。

等价性单元检查以独立穷举核对自由选仓、非对称非度量距离、零距离和紧容量情形；
另检查趟数与首任务排序兼容性。性能实验之外的这些小型构模检查不扩展正式算例或实验种子。
