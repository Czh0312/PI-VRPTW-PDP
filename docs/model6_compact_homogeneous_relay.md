# Model 6：同质空箱异步交接紧凑精确模型

## 1. 模型边界

Model 6 保留 Model 3 的固定分仓、E1/E2 路线、配送与延后回收、容量、时间窗、
先配送后回收以及 E1–E2 同步约束，并增加同一前置仓 E2 车辆之间的空箱交接。

为避免 Model 5 的“回收任务 × 交接点 × TP/TD/RP”节点展开，Model 6 采用以下
业务边界：

- 空箱型号相同、可替代，以整数数量计量；
- 交接只能发生在已有顾客配送/回收事件对应的物理地点；
- 发送车和接收车访问同一个事件副本，但允许“先放入临时库存、后取走”的异步交接；
- 转出的原生空箱必须随发送车进入交接点，禁止在回收原点原地留下的零承运接力；
- 一辆车可为交接专程参加事件，但没有服务或交接时不能产生无意义访问；
- 每个空箱最多发生一次车辆间交接；
- 交接车辆属于同一前置仓，禁止跨仓交接。

因此，Model 6 是上述完整事件交接范围的全局精确模型。它与允许任意独立
`TP/TD/RP` 操作的 Model 5 具有不同可行域，二者的目标值用于比较建模口径和求解
性能，不能把 Model 6 的最优性证书直接当作 Model 5 的最优性证书。

## 2. 核心变量

- \(x_{ijk}\)：E1 车辆弧变量；
- \(z_{ijv}\)：E2 车辆弧变量；
- \(s_{iv}\)：车辆 \(v\) 是否执行事件 \(i\) 的顾客任务；
- \(a_{iv}\)：车辆 \(v\) 是否访问事件 \(i\)；
- \(g_{ivh}\)：事件 \(i\) 中车辆 \(v\) 交给车辆 \(h\) 的整数空箱数；
- \(G^w_{ijv},G^c_{ijv}\)：弧上的配送重量与配送体积；
- \(O_{ijv}\)：弧上的原生空箱，即本车直接从顾客回收、尚未中转的空箱；
- \(R_{ijv}\)：弧上的接力空箱，即从其他车辆接收的空箱；
- \(T_i\)：顾客任务的服务时刻；
- \(A_{iv}\)：车辆 \(v\) 访问事件副本 \(i\) 的时刻；
- \(y_{ivh}\)：车辆对在事件副本上是否发生正数量交接。

## 3. O/R 空箱流

对 pickup 事件 \(i\)，令 \(q_i\) 为产生的同质空箱数。车辆 \(v\) 的原生空箱
守恒为：

\[
\sum_j O_{ijv}-\sum_j O_{jiv}
=q_i s_{iv}-\sum_{h\ne v}g_{ivh}.
\]

接力空箱守恒为：

\[
\sum_j R_{ijv}-\sum_j R_{jiv}
=\sum_{h\ne v}g_{ihv}.
\]

交接只出现在第一条式子的减项中；接收量只进入第二条式子。模型不存在从 \(R\)
中扣除的交接变量，所以已接力空箱无法再次交接。这在不追踪空箱来源身份的情况下
严格保证每箱最多中转一次。

此外加入：

\[
\sum_{h\ne v}g_{ivh}\le \sum_j O_{jiv},
\]

保证发送车只能转出进入该节点前已经承运的原生空箱，排除在回收原点“服务后原地
暂存、发送车从未承运”的建模漏洞。

弧容量直接写为：

\[
G^w_{ijv}+w_c(O_{ijv}+R_{ijv})\le Q^w_v z_{ijv},
\]

\[
G^c_{ijv}+c_c(O_{ijv}+R_{ijv})\le Q^c_v z_{ijv}.
\]

配送流、原生空箱流和接力空箱流都是连续弧变量。由于车辆路径为整数路径、pickup
供应和交接量为整数，它们沿路径的实际载量仍为整数；只有 \(g\) 需要声明为整数变量。

## 4. 服务事件交接

每个配送/回收任务恰由一辆车服务：

\[
\sum_v s_{iv}=1,\qquad s_{iv}\le a_{iv}.
\]

交接要求发送车和接收车都访问事件副本：

\[
g_{ivh}\le C a_{iv},\qquad g_{ivh}\le C a_{ih},\qquad v\ne h.
\]

任务服务车辆满足 \(A_{iv}=T_i\)，非服务车辆可在时间窗外专程到该物理地点接收。
若 \(g_{ivh}>0\)，则用激活变量施加异步先后关系：

\[
A_{ih}\ge A_{iv}+s_i.
\]

因此发送车可先放下空箱，接收车稍后到达。事件 \(D_c\) 和 \(P_c\) 的实际任务服务
仍保持各自时间窗，并满足：

\[
T_{P_c}\ge T_{D_c}+s_{D_c}.
\]

## 5. 精确性口径

`models.model_6.solver.solve_exact` 默认先解无中转可行上界与零回收载荷严格松弛。
在距离满足三角不等式时，任何M6接力路线删除交接专程访问并捷径化后，都会映射为
一个不更贵的松弛可行解。因此松弛下界等于无中转上界时，可直接证明完整M6最优。
证书不闭合时，入口再构建上述完整事件集合、同仓全部车辆对和全部合法路线弧；完整
MIP请求 `mip_gap=0` 且Gurobi返回 `OPTIMAL` 时同样得到精确解。两条路径都会设置：

```text
solution_type = proven_optimal
proven_optimal = True
proof_scope = compact_async_event_handoff_model6
```

时间限制下的 incumbent 固定标为 `feasible_not_proven`。历史固定路线第二阶段模块
`transshipment_mip.py` 仍供 ALNS/历史实验使用，但不参与新的精确入口。
