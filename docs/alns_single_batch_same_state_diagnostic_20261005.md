## 1. 为什么补做同状态诊断

对上一轮 M3 30/60 秒试验的原始改进历史进行事后分段统计：短预算候选在策略启用前的 80% 时点，平均已比基线差 **9.0138%**；最终平均差 **9.2386%**。八对的初始目标相同，但墙钟冷却和停止条件会使两次运行的探索路径不同。

这说明不能把最终退步全部归因于末段选择器。这里没有证明外部负载造成了退步，也不能把两个均值相减当作策略的因果贡献。旧试验的同墙钟拒绝结果继续有效。

证据：[旧试验分段统计及原始文件哈希](../output/experiments/alns_single_batch_same_state_20261005/previous_wall_stage_analysis.json)。

## 2. 如何保证从相同状态出发

先冻结当前 models/configuration/config/tests 的 384 个源文件及三组业务输入，再登记新诊断。与上次源码相比，本轮包含共享目录中其他聊天已完成的公共模块更新。仅在实验快照内添加观测入口，并复制已拒绝的多样化枚举实现供机制比较，未写入生产目录。

每个 M3 作业先运行一次共同前缀。在总迭代数的 80%、首次下降枚举前，通过独立 Python 进程的 `fork` 复制完整内存。两个分支继承相同的当前解、最好解、随机数状态、算子权重、评价缓存和其他缓存。子进程跑完后，父进程才继续另一条分支；基线先行与候选先行交替安排。八组共享状态均保存压缩快照及 SHA，两个分支的入口 SHA 全部一致。

短档为 **10,000 迭代**：50/100 顾客各三种子 551、552、553；长档为 **30,000 迭代**：另一组 100 顾客、种子 551、552。墙钟上限设为不触发的 10⁹ 秒，外层每个进程组仍有 600 秒硬超时；冷却由迭代进度主导。固定迭代不意味着等评价次数、等 CPU 或等墙钟，相关实际计数分别保存。本诊断不具备生产采用资格。

正确性检查：

- 现有下降、晚期回收接受、时间预算和求解审计等定向检查 **201 passed**；lazy pickup prefix 所在生产文件保持原字节。
- 关闭观测入口，两组 100 顾客 × M1–M4、固定 500 迭代的 **8 对/16 次**，线路、分仓、目标及相关统计逐项复现生产基线。
- 两组 100 顾客的 **2 对/4 次基线对基线分支**，从入口到最终输出一致，并匹配未插桩的公共入口结果。
- 上述 20 个保存解均通过无缓存新鲜解码、固定/自由分仓独立审计及周期重放，目标一致。

在任何 fork 作业前发现并修正了辅助 CPU 汇总字段：子进程的 `process_time` 会重新起算，应使用“实测共同前缀 CPU＋当前分支 CPU”。旧脚本和旧执行哈希完整保留。分支 CPU 本身原已正确；没有修改搜索、输入、种子或采用标准，已完成的非 fork 复现结果不受影响。

## 3. 同状态下的候选多样化结果

距离变化为每对 `(多样化/基线−1)×100%`，负值表示更好。

| 固定迭代分组 | 平均距离变化 | 改善/相同/退步 | 最大单次退步 |
|---|---:|---:|---:|
| 短档，50/100 合计 | +0.5314% | 1/2/3 | +3.0450% |
| 短档，50 顾客 | +1.0150% | 0/2/1 | +3.0450% |
| 短档，100 顾客 | +0.0478% | 1/0/2 | +0.2586% |
| 长档，100 顾客 | −0.0014% | 1/0/1 | +0.8087% |

八对入口状态一致，全部完成登记迭代数。16 个最终解均重新无缓存解码，完整独立审计和周期重放通过，目标一致。长档两个结果接近抵消；短档仍有整体退步。保持多样化关闭，没有再次运行上一轮已取消的确认矩阵，没有调规则、换种子或挑选子集采用。

这组结果降低了“原来约 9% 的差距全部来自选择器”的解释可信度，但新试验使用不同种子、固定迭代和更新的公共代码，不能直接分解旧试验差距。CPU 含观测开销、分支路径工作量不同且机器负载未控制，不作为提速证据。

证据：[逐对目标、CPU、评价次数和分层汇总](../output/experiments/alns_single_batch_same_state_20261005/diagnostic_comparison.json)、[16 解新鲜审计](../output/experiments/alns_single_batch_same_state_20261005/diagnostic_fresh_audit.json)、[原始作业及负载记录](../output/experiments/alns_single_batch_same_state_20261005/diagnostic/workers.json)。

## 4. 罚分诊断：只追加违反程度不能跨越当前障碍

八个共同前缀只计一次，加上 16 条后续分支，共记录 **133,203 次非空提案决策**。这些决策包含评价缓存命中，不是 133,203 次独立完整解码，也不是独立统计样本。

所有观测到的当前解均可行；其中 **67,052 次提案不可行，全部从可行当前解出发，其模拟退火接受概率在浮点计算中均为 0**，没有接受不可行提案。当前全局评分含每条违反规则 10⁶ 的罚分。

因此，对这批已观测决策，仅在现有罚分上再加非负“违反程度”项，不会让这些接受概率变为非零。降低或替换原罚分、允许短暂不可行搜索是另一种算法，尚未验证，不能由本结果宣称无效或有效。最终最好解的完整可行审计必须继续保留。

证据：[完整计数、算子分层和计数口径](../output/experiments/alns_single_batch_same_state_20261005/acceptance_observations.json)。

## 5. 对真实拒绝提案的车辆关联链修复：不进入在线试验

在读取共享快照的缓存条目前预登记单一规则：每个状态从最新缓存向前，最多取 8 个“距离低于当时最好解、唯一解码违反类型为 E2_TIME_WINDOW”的真实搜索提案。没有符合项则保留空结果，不补选状态。

从晚到客户或晚归线路出发，加入同一物理车辆的前序趟次，以及回收任务对应的配送线路，展开两层依赖。按线路索引取最多 12 条关联线路；逐条改派到同仓其他物理车辆，保留所有任务、线路顺序和一层方案，每个原提案最多 32 个变体。该依赖集合是关联范围，未证明其中每条边都在真正阻塞时间的关键路径上。

新增 4 项依赖闭包、两层边界、空线路映射及缓存状态重建检查全部通过。对全部 8 个共享状态，共找到 **13 个符合项**，生成 **100 个变体**；每个原提案和变体都新鲜解码并执行完整独立审计，全部成功及失败原始记录保存。

**100 个变体中，完整可行解为 0，改善为 0。** 其中 89 个仍有时间窗违反，11 个产生时序环；70 个另有终端未回收问题，各违反类型可重叠。四个共享状态没有符合项，也保留在 8 个状态的完整分母中。

登记准入要求至少两个不同共享状态改善，且覆盖 50 和 100 顾客。本试验未达到，因此不实现或启动该规则的在线质量候选。它只否定本次有界车辆改派方案的准入，不能证明完整的一层供货、配送—回收和车辆日程联合修复不存在收益。

证据：[修复登记](../output/experiments/alns_single_batch_same_state_20261005/chain_protocol.json)、[修复检查日志](../output/experiments/alns_single_batch_same_state_20261005/chain_tests.log)、[100 个变体汇总](../output/experiments/alns_single_batch_same_state_20261005/chain_totals.json)、[完整准入决定](../output/experiments/alns_single_batch_same_state_20261005/chain_decision.json)。全部逐方案状态、解码结果及审计保存在实验目录 `chain_results/`。
