## 2026-10-05 基础版调整：等长批次、共同分界

先研究均匀分批，再把各批分界不同时长与批次长度不同作为后续扩展。基础版通过 `schedule_mode=uniform_cycle` 实现：周期总长H固定；K为正整数决策，L=H/K；第b批开始s_b=t0+(b-1)L、结束e_b=t0+bL，分界c_b=s_b+d。所有批次共用整数分界时长d，满足m≤d≤L-m，m为显式最短阶段时长。因此同一个方案内，各批的第一阶段、第二阶段分别等长，绝对钟点不同。

订单分批、N及两级路线仍联合优化原成本目标。K变化会重建全部批次起止，不能只减少旧候选日历中的配送启用数。K为全周期的划分数，有配送的批次和实际空箱回运轮数另行报告；关闭配送的周期区间不会被误称为已删除的时间段。固定候选日历下逐批截点自由的旧实现保留用于历史复现。

精确算法逐一枚举K，用共同d的独立MILP求解，其全局最优值为各可行K最优值的最小值。所有K均已证明最优或不可行才声明全局最优；否则保存各K下界、限时状态和已得方案。ALNS逐一探索K，所有截点同步移动，共用整个调用的时间与迭代预算。初始可行解须通过同一均匀允许域审计，不继承原最优证明。

输入仍保留顾客绝对送取窗、release_time、需求、固定分仓、道路、车辆、清洗及费用。新日历覆盖整个cycle_start到cycle_end，包括原日历尾部的空白；末轮总仓卸箱加清洗必须在cycle_end前完成。第二阶段仍允许二级回收；本轮全取量依据二级卸回前置仓完成时刻≤c_b确定，迟到空箱留待后续回运。没有按箱数乘清洗时间，也没有新增清洗排队假设。

2026-10-07：默认允许全部满足 `1≤K≤floor(H/(2m))` 的正整数，m=1分钟仍为显式场景约束。上界由有限周期和两阶段最短时长推出，不再由原批数或1/2/3列表决定。均分需要分数刻度时，为每个K单独细分时钟并记录倍率，保持原物理分钟与严格等长批次；不要求K整除原周期刻度。显式K列表仅用于历史复现和诊断。重新划分仅接受原allowed_batch_ids覆盖所有原批次的订单，已有时间/批次限制不得静默放宽。

| 候选领箱、配送截止、一级回仓时刻 | 给定 | 给定 |
| 订单配送批次 | 给定 | 在合法候选集合内决策 |
| 启用配送批次数 | 给定 | 由订单分配决定 |
| 容器池规模 | 给定 N | 整数决策 N，可设预算上限 |

| 成本处理 | 对距离方案后处理 | 进入两个求解器的评价与搜索 |

M6 首版沿用固定分仓、同质容器、无永久损失、整单送取、总仓清洗、周期末全池清洁归仓。一级每物理车每候选轮次最多一趟，每仓每轮配送和回收各不拆分；二级有限物理车可多趟，每趟最多携带一个配送批次的货物，可以回收此前订单。暂不增加自由选仓、连续发运时刻、清洗产能或随机损失决策。

**配送批次启用与回收轮次要分别定义。** 候选时段 b 的配送启用变量只表示该时段是否发出货物。各候选时段的回收截止仍然保留；即使没有配送订单，截止前入仓的应取空箱仍须由显式的纯取趟次回运。纯取趟次计入车辆、趟次、距离和工时，不能通过关闭配送批次取消回收义务。这保留 M5 的截止全取规则，也保证两模型具有相同的回收机会。联合优化回收轮次启用属于后续不同策略，不能混入首版比较。

## 输入与合法分批

候选时段按时间顺序记为 b=1,…,Bmax，每个时段给定领箱时刻 a_b、配送与空箱资格截止 c_b、一级卸回期限 e_b，周期结束 H。沿用现有阶段衔接，下一候选时段从上一阶段结束开始；没有配送的候选时段也不从时间轴删除。Bmax 是候选时段数，启用配送批次数由求解决定，可以退化为一次配送。

每笔订单 i 给定顾客、固定前置仓 s(i)、箱数 n_i、货重、绝对配送窗、绝对回收窗、服务时长、最短使用时长，以及独立的货物可领用时间 release_time_i。后者限制领箱装货时点，不等同于顾客服务开始窗。M5 的原输入没有独立货物释放字段，M6 需新增；缺失时必须显式登记“全周期开始前备货”等情景，不能默认为真实已备货。

每笔订单给定 allowed_batch_ids，可由货物释放、仓供货最早到达和顾客时间窗必要条件筛选，不能按一次启发式失败删去候选。定义 E_i 为合法候选集合；若 E_i 为空，应报告结构性不可行及证据。合法候选只是必要筛选，实际路线仍需满足完整交接与送取约束。

原 delivery_batch_id 可保留为 M5 对照或初解，M6 不把它当作固定订单约束。单纯把现有输入的 model 改为 6 不构成数据适配。顾客窗口、货物释放和周期时刻在两个求解器与各对照之间保持一致，不随分批结果平移。

新增案例配置应显式包含：model=6、候选时段、订单合法批次、货物释放、容器池上下限、两级车队与二级趟次上限、经济参数配置路径及证据登记路径。采用独立策略标识 joint_batch_cost_v1，不能用 M5 的结果格式伪装成 M6 已优化结果。

## 核心决策与容器约束

令 y_ib∈{0,1} 表示订单 i 归属候选时段 b，z_b∈{0,1} 表示该时段启用配送。必须满足：

```text
sum(b in E_i, y_ib) = 1                         每单唯一分批
y_ib = 0 for b not in E_i                      禁止非法时段
y_ib <= z_b                                   有订单则启用配送
z_b <= sum(i, y_ib)                            无订单不算配送批次
D_sb = sum(i: s(i)=s, n_i*y_ib)                 各仓各批箱数
D_b = sum(s, D_sb)                             各批领箱量
B_used = sum(b, z_b)
1 <= N <= Q, N integer, Q = sum(i, n_i)         非空订单、初始全池清洁、无损失
```

不设置“启用时段必须连续”的对称约束，因为跳过中间配送时段可能是必要且最优的合法安排。N≤Q 只限制容器供给范围，不保证路线、容量和服务时间可行。

二级每趟的配送批次变量与所有所载配送订单 y_ib 一致；不同配送批次货物不能混装。两级供货衔接、每仓不可拆分容量和车辆连续占用均依据新 D_sb 和货重重新建立。回收订单可以来自多个配送批次，但必须在配送完成及最短使用时长之后、且落在原绝对回收窗内。

设 u_i 是订单空箱二级卸回前置仓的完成时刻，q_sb 是该仓本轮应回运箱数。在初始空箱为零、各轮全取下：

```text
q_s1 = sum(i: s(i)=s, n_i * 1[u_i <= c_1])
q_sb = sum(i: s(i)=s, n_i * 1[c_(b-1) < u_i <= c_b]), b>1
```

截止等号归本轮。截止分类要由实际时间双向确定，不能把已经符合本轮条件的箱子任意推到后轮。q_sb>0 时必须存在一级取箱访问，并一次全取；q_sb=0 不制造空取任务。

若 R_clean(a_b) 是截至 a_b 已完成总仓卸箱及清洗的累计箱次，每个候选领箱时点必须满足：

```text
N + R_clean(a_b) >= sum(h<=b, D_h)
```

同一时刻先处理清洗释放，再处理本批领箱；累计释放是箱次，可包括同一实体箱的多次周转。固定路线与时刻表的最小池为 max_b{sum(h<=b,D_h)−R_clean(a_b)}。这是该时间表的最小池，不能当作联合问题已证明的最小池。

末批全部回收必须在最后候选截止前完成二级卸箱，一级在对应期限内卸回，H 前清洗完成并恢复车辆可用。完整账本及连续两周期重放沿用现有因果、守恒要求，且审计必须接受并核对新的分批结果。

## 成本目标及证据条件

首版采用成本组成互不重复的口径：

```text
min C = k_N*N
      + sum(l in {E1,E2}, d_l*L_l + w_l*H_l + f_l*K_l + g_l*T_l)
      + c_clean*Q_return + c_track*Q_issue + C_container_wear
```

L_l 为实际道路公里，H_l 为明确边界内的付费/分摊工时，K_l 为实际启用的不同物理车辆数，T_l 为实际非空运输趟次。纯取趟次全部计入 T_l。不得将车辆数按每批重复累加，不得将候选时段数当作趟次。g_l 只有存在与其他费用不重叠的实际按趟收费时才启用；每批固定费同理，不为诱导批次数少而编造收费。

距离项若只含能源与公里维保，才另加人工与车辆固定项；若采用含人工、折旧、保险的全成本运价，就要删除已包含的组成。自有闲置车辆的不可避免费用属于常数，不能宣称少出一辆车就节省全部日固定支出。按启用车辆计费需匹配可避免租赁或明确的成本分配用途。工作分钟必须声明是否包含装卸、趟内等待、趟间待命与交接班；只计路线占用时间时，结果不能称完整企业损益。

**容器池成本不能机械采用购价除以使用次数。** 固定 Q、购价 P、按使用次数寿命 U 的线性磨损分配为 QP/U；减少 N 不会自动降低该项。清洗和跟踪在固定全额送取、单价不变时也可能是常数。常数可在求解目标中省略，但总费用和两算法比较时必须一致补回。

k_N 必须来自与评价期匹配、且排除其他重复费用的池规模成本证据，首版支持以下互斥计价设计：

- 按实体箱和时间收取的池租赁费：先核对租赁合同是否包含磨损、清洗、回运；已包含的项目不得另外收费。
- 自有箱：资金占用或机会成本按实际资金成本和持有期换算；使用磨损另按 QP/U 分配。日历老化只有有适用证据时才另计，资金成本不能再次包含已计磨损。

购置投入 PN 单独报告。若评价目标改为有限期购置、补购与残值的折现现金流，应另立明确的评价期和更换/残值模型，不能将 PN 与同一购置款的全部折旧相加。模型6首版不声称已实现该现金流扩展。

参数记录数值、单位、含税口径、地区、价格基期、箱型或车型、来源机构、原始 URL、页码/段落、核实日期、公式输入、成本组成、适用限制和不确定性。证据分为同业务实测、匹配公开参照、跨业务代理、未核实情景；来源权威不能代替规格与场景匹配。

当前核实结果和未解决项见 [模型6成本证据](../reference/cost/06_model6_cost_evidence_20261004.md) 与 [机器登记](../reference/cost/model6_cost_evidence_20261004.json)。现阶段没有可宣称全部适用参数已实测的人民币基准。未知参数保持 null，不能用 0 代替。合成机制例可明确提供人工单位参数用于算法验证；正式成本结论需匹配的证据与计价范围。跨业务代理只能支撑明确假设下的条件分析。

没有可信 k_N 时，先研究不同 N 上限下的最小运营费用前沿，单独报告 N、车辆、趟次、距离、工时，不能用任意权重宣称经济最优。成本相同的合法解可按 N、趟次排序，仅用于展示；若作为求解的次级目标，必须显式记录，并对每层分别判断证明情况。

## 精确求解部分

独立目录：[model_6/exact](../models/routing/model_6/exact/README.md)。已实现完整联合 MILP，包含 y_ib、z_b、N、两级路径、车辆启用、二级趟次、实际作业时刻、截止归属、取箱量和清洗释放。未调用 M5 求解器，未采用依赖固定分批的距离剪枝。

候选时段、时间刻度、车队及趟次上限是证明范围的一部分。截止分类和清洗释放用双向二元链接，严格不等式通过一个整数时间 tick 表达；不使用大于0的浮点容差改变归属。变量箱数与释放资格的乘积以 Q 的有限上界线性化。车辆启用为所有对应趟次启用的逻辑或；工时、趟次和里程必须和独立成本审计一致。Big M 来自周期、窗口和容量界，不使用未说明的无限大值。

只复用经证明仍对 M6 有效的容量、时间和守恒工具。M5 依赖固定分批、固定 N 或距离目标的下界和剪枝必须重新证明，不直接加入 M6 的成本模型。精确内部初解不得依赖 ALNS；可由公共的非搜索校验工具或精确部分自身构造，ALNS 也不加载 Gurobi。

输出最优可行成本、成本下界、gap、状态、证明范围、各组成及资源指标。仅完整模型取得相应最优证明且独立审计通过时，才标记 proven_optimal。限时有解、限时无解、已证明不可行分别记录。证明成本最优不等于证明 N 全局最小，须分别报告。

## ALNS 求解部分

独立目录：[model_6/alns](../models/routing/model_6/alns/README.md)。状态包含订单分批、两级任务序列、二级车辆趟次与时间调度选择；配送批次启用可由订单归属推导。

在没有容器数量影响服务/清洗产能的首版范围内，给定完整时间表可计算最小可行 N，因此解码器可消去独立 N 搜索：按账本计算所需池，检查池上限，按实际池规模计费。若池成本为0，则明确采用最小池作为同成本表示。以后加入依赖 N 的非单调机制时，这种消元需重新验证。

破坏与修复必须覆盖跨批订单迁移、批次合并/拆分、关闭/重新启用配送批次、配送和回收路线重新组合、二级物理车复用顺序、可行等待与跨截止调整。跨批移动整笔订单的配送归属，回收保留订单身份和因果；不能强行把回收也绑到同一配送批次。

每个候选重新计算各仓需求、一级供货、二级送取日程、截止取箱量、一级回运、清洗释放、容器峰值和成本。需要专门保留能够赶上截止的时间选择；只使用单一最早时间解码器的搜索限制必须披露。缓存包含分批、时序和成本配置哈希；只缓存总距离不能代表完整成本评价。

搜索可用有单位说明的自适应违约罚项帮助修复，但最终输出必须完全可行、独立审计通过；罚分不报告为经济成本。每个算例使用多随机种子与统一预算，报告全部尝试、可行率、最佳/均值/变异、耗时和相对成本界。启发式未找到解不等于已证明不可行。

## 模型目录与公共接口

```text
models/routing/model_6/
  exact/model.py           完整联合 MILP
  exact/solver.py          精确求解、解提取与目标核对
  exact/batch_search.py    精确求解的 K 搜索预算与证明汇总
  alns/solver.py           联合分批、路线、调度与成本 ALNS
  alns/batch_search.py     ALNS 的 K 搜索预算与结果汇总
models/common/cycle/
  joint.py                联合业务实例与独立审计
  uniform.py              等长共同分界的实例与审计
```

M6 已加入运行时 catalog，使用独立输入与结果适配，solver=exact/alns 按需加载；两个求解器不互相导入。公共实例、成本计量与审计分别位于 `models/common/cycle/joint.py` 与 `models/cost/joint_batch.py`，不依赖任一求解器。ALNS 的调度传播、候选评价、构造和路线修复代码均在本模型的 `alns/` 内，不调用其他编号求解器；业务规则、成本与独立审计仍统一维护。未恢复历史已归档的旧 M6。

ALNS 对固定客户事件与回仓时刻，将二级出发时间推迟到第一项服务前恰好可到达，避免在途中承担可转移到仓内的等待工时。该调整不改变客户时刻、截止归属或清洗释放，之后仍完整独立审计。内部等待尚由最早因果传播及显式等待算子决定，不声明该时间解码器覆盖所有调度。

公共结果需包含 schema_version、model=6、strategy、candidate_schedule、order_batch_assignment、delivery_batch_activation、delivery_batch_count、recovery_rounds、container_pool_size、E1/E2物理车辆与趟次、完整时间表、账本、cost_components、cost_basis、economic_profile_hash、evidence_hash、price_basis、audit、求解状态与证明字段。回收轮次与配送启用分开序列化，冻结副本同时保存输入、参数、证据及代码哈希。

## 实验与验收

首先构造可手算的机制例：分批使箱池下降但运输增加；同成本不同 N；无配送但必须纯取；恰好截止与恰好清洗释放；合法候选集合为空；早知道订单但货物未释放；一辆车多趟而只收一次车辆固定费；非零成本项导致距离最优与费用最优不同。精确与 ALNS 输出按同一审计核对，不用人工费用例证明真实经济效益。

正式比较包含 M5 现有距离方案的费用评价、同一固定分批下的费用重优化对照，以及 M6 联合分批费用优化。中间的费用对照作为实验配置明确标识，不偷偷改写 M5 的正式目标。这样可以区分目标变化和分批自由度各自的收益。基线输入未通过 M6 的释放与服务约束时，记录不可比或不可行，不能静默放宽。

小例用精确法给出成本证明和 ALNS 误差；中大例采用多种子，并报告限时成本上下界。参数敏感性应重新优化，而不是只对同一条路线重新乘单价。各参数区间分别注明统计分位数、报价范围或人工扫描范围，不能将情景网格称为置信区间。不同候选时段密度和 N 上限可形成资源前沿，报告分批稳定性和成本差异。

可宣称“经济最优”的条件包括：目标成本组成完整覆盖声明范围、参数证据适用、输入与算法范围明确、获得相应证明。没有真实账单与工序记录时，只能表述为明确参数情景下的优化结果。本次4个机制例仅证明代码、约束与小规模算法表现；全部价格用 synthetic_units，不能推断真实经济收益或中大规模性能。

算例生成器为 tools/data/build_model6_demo_suite.py；对比入口为 experiments/runs/run_model6_comparison.py。对比包含 M5 距离方案的独立计价、M6固定原分批与原池、仅放开池、仅放开分批、完整联合求解；M5和联合M6的ALNS各用3个种子。原模型5距离最优方案的等待和同距离路径并非成本最优，因此联合自由度收益应同时参考 M6 固定成本对照。完整输入、价格、源码哈希、预算、路线、成本分项及失败/限时记录均保存。

较大场景转换器为 tools/data/build_model6_static_suite.py，保留原始数量和绝对时间窗，不扩大机制小例的箱量。物理业务仍包含原数据声明的派生及情景字段，释放时刻和费用假设另记。模型5预配N、所得时间表的最小所需N、全部运行中最小所需N分别报告，不把预设N称为最低需要。

独立资源分析位于 experiments/analysis/summarize_model6_resources.py。合法域只有一个候选批次的订单，其箱量必须同时在该批次发出，故N至少为各强制批需求的最大值，并至少覆盖最大整单箱量。若可行方案达到这一必要下界，可单独证明箱池最小。给定N时，各配送批最多发N个实体箱，因此B_used至少为ceil(Q/N)，并满足强制启用批数下界；达到时可证明给定箱池下的最少配送批次。这些资源证书不改变成本目标，不证明未收敛的MILP或ALNS已取得最低成本，也不证明允许增加箱池时仍至少要同样多批。

全量V2多批次筛查覆盖186个B2/B3配置，即93个基础场景，其中Zhou派生140个、LaDe派生42个、人工机制4个。生成器通过 `--all-multibatch` 保留全部原物理字段并显式记录释放与价格假设；比较器用隔离子进程并发、逐次原子保存结果，所有超时和无可行解状态不删除。首轮统一预算为精确3秒、ALNS每种子2秒、三个种子，共2232次计划运行；并发竞争、初始化和短搜索的限制明确披露。单批次B1和历史V1结果不混入。

汇总入口 `experiments/analysis/summarize_model6_full_suite.py` 分来源、配送点数量和候选批次数统计箱数减少/相同/增加、配送批次、距离及趟数变化，保留全部缺失对照、种子差异、资源下界证据以及已观察到的箱数/批次取舍。箱数基线为模型5各次已得时间表的最小需箱量，而非预配N=Q；模型6按已得最低测试成本选取，所以可能出现更多箱子、更少批次的合法成本最优解。联合与固定分批对照的取舍合并仅用于展示已观察到的可行资源组合，不归为联合算法单独贡献，也不声称已证明完整资源前沿。见 [全量结果](../output/model6_comparison/20261004_static_v2_full/full_summary.md)。
