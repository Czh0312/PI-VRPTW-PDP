**1．目标、已确认规则与实施默认值。**

目标：在固定大周期、有限容器池和有限车队下，联合安排多个串行一级批次、二级配送与延后回收，使每批均有足够清洁箱可用，并在大周期末恢复可重复运行的状态。批次数为 1 是同一新框架的边界情形。

用户已确认的业务规则：

| 项目 | 确认后的定义 |
| --- | --- |
| 一级批次结构 | 配送阶段结束后进入取回阶段；取回阶段结束后，才开始下一批配送 |
| 批次间关系 | 上一批一级取回与下一批一级配送不重叠 |
| 阶段长度 | 配送时长、取回时长是参数；5 小时 + 1 小时只是示例 |
| 取箱资格 | 本批配送阶段截止前，已由二级送回前置仓的空箱进入本轮回运 |
| 截止后入仓 | 必须留到下一轮，不能因大车稍晚到仓而顺带取走 |
| 本轮取箱量 | 截止前已入仓且未被取走的全部库存；不允许任意少取、漏取 |
| 容器供给 | 容器池有限，批次之间追踪真实周转，不逐批重置或补满 |
| 大周期目标 | 最后一轮完成全部外发容器回收，形成可以持续重复的系统 |
| 单批次关系 | 当唯一截点足够晚、所有空箱都已回到前置仓时，本轮完成全部回收 |

以下是为便于第一版实施而提出的默认值，不等同于用户逐项指定：

| 维度 | 第一版默认建议 |
| --- | --- |
| 订单、分仓 | 全大周期订单已知，固定订单所属配送批次，固定分仓 |
| 容器 | 单一规格、同质、无损耗；每个订单送出和应回收箱数相等，无中途采购 |
| 顾客服务 | 保留本单先送后取和各自时间窗；不允许车辆间在顾客点交接空箱 |
| 前置仓入库时刻 | 二级车回仓且卸箱完成；尚在顾客处、二级车上或卸箱中的箱子不算入库 |
| 一级路线 | 每辆物理车每批最多一趟，路线为总仓—配送段—取箱段—总仓，允许纯送/纯取 |
| 二级路线 | 每辆物理车可执行多趟，回收可跨越一级批次边界，必须检查实际车辆占用 |
| 同仓拆分 | 每仓每批一级配送不可拆分；每仓每轮取箱也不可拆分，由一辆一级车取完 |

| 初末状态 | 初始全池清洁可用，其他位置无箱；周期末同样全池清洁可用，车辆回各自基地 |
| 优化目标 | 首先固定 N，最小化两级总距离；工时、等待和池规模作为结果；费用目标后续接入 |

**2．统一时间轴，避免把截点、回仓期限和周期末混为一谈。**

设批次 b = 1,…,B，配送阶段时长为 D_b，回收阶段时长为 R_b：

```text
a_b：第 b 批配送阶段开始（第一版约定为集中领箱/装车开始）
c_b = a_b + D_b：本批配送阶段截止／空箱资格冻结时刻
e_b = c_b + R_b：本批一级完成回总仓并卸箱的期限
a_(b+1) = e_b：下一批开始
H：整个大周期结束；H >= e_B，可含最后清洗、准备的尾部时间
```

统一采用绝对时间，输入和图表单位为分钟，实际结果 JSON 使用显式标注的整数 ticks，时间单位见第 7 项。禁止每批时间重新从零起算后丢失真实先后关系。5 + 1 小时示例对应 a = 0、360、720；c = 300、660、1020；e = 360、720、1080（分钟）。

| 阶段 | 一级车辆 | 二级车辆与空箱 |
| --- | --- | --- |
| [a_b,c_b] | 装车、配送，完成本批所有一级卸货 | 配送、顾客延后回收、回前置仓；不要求全部在 c_b 前返回 |
| c_b | 冻结各仓本轮应取空箱 | 同刻完成的二级卸箱先入库，再冻结库存 |
| [c_b,e_b] | 取走冻结库存，回总仓并卸箱 | 可以继续服务/回仓；c_b 之后新增空箱归下一轮 |
| [e_B,H] | 不再自动生成额外取箱任务 | 仅做已明确安排的周期尾部处理，不用来隐藏迟回空箱 |

阶段起点采用“领箱/装车开始”是实施约定，避免非零装车时间被忽略。一级配送车在 a_b 领箱，在 a_b + 配置装车时长后发出，装车时间计入 D_b；若以后业务要求 a_b 是发车时刻，必须另设更早的领箱时刻，并在那里检查库存。

第一版建议把驶向首个取箱站的行程也算在回收阶段：混合路线在最后配送点完成配送后等待到 c_b，再前往首个取箱点；纯取路线从总仓不早于 c_b 出发。同一地点连续送取时等待到 c_b 才装空箱。不强制混合路线在两阶段之间先回总仓。不得把回收行驶提前塞入配送阶段来满足过短的 R_b。

每辆一级车本批回总仓、卸箱完成 <= e_b。复用同一车辆时，下一批装车开始不得早于上批卸箱完成；若另设车辆整备时间，也应计入。纯送和纯取车仍共用实际车队，不能各获得一套独立车辆额度。

**3．截止规则是数量等式，不是可选择的回收比例。**

设二级回仓卸箱事件 r 的时刻为 u_r、所在仓为 s(r)、卸入空箱数量为 p_r。p_r 由该趟实际完成的顾客回收任务汇总得到，不由对应配送批次的总箱量替代。

一般累计表达为：

```text
q_(s,b) = I_s(0)
          + Σ[p_r：s(r)=s 且 u_r<=c_b]
          - Σ[q_(s,h)：h<b]
```

q_(s,b) 是该仓第 b 轮必须取走的数量。本版前轮取箱均在下一截点之前完成，因此该式就是 c_b 时刻实际未取库存。初始 I_s(0)=0 时也可写成：

```text
q_(s,1) = Σ[p_r：u_r<=c_1]
q_(s,b) = Σ[p_r：c_(b-1)<u_r<=c_b]，b>=2
```

本轮所有实际一级取箱量之和必须等于 q_(s,b)。第一版同仓不拆分，q>0 时恰好一辆车访问；q=0 时无需创建空取箱任务。若冻结量超过单车重量/容积容量，不可通过少取来修复，应调整回仓安排、配置或明确报告该候选方案不可行。

必须同时维护“物理库存”和“本轮冻结库存”。冻结是预留，不是物理出库：箱子到实际一级装载时才从仓内库存扣除。冻结后新增空箱继续占仓容，但不能加入本轮一级车载量。

例如 c_1=300，大车 330 到仓：299 完成卸箱的 3 箱本轮取走，301 完成卸箱的 2 箱留到 c_2=660 对应的回收阶段。大车不能取 5 箱，也不能只取前 3 箱中的 2 箱。

**4．有限容器池必须按位置、状态和事件守恒。**

固定池大小 N。至少区分清洁可用、已领用/装货、正向在途、顾客处、二级回收在途、前置仓空箱、一级回收在途、总仓待处理/处理中。实现可以合并部分位置展示，但必须保证每个时刻每个箱子只属于一个物理状态；冻结标签不是第二份库存。

推荐采用以下事件账本：

| 事件 | 容器状态变化 |
| --- | --- |
| 总仓给批次领箱 | 清洁可用 -> 已领用/装货 |
| 一级装货发出、前置仓卸货、二级领货 | 在正向各位置间转移，不能再次扣总仓清洁箱 |
| 顾客配送/使用/回收 | 正向在途 -> 顾客处 -> 二级回收在途 |
| 二级卸箱完成 | 二级回收在途 -> 前置仓空箱 |
| 截点库存冻结 | 仅加本轮预留标签，不改变物理位置或总量 |
| 一级取箱装载 | 前置仓空箱 -> 一级回收在途 |
| 一级回总仓卸箱完成 | 一级回收在途 -> 总仓待处理/处理中 |
| 清洗检查完成 | 待处理/处理中 -> 清洁可用 |

设第 b 批需求 n_b = Σ[本批订单用箱量]，第一版在 a_b 集中领用。一级回仓卸箱事件 j 的完成时刻为 v_j、带回数量为 Q_j，固定处理时长为 τ，则清洁释放时刻 z_j=v_j+τ。在不考虑损耗和采购时：

```text
C_b^- = N - Σ[n_h：h<b] + Σ[Q_j：z_j<=a_b]
C_b^- >= n_b
C_b^+ = C_b^- - n_b
```

同刻清洗完成的箱子先释放，再执行领箱；这个顺序要与求解器和审计一致。v_j<=a_b 但 z_j>a_b 的箱子不能参与本批领用。一次回收量不得在多个释放事件中重复计数。

任意事件之后所有物理状态的箱量之和均为 N，各状态非负。累计配送使用次数可以大于 N；累计“送出次数等于回收次数”与“池中只有 N 个物理箱”应分开报告。

给定完整路线和时间表时，可以用“累计领箱量减累计清洁释放量”的最大前缀差计算该时间表需要的最小初始池，用于审计与敏感性提示；不能把它称作所有可能路线下的全局最小容器池。

清洗第一版只用固定时长和无限并行能力，所有实例必须显式给出 τ，零时长只能是注明的测试/情景假设。有限清洗能力、洗箱批量和排队另作扩展。

**5．二级作业可以跨批次，订单身份与物理地点必须分开。**

一级串行不代表全系统所有活动都按批次清空。二级车辆可以在一级回收阶段工作，某个早批订单的回收任务也可以由后续二级趟次完成。仍须满足顾客配送完成 -> 顾客回收开始的先后关系、顾客时间窗和固定分仓，不把“下一轮一级取箱”误写成“下一轮才允许二级回仓”。

建议第一版每个二级趟次最多装载一个配送批次的货物，但可回收该仓任意已经配送过的订单，包括早批订单。纯回收趟次不依赖当前批次是否有新配送。不给回收任务强行绑定其原配送批次。

二级路线使用实际物理车辆 ID 和有序趟次槽位，每车最多趟数作为显式参数 `e2_max_trips_per_vehicle`；槽位数量是模型边界，必须报告，不能当作无限多趟。是否使用各槽位、服务哪些任务与出发时间由求解决定。

每个配送趟次须在对应仓收到该批货物且完成准备后出发；同一趟不得提前领取未来一级尚未送达的货。每辆二级车上一趟回仓卸箱完成，再加必要准备时间，才可执行下一趟。未返回的旧批车辆不能在新批被重置成可用。

新数据采用独立订单表。订单至少包含 `order_id`、`customer_id`、`satellite_id`、`delivery_batch_id`、箱数、商品重量、配送/回收时间窗、服务时长，以及可选最短使用时长。一次订单的配送/回收数量一致。顾客物理地点可以重复出现多笔订单，矩阵仍按物理地点建立；任务 ID 采用独立订单 ID，禁止靠复制顾客节点或给节点名简单追加批次来混淆位置与业务身份。

最短使用时长未输入时为显式 0，不能再次叠加已经包含在回收时间窗生成过程中的使用延迟。订单释放、批次归属和顾客时间窗的定义应随数据保存。

**6．大周期闭合与单批次退化条件。**

第一版采用 `terminal_policy=all_clean_at_depot`：a_1 前全部 N 个箱清洁可用，周期末 H 前全部 N 个箱回到清洁可用状态；顾客、两级车辆、前置仓、待处理区均无遗留；车辆回到各自基地并满足下一周期首批准备条件。

最后一轮以后没有下一截点，因此所有带箱二级路线必须在 c_B 前完成回仓卸箱，所有应取箱在 e_B 前完成回总仓卸箱，所有箱子在 H 前完成处理。零箱二级路线也必须在周期末回基地并完成必要准备。

不自动延长最后期限、不偷偷增加免费收尾车、不把 c_B 后入仓的箱子塞进最后一轮。若需要末批更长的配送/回收时段，用显式 D_B、R_B；若需要额外收尾轮，必须作为显式批次列出、计入车时和费用，不能由求解器后台补出。本版默认不加隐藏收尾轮。

重复循环的验证应将同一个解平移 H-a_1，再重放两个大周期，检查所有边界；第二周期初始状态必须来自第一周期实际末态。仅检查全池总量等于 N 不足以证明可循环，因为箱子可能仍在顾客处或处理中。无损耗、确定性需求和参数按周期重复，是无限重复的建模前提，不声称覆盖随机丢箱或随机延误。

新模型内设 B=1，同时满足：所有订单属于唯一配送批次；c_1 不早于全部带箱二级路线卸箱完成；R_1 足够回运；H 足够处理；N 至少覆盖该批全部用箱量。此时全部空箱进入唯一回收轮，得到统一截止口径下的一批次模型。

兼容性说明：现有 `single_day_backhaul_v1` 没有统一全局取箱截点，允许某仓收齐后较早取箱。保留其文件和已验证结果。新模型 B=1 的精确退化基准应使用“同一截止、同一时间精度、同一容量和末端条件”的单批参考模型；不能无条件要求它与历史单日版的最优目标、等待量相等。这不改变两者“最终全部回收”的业务对应关系。

**7．时间精度、同刻事件与调度自由度必须在编码前固定。**

取箱资格的双向条件是“u<=c 必须本轮取，u>c 必须留下一轮”。只写一个方向会允许模型把已经入仓的箱子任意推迟。连续变量的严格大于和求解容差容易使两个实现采用不同规则。

第一版内部采用整数时间刻度，例如 `time_tick_seconds=1`，输入和图表显示分钟；实现时为保持保存后截止归属不变，结果 JSON 使用 ticks，并记录精度，分钟 = ticks × time_tick_seconds / 60。业务截点、阶段长度应是刻度的整数倍，否则输入报错；行驶/作业时长向上取整，时间窗下界向上、上界向下取整，记录原值、转换值及单位。距离目标仍用原距离，不将时间取整冒充距离变化。

在整数刻度上，u<=c 与 u>=c+1 精确划分。只在读取求解器数值时用很小容差确认变量接近整数，不能用容差把迟到一个刻度的箱子提前收走。这是离散时间版本的精确模型；不声称它与未离散的旧连续模型数值完全相同。若以后保留连续时间，必须另行定义边界政策和证明域，不能靠任意 epsilon 悄悄更换模型。

同刻事件采用由物理依赖决定的顺序：作业完成释放箱/车 -> 截点库存冻结 -> 领箱、开始后续作业。τ=0 时允许同刻完成卸箱、处理并释放，但必须记录这个显式假设；正时长作业禁止零耗时穿越。各物理状态转移只处理一次。

最关键的算法变化：新版输出必须含实际时间表。人为等待可能使二级回仓从本截点前移到截点后，改变本轮一级任务和后续供箱，因此不能拿完整路线重新计算一个“最早时间表”并继续沿用原回收批次/数量。新审计应验证输出时间表的真实性与可行性，不代替求解器重新安排时间；若重新调度，必须生成新解并重算全部数量和库存。

时间表中的可选择等待是模型决策，必须计入工时/等待指标。ALNS 如果暂只搜索最早调度，要标注其搜索限制，不能声称覆盖完整模型；正式版应具备跨截点的出发/等待调整算子。

**9．完整数学模型：先实现一个明确的精确后端。**

建议新建 `multibatch_indexed` 后端，以物理车、趟次和批次索引建立联合 MILP。旧 `commodity_flow` 与 `indexed` 保持原模型支持范围；第一版不同时重写两个旧后端，也不把旧模型套 B 次后拼接称作多批次精确求解。新策略请求不支持的后端时必须明确报错。

模型至少包含下列变量组与约束：

| 变量/约束组 | 必须表达的内容 |
| --- | --- |
| E1 路径与启用 | 每物理车每批最多一趟；仓配送任务按批生成；取箱访问是否存在取决于冻结数量 |
| E2 路径与趟次 | 每个配送/回收任务恰好服务一次，物理车辆与趟次槽位有序，可含纯回收趟次 |
| 连通与子环消除 | 不能仅依靠正行驶时间消环；同地点/零时间弧也必须正确处理 |
| 两级装载 | 商品与箱体重量、容积一致，逐弧检查载量；配送卸载和回收装载分别计算 |
| 配送同步 | E1 完成该仓该批卸货及必要准备，E2 才能装载本批货物出发 |
| 顾客先后 | 同一订单先完成配送，再开始回收；允许不同车辆执行 |
| 一级阶段 | 配送服务完成 <=c_b；进入取回阶段不早于 c_b；回仓卸箱完成 <=e_b |
| 截点分类 | 二级卸箱时刻与每个截点的双向关系；每份已收回箱量进入首个满足条件的回收轮 |
| 取箱数量 | 每仓每轮实际一级取箱总量 = 本轮截止冻结量，不允许自选少取 |
| 清洁箱释放 | E1 实际卸箱完成 + τ 决定可复用时刻，与后续领箱库存关联 |
| 有限容器池 | 每批装车前可用清洁箱充足，所有箱量均从初始池和真实释放产生 |
| 车辆重用 | 同一车辆上一趟卸箱及准备完成后才能执行下一趟，跨周期也成立 |
| 末端闭合 | 全部订单送取完成，箱子按最后截点回运且 H 前全池清洁可用 |

截点分类的建议线性表达：对实际启用的二级趟次 r，设 h_(r,b)=1 当且仅当其卸箱完成 U_r<=c_b。整数时间下使用双向约束：

```text
h_(r,b)=1 => U_r<=c_b
h_(r,b)=0 且 route_used_r=1 => U_r>=c_b+1
h_(r,b)<=route_used_r；h_(r,b)<=h_(r,b+1)
g_(r,b)=h_(r,b)-h_(r,b-1)，h_(r,0)=0
```

g 表示该趟返回空箱归属哪一轮。因为该趟取箱数量取决于所服务回收订单，不能直接在 MILP 中写“变量数量 × g”。可令 x_(o,r) 表示订单 o 的回收任务位于趟次 r，用二元 w_(o,r,b)=x_(o,r) AND g_(r,b)，再设：

```text
q_(s,b)=Σ[n_o * w_(o,r,b)：趟次 r 的基地为 s]
Σ_b w_(o,r,b)=x_(o,r)       # 每个已完成回收的订单均进入某一正式轮次
```

以上是实现骨架；所有未启用趟次必须有正确门控，避免空趟被强制安排回仓时间。实际顾客回收量 n_o 是常数。二级 route 可以混合不同原配送批次的回收任务，其归属由同一个实际卸箱事件决定。

一级每仓不拆分时，分配给某车的取箱量等于 q_(s,b) 与访问二元变量的乘积，需使用有效箱量上界进行标准线性化。清洁箱累计释放也涉及“该一级趟返回箱量 × 是否已在某批领箱前处理完成”，应显式线性化。所有 Big-M 和数量上界从大周期、时间窗及总需求推导，不能把既有 `TFp=9999` 同时充当业务时刻和通用 M。

精确后端必须联合优化两级路线、趟次、实际时间、截点归属、取箱量和清洁释放；先固定 E2 再优化 E1 的结果只能称为条件解。用小例手工枚举回收轮次与路线，配合独立审计检查完整 MILP。

首版目标为 min(全周期 E1 距离 + E2 距离)。N 是硬约束参数，清洗次数在无损耗、全回收情景下应由实际使用次数得到，不能按 N 一次性计入每个批次。等待与工时尚非优化目标时，应明确不宣称它们最优。

若研究最小池规模，后续可增加 `min_pool` 模式：首目标 min N，再以运输费用或距离为第二目标。也可以对固定 N 做可行性搜索，但只有精确不可行证明/有效下界能排除某个 N；ALNS 没找到解不能用来证明“最小需要 N 个”。在其余条件不变、初末都允许新增箱作为闲置清洁库存且没有总仓清洁箱库容上限时，N 增大不会破坏原可行解；这是可行性搜索的单调性依据。

**10．ALNS：搜索全周期状态，不能只在单日求解器外加 for 循环。**

新建独立 `MultiBatchSolution`，存储物理车、批次、趟次、路线、出发时间/等待决策、回仓事件、截点归属、清洁释放和全周期账本。沿用现有 ALNS 引擎中可复用的接受准则与权重更新，不让旧 `Route/Solution` 的浅拷贝丢掉新状态。

一次完整候选评价的顺序：

1. 验证订单分配、一级配送任务、两级车辆/趟次和路线容量；建立含时间窗、先后关系、车辆占用的实际时间表。
2. 根据 E2 路线的实际卸箱完成时刻，生成带数量的入仓事件和每轮冻结量。
3. 根据冻结量重建/更新 E1 回收任务及载量，验证阶段时间、所有应取库存覆盖和回总仓期限。
4. 生成 E1 卸箱、处理完成事件，逐批核对 N、清洁箱供给以及全周期初末状态。
5. 全部满足后计算目标与指标；任何调整时间或路线的修复必须返回第 1 步重新评价受影响链条。

这不是一次线性遍历就必然得到联合可行解：E1 配送时间影响 E2 回仓，E2 回仓影响 E1 取箱量，E1 回收又影响后批库存和车辆。候选必须携带明确调度；若采用传播/局部修复，应限制迭代并保留失败原因，不能在不断更改时间的循环中使用陈旧快照。

建议初始构造采用“先给出全周期配送骨架 -> 插入顾客回收 -> 生成截点量 -> 插入一级取箱 -> 修复缺箱/车辆冲突”的启发式；必要时后退调整前批路线，不把早批结果永久冻结。小例可以用完整 MILP incumbent 作为单独标注的热启动；默认 ALNS 仍应能够在没有 Gurobi 的机器上构造和搜索。

必须新增/适配的邻域：

| 邻域 | 作用与边界 |
| --- | --- |
| 同批 E1 配送换序/跨车交换 | 改变前置仓到货时刻，必须重新评价二级回仓与所有后批 |
| E2 配送/回收移动与交换 | 保持订单身份和顾客先后；回收可跨不同配送批次的趟次移动 |
| E2 趟次拆分/合并 | 让部分箱子更早入仓，或减少路线数量；保持物理车和趟次上限 |
| 截点邻域 | 调整出发、等待或回收顺序，让卸箱事件在某个截点两侧变化 |
| E1 回收换序/换车 | 改变总仓回运和清洁释放时间，检查所有后续批次库存 |
| 车辆多趟重排 | 修复跨批占用冲突，不能凭空增加实际车辆 |
| 缺箱驱动破坏/修复 | 从第一个缺箱批次追溯可提前完成的回运或 E2 入仓事件 |

订单配送批次在第一版固定，不能在“跨批回收邻域”里偷偷修改订单的配送批次。遗留 empty pickup 任务在 q 变成 0 时应删除，q 从 0 变正时必须插入实际访问；取箱任务 ID 应含仓和回收轮次，而不是顾客原配送批次。

已有 `evaluation_cache` 不能只按一条路线节点序列缓存新版可行性。缓存键至少覆盖策略/输入版本、物理车与趟次、实际时间决策、上游到货/入仓事件和批次初始库存。先做完整重算，再按首个受影响事件向后失效；不要为了提速冻结旧 q 或旧清洁库存。

启发式可在内部使用不可行惩罚探索，但最终交付解必须通过全部硬约束审计。不得用“漏取一点”“增加几个临时箱”“延长一小时”作为没有计入模型的修复。

**12．独立审计和错误诊断。**

新审计从原始订单、物理路网、策略和提取后的路线/实际时间重算事件，不直接信任模型输出的 q、库存、批次归属或 claimed validity。可共用单位定义、不可变类型和物理参数，但核心库存核对不调用求解器 evaluator 的结论作为证据。

检查顺序为任务覆盖 -> 路线/车辆 -> 物理时间 -> 截点分类 -> 每轮全取 -> 容器流 -> 清洁供给 -> 周期末态。截止快照应由真实二级卸箱事件计算，与所报快照和一级实际载量分别比对。

建议错误类型至少区分：

```text
INVALID_INPUT / UNBALANCED_ORDER_COUNTS / UNSUPPORTED_POLICY_BACKEND
MISSING_TASK / DUPLICATE_TASK / CUSTOMER_PRECEDENCE / TIME_WINDOW
```

缺箱应报告首个缺箱批次、领箱时刻、所需量、实际清洁可用量、缺口和下一次预计释放事件。末端错误应指出箱子仍位于何处、对应订单/趟次，以及为何没赶上最后截点。

状态区分：输入不合法、模型已证明不可行、限时无可行解、启发式未找到可行解、找到可行但未证明最优、已证明最优。审计失败的 incumbent 不能作为有效结果参与均值和费用统计。

**13．分阶段实施顺序与交付门槛。**

| 阶段 | 工作与依赖 | 可检查的交付物/完成标准 |
| --- | --- | --- |
| P0：冻结契约 | 以本计划为依据写正式问题定义、确认实施默认值，核对已存在改动 | 确认时间起点、清洗、二级趟次上限、末态和精度；手工推演 3 个机制例 |
| P1：输入与数据结构 | 建 policy/订单/日程/组合实例/新结果类型，入口按版本分流 | 新旧案例分别解析；非法参数提前报错；同一顾客多订单不丢失 |
| P2：账本与独立审计 | 用人工指定路线和真实时间表实现冻结、回运、清洁释放、末态重放 | 所有边界机制例得出可手算的 q、C、错误类型；此时不依赖求解器 |
| P3：联合精确模型 | 在 P2 基础上实现新 indexed MILP、提取完整时间表 | 机制例与手工枚举一致，小例闭合最优或如实给 bound/gap，全部通过独立审计 |
| P4：ALNS | 全周期构造、跨截点/跨趟次邻域、缺箱修复、完整缓存失效 | 无 Gurobi 可运行；机制例与小例产出真实可行解；相同预算与精确参考比较 |
| P5：端到端集成 | CLI、结果持久化、重新加载审计、图表、支持矩阵 | 新案例端到端完成；两个大周期连续重放；旧单日与其他受影响模型回归通过 |
| P6：正式实验 | 冻结数据、配置、种子和预算，按第 15 项运行 | 保存成功/失败、原始路线时间表、manifest、源快照和完整汇总 |
| P7：运营费用与写作 | 使用通过审计的周期指标，更新专属成本入口和论文表述 | 周期运输/工时/容器资金口径一致，所有结论对应真实求解证据 |

P0–P5 是可实现、可重复循环的核心模型验收；P6–P7 是研究评价交付。实现一个“逐批循环调用原单日模型”的演示不算 P3/P4 完成。有限库容、有限清洗能力、自由分仓、动态订单、跨周期有在途库存的稳态模型、配送/回收时长内生优化均不属于第一版必要范围。

无需为了例子 5+1 小时不可行而偷偷改规则。P0/P2 的机制例应至少包含一个可行例和一个有意不可行例，保证失败链条能被正确识别。

**15．实验设计：固定总需求，分开机制与算法比较。**

研究问题：给定每日需求、车队、容器池和顾客时间窗，哪些批次长度与批次数可行；运输成本、等待、回收滞留和清洁箱需求如何随制度变化；ALNS 在相同模型与预算下能多接近小例精确解。

待检验预期而非既定结论：更多批次可能提高容器复用机会，也可能增加路线或因回收处理滞后而不减少池需求；放宽截点可能使更多空箱赶上本轮，但也可能增加本轮回收负荷。在固定“全取”规则下，截点变化会改变任务量，不能套用简单的可行域包含关系宣称距离单调。

| 实验组 | 固定内容与变化因素 | 主要输出 |
| --- | --- | --- |
| A：机制例 | 1–3 仓、少量订单、1–3 批；有意设置边界 | 逐事件手算、截点快照、库存和车辆时间轴 |
| B：单批退化 | 同一新框架 B=1，与同截止参考对照 | 全取、池下界、目标一致性与末态 |
| C：小规模精确/ALNS | 同实例、同 N、同时间精度、同 E2 趟数上限 | 可行率、已证最优 gap 或 bound gap、耗时 |
| D：批次参数 | 固定大周期 H、全天订单总量与原时间窗，改变显式 D/R/B | 可行域、距离、工时、峰值库存、所需池规模 |
| E：容器池敏感性 | 固定批次表和需求，改变 N | 可行性、缺箱位置、距离/费用与最小池证据 |
| F：周转滞后 | 固定其他参数，改变处理时长、顾客使用/回收窗 | 跨轮箱量、复用批次间隔和缺箱风险 |
| G：车辆敏感性 | 固定其他参数，改变 E1/E2 物理车数与容量 | 回收窗口是否可完成、车辆重用与工时 |
| H：大实例/实际路网 | 小例验证后再扩到 100/200 顾客和已有道路矩阵 | 多 seed 有效解、运行稳定性、场景可解释性 |

不得把一份全天需求复制 B 遍后，称为“相同需求下不同批次数”的比较。应一次生成全大周期订单，再以明确且可复现的规则分配到不同批次；顾客原时间窗、总箱次和路网保持一致。若订单批次分配也优化，应作为后续单独实验，不混入第一版参数比较。变更批次安排后某些订单不再可行，应保留并解释，不能为了全可行逐例移动时间窗。

现有 Zhou 与 LaDe 回收时间窗未必适合 5+1 或其他新时段，应先说明继承与派生规则。LaDe 配送/回收数量不一致的数据不能直接用于无损耗闭合，需新建明确标注情景假设的数据副本，不覆盖原数据。Zhou 坐标距离不能直接解释为真实公里。

建议先机制 smoke，再一组小例完成 MILP 验证，最后正式批量。正式预算可沿现有实验体系设小例 exact 300 秒、ALNS 10 秒和 seed 42–46；这些是初始建议，正式运行前统一冻结。若加入 60 秒组，应作为所有对应实例共用的额外预算组。运行时保存求解预算、含构造/审计的墙钟时间、失败原因和源代码哈希，不对失败例静默加时或筛除。

新 runner 对每个任务配置外层超时和过程存活检查；批量执行前估算例数×算法×种子×预算，先 smoke 再扩展。失败和限时按状态分别汇总，保留日志，不将未解出当作数学不可行，不把失败距离填成 0。精确参考未证明最优时只报告有效下界 gap，不冒充相对最优 gap。

输出根目录建议为 `output/experiments/multi_batch_cutoff_v1/<run_id>/`；每次写入新目录，保存 inputs/config、source_snapshot、manifest、逐例完整 JSON、汇总 CSV/Markdown、路线/车辆/容器时间图。池规模变化、时间窗变化或批次变化均应重求解，不能按需求比例缩放旧路线替代。

**16．经济评价、关键指标和最终交付。**

单周期至少输出：批次数及各阶段起止；每批发出箱次、每仓冻结箱数、迟回结转箱数；每批清洁库存与最低库存；全周期使用箱次/固定池大小；两级距离、实际启用车辆数、趟次数、等待/工作时长；空箱前置仓停留、清洗等待释放时间；所有末态分量及重复周期验证结果。

车辆数与趟次数必须分开。`总使用箱次/N` 可作为池利用频次指标，但不是每个箱子的实际平均寿命，也不直接等于经济回收期。前置仓峰值库存是本版充足库容假设需要的空间，不写成已满足未经配置的实际库容。

经济目标接入时采用清楚的分解：周期行驶费用、车辆工时/启用费用、实际清洗处理费用、必要仓储费用以及容器池资金成本。采购 N 个箱子的初始投资与每周期摊销二选一说明或分表报告，不能每批重复采购 N 个，也不能把全寿命投资与同口径摊销重复相加。清洗按真实循环使用/处理箱次计费。若每公里全成本已含人工或折旧，不得再重复计入工时/固定成本。

一次性包装对照应使用相同的全天订单、顾客服务要求、车队物理条件和所声明的批次制度；其不需要空箱回收。若允许一次性方案在循环方案回收时段执行配送，应作为“各自制度最优”的另一组对照，不能把服务安排差异隐藏为包装差异。

第一版的完整交付清单：

- 正式模型说明：冻结规则、时间精度、数量等式、容器状态、初末条件与单批退化条件。
- 新策略、独立订单数据、案例配置、输入验证，以及向后兼容的入口分派。
- 一个完整联合精确后端、一个能够搜索全周期的 ALNS、实际时间表结果结构。
- 独立事件审计、机制/退化/周期边界测试、旧策略相关回归。
- 批量 runner、原始 JSON/CSV、配置与源码快照、状态完整的研究报告与时间图。
- 核心通过后接入的新经济评价入口与对应论文叙述；未完成部分保留明确状态。

最终验收不能只写“能跑出路线”：必须同时证明每个交付解的取箱批次正确、截止库存全部取走、每批清洁箱供给充足、车辆无冲突、最后没有遗留箱、处理完成可接续下一周期，且求解状态和最优性表述真实。

**17．后续研究的起点。**

上述版本化数据结构、手算机制审计、联合精确模型和 ALNS 基线现已实现。下一步使用固定总订单数据开展批次数、阶段时长和池规模的系统对照，再扩展 Zhou/LaDe 路网多种子实验；保留无解和超时结果，继续以独立审计及同口径精确参考衡量算法。不要把当前小规模机制验证写成已完成正式研究评价。

第一轮实现无需同时修改 M1–M8，也无需先做大规模实验或重写经济模块。首先把“截止冻结 -> 本轮全取 -> 回总仓处理 -> 下一批领箱 -> 周期复位”这条可检查的链条实现正确。
