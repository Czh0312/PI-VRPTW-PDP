# M4 平衡价格供列：实现与验证（2026-10-05）

本轮已经实现、完成对照并归档，**没有新增默认采用方案**。24 次冻结对照中，平衡价格供列累计加入 200 条在原主问题对偶下约化成本为负的新路线，但 12 组配对的有效 E2 下界均为 `0 → 0`，没有完整路线 LP 收敛，也没有新增原整数最优证明。因此保持 `balanced_columns=False`，按事前门槛不再启动完整整数模型的计时矩阵。

这是一轮根松弛算法实验；不是完整 M1–M4 求解器提速结果。本轮只针对 M4 新增可选入口，M1–M3 不引入这个策略。此前夜间报告和最好整数上下界账本保持封存，本次较弱根界不替换历史最好界。

## 实现与正确性边界

[single_batch_pickup_bound.py](/Users/chenzeheng/Desktop/2E-VRPTW-PDD/models/routing/solvers/exact/single_batch_pickup_bound.py) 新增订单配送/回收价格平衡供列。每个订单以 D/P 两个价格的均值进行探索，保留订单任务身份，不把同地址的不同订单合并。复用已有定价模型，完整步骤为：

1. 仅在第二阶段按平衡价格发现路线。
2. 用原距离、任务时序和**当前原主问题价格**重新计算可行性、成本及约化成本；只加入原约化成本小于 `-1e-7` 的未重复路线。
3. 新列加入原主问题后重解；下一轮必须恢复原对偶定价，不能连续以平衡探索替代证明。
4. 平衡定价的最优状态和下界只记为诊断，绝不用于原对偶证书、完整 LP 收敛或整数证明。

供列名义配额为根预算的 20%，单仓调用上限 1 秒；探索、原定价和建模都计入同一个总时钟。实际求解器返回与路线验证存在少量配额超时，详见预算记录。此开关仅允许 M4，不能同时启用旧启发式供列，以隔离假设。

本候选不修改原业务输入、整数模型、任务集合、仓库、容量、时间窗、配送与使用时间、回收截止、容器库存或真实车辆串行规则。根松弛本来就放松部分 E1 同步和跨趟物理约束；其路线不是完整可行整数排程。保留全部 D/P 任务和共享客户分配，不意味着根松弛已经实现完整物理约束。

## 瓶颈诊断

有效界采用原主问题目标加上各仓 `K × min(0, 定价下界)` 的修正，再扣数值裕量，并与非负距离给出的零界取最大值。供列后仍存在很大的负修正，路线数量增加未使该证书转正。

例如第一来源种子 44、30 秒候选的最好记录中，受限目标为 556.251683，三个仓的 `K` 都是 24，定价下界约为 -133.898、-114.217、-125.558，修正后为 -8411.921309。前两个仓已完成该次定价，第三个仓尚未完成。因此不能简单归因为“每仓 1 秒不够”；即使已完成定价的仓仍有显著负约化成本，原主问题也尚未达到完整路线 LP 的对偶可行状态。

该观察仅用于形成下一轮假设，不是所有大例负定价证书的独立证明。后续更值得单独检验对偶稳定化或保留物理排程的条件分解；本轮未混入自适应预算、拉格朗日算法或 Benders 改动。
