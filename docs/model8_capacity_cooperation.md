# M8：两级路径与空箱容量协作联合优化

当前版本为 `joint_capacity_cooperation_v3`。不先求 M3，不固定 M3 路线或配送骨架，
也不把车辆范围限制为某个基础解已投入的车辆。原两阶段方案已归档到
`models/routing/variants/model_8/two_stage_v2/`；
[历史设计及实验](model8_two_stage_capacity_history.md)不作为当前联合版本的实验结果。

## 1. 联合决策范围

在给定顾客所属卫星仓、车队上限、需求、容量和时间窗下，一起决定：

- E1 大车路线、卫星仓配送与回收访问顺序，以及用车；
- E2 小车路线、配送和回收任务归属与顺序，以及用车；
- 顾客地点的空箱放置与接收事件、发送与接收车辆、整数箱量和访问时间。

目标为两级车辆总行驶距离之和。顾客分仓沿用问题输入；“固定分仓”不表示固定任何车辆路线。

允许一个发送车在顾客点放 3 箱，由两车分别取 2 箱和 1 箱，也允许不同时刻取走。
每个箱子最多换车一次；同一个交接点可以有多个接收车辆访问。
当前假设不设临时存放容量、存放期限或按数量计算的装卸时间，沿用现有业务规则。

## 2. 数学模型与精确求解

E1 弧变量 x、E2 弧变量 z、任务服务变量、用车变量和交接量 q 一起优化。
车上区分配送货物、尚未转交的原生空箱 O、已接收空箱 R：

- 原生箱守恒：离开 O − 到达 O = 本车回收量 − 转出量；
- 接收箱守恒：离开 R − 到达 R = 接收量；R 不能再次转出；
- 转出量不能超过到达该事件时已经携带的 O，防止在原回收点原地代取；
- 所有弧检查重量与体积上限；包括车辆出发时的配送载荷；
- 接车时间不早于发送车完成该次访问；数量分拆保持守恒；
- 配送先于对应回收，E1/E2 衔接、时间窗、完整任务覆盖和回路约束同时成立。

**当前规则下，解除旧 M8 的固定条件后，其精确可行域与 M6 相同。**
精确模型复用 M6 紧凑 O/R 流模型，不宣称仅靠编号就形成新的数学机制。
M8 的算法工作是围绕容量释放设计联合路径与交接操作。

精确入口直接建立并求解一个完整 MILP；不会先调用 M3，也不会先求固定路线子问题。
可选 `warm_start_routes` 只设置初始值，不固定变量。只有完整联合模型闭合才设置
`proven_optimal=True`；不再使用 `conditional_proven_optimal` 或两阶段证书。

## 3. 联合 ALNS

共享的可行路线构造器生成起点，不调用 M3 的精确或 ALNS 求解入口。
对小规模紧时间窗实例可使用受总时间预算限制的构造性插入候选队列。
初始化失败不代表模型不可行。可选 `warm_start_routes` 或 `initial_state` 也仅是搜索起点。

整个算法始终只有一份当前完整方案、一个总距离目标、一个接受准则和一个时间预算。
同一自适应搜索循环中包含：

- E1 任务移位、换车、交换以及同仓配送/回收任务成组移动；
- E2 配送任务移位与换车、配送交换、同顾客配送/回收成组移动；
- 单车或多来源回收任务重分配；
- 将回收重分配与容量释放交接一起构造，允许多个接收车分取；
- 删除已有交接并重新安排回收。

所有配置内的车辆都在状态中保留可激活位置，可以启用之前闲置的车辆或停用原车辆。
每个被接受的候选都通过完整 E1/E2 载荷和联合时序审计。

当前仍是有限邻域启发式：默认回收组至多 3 个任务，联合交接从 6 辆候选车中选至多 3 辆，
不穷举所有全局组合。新增交接目前要求该次完整修复改善当前距离；
这些是算法限制，不是数学模型的固定路线约束。ALNS 不提供最优性证明。

## 4. 无传递对照与 M3

`allow_transfers=False` 仅禁止车辆间转交空箱，仍联合优化所有 E1/E2 路线与任务分配。
在相同输入及当前同质空箱假设下，其业务可行域对应 M3。和 M3 使用不同的算法时，
有限时间内得到的数值可能不同；这属于搜索差异，不是新增业务收益。

比较传递收益时，同一初始构造、原始数据、完整车队上限、时间预算和随机种子下，
分别求禁止/允许传递版本。不能将相对某个较差初始解的全部改善归因于传递。

## 5. 入口与版本

```bash
python main.py route --case config/cases/zhou_small_demo.json --model 8 --solver alns --time 10
python main.py route --case config/cases/zhou_small_demo.json --model 8 --solver exact --exact-time 30
python -m pytest tests/routing/test_model8_joint.py -q
```

Python 的 ALNS/精确入口均支持 `allow_transfers=False`。
旧参数 `base_routes`、`stage1_time_ratio`、`delivery_policy` 不适用于当前联合入口。
CLI 结果输出到 `output/single_runs/model8_v3_joint_*`，完整状态文件后缀为 `_joint.json`。

历史程序通过显式 `two_stage_v2` 导入保留原语义；旧报告和源代码快照不覆盖。

## 6. 当前联合版本验证

2026-09-22：60 项相关测试通过，覆盖 E1 路线改变、配送换车、闲置车辆激活、
无 M3 求解调用、非固定热启动、2＋1 不等量分取、载荷时序及应用入口分发。
命令行精确和 ALNS 均已独立实跑。

另完成 30 次独立求解并重新加载审计：一个构造机制例、一个原始 7 客户例及两个原始 100/200 客户例。
两个小例的 M3 与无传递联合模型都证明最优且距离相同。构造例允许传递后达到更短的全局最优值；
原始 7 客户例的允许传递最优值与 M3 相同。大例仅运行短时 ALNS，不提供收益稳定性或最优性结论。
