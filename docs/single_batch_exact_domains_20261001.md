# 单批 M1–M4 第九轮：路线编号界、建模缓存与仓库流诊断

本轮默认保留两项等价调整：按任务实际可用路线收紧路线归属编号界，并缓存任务覆盖求和。
仓库流连接已实现，但多种子和短预算对照存在可行解搜索退步，最终只作为显式诊断开关。
固定工作量对照尚未显示默认调整明显提高求解质量或缩短最优证明时间。
有限车队、趟数、整数时间、距离目标、送取规则、零 Gap 和独立审计均保留。

## 路线编号界

压缩模型以连续变量 R_i 表示任务 i 的路线编号，其定义为
`R_i = sum(r * visit[r,i])`。每项任务恰好访问一次，所以整数解中的 R_i 是实际路线编号。

此前所有 R_i 使用统一范围 `[1, 全部路线数]`。
现在令 A_i 为建模时拥有任务 i 的所有路线编号，使用
`L_i=min(A_i)`、`U_i=max(A_i)`。A_i 可以包含实际不可行的路线，因而仍是保守范围。
固定分仓任务的 A_i 只来自所属仓点；自由分仓任务保留全部必要条件筛选后允许的仓点。

内部弧 x_ij 被选中时，两个任务仍必须属于同一物理车辆和趟次。线性连接改为

```text
R_i - R_j <= max(0, U_i-L_j) * (1-x_ij)
R_j - R_i <= max(0, U_j-L_i) * (1-x_ij)
```

当 x_ij=1 时两式要求编号相等；当 x_ij=0 时两式对区间内所有值成立。
不增加变量或约束，不改变整数可行域，也不删除任何仓点或路线。
较小的非压缩模型不使用该归属变量，因此其建模路径不受影响。
`tight_route_bounds=False` 可还原统一编号界与统一失活系数。
结果新增 `e2_tight_route_bounds`、`e2_route_identity_ranges_reduced`，区分启用策略与实际收紧的任务数。

## 覆盖求和缓存

此前为每个订单、任务种类和可选仓点重新扫描所有路线的全部节点。
现在一次遍历二级路线，按 `(仓点, 订单, 任务种类)` 收集访问变量，再用于原有覆盖等式。
变量顺序、求和次序、系数、右端值、分仓关联与约束生成顺序均保留。
缓存构造也检查原总预算，不另增求解时间。

三轮交替建模顺序对照使用30客户 M1–M4，关闭路线编号收紧以隔离缓存效果。

## 未默认启用的仓库流

`single_batch_site_flow.py` 把全局二元内部弧 x_ij 分解为连续仓点流 y_sij。
只在仓点 s 的两个任务节点和必要条件弧都存在时建立流，并要求

```text
sum_s y_sij = x_ij
仓点起始弧流入(i) + sum_j y_sji = assign[customer(i),s]
仓点结束弧流出(i) + sum_j y_sij = assign[customer(i),s]
y_sij >= 0
```

单一可用仓点的内部弧直接复用 x_ij，不新增辅助变量。
其余流为连续变量，没有恢复按物理路线复制的内部二元弧。
全局弧仍只计算一次距离；原路线归属、时间、载荷、因果序位及物理车辆串行约束仍保留。

整数可行解中，一条选中弧的两端属于同一实际路线和仓点，将其单位流放入该仓点即可满足新式。
如果该仓点的必要时间界已排除某条弧，原选中弧的时间连接与启用后的仓点窗口也会相互矛盾，
因此该弧不可能出现在原整数可行解中。反向消去仓点流即可还原原模型。
新式只收紧分数解，允许配送和回收位于不同趟次，并保持同一顾客所有订单的统一分仓。
