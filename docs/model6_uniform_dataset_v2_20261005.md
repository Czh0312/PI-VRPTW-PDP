# 模型6均匀分批数据集第二版

后续M5/M6主对比请使用 [共享数据集](model5_model6_shared_dataset_20261005.md)。本版作为其不可变来源，仍适用于M6内部决策对照；下文旧M5/M6运行器的限制不影响新增的共享配对入口。

Material Passport：academic-research-suite/experiment-agent；validate；2026-10-05；ANALYZED。确定性生成、输入守恒和物理方案审计分别核验；短预算随机搜索不构成算法性能或成本最优证明。

## 目的与范围

当前模型6优化整个周期的均匀划分数K、共同分界、订单分批、箱池和两级路线。旧静态V2窗口围绕08:00、12:00、16:00构造，新K=3日历却从08:00、12:20、16:40开始。只改变模型允许域、保留旧窗口时，21个LaDe及38个Zhou场景没有订单能由新第3批配送。

本版新增 `data/model6/uniform_v2_20261005/`，版本标识 `model6_uniform_suite_v2`。旧 `data/manifest.json`、M1–M5数据、模型6历史适配数据与实验结果均保留。它们不与本版按同名场景混合统计。

只从每个旧family选一个B3记录获取网络与需求；B3不是新预约时间的生成依据。旧B2/B3替换为相同均匀日历后会成为相同问题，不能作为两个独立新算例。

## 组成

| 层次 | 组成 | 配置数 |
|---|---|---:|

| 敏感性 | Zhou七个顾客规模、LaDe三个AOI规模，各选一个来源family，增加12个配对变体 | 120 |

Zhou覆盖7/10/12/20/30/50/100顾客；LaDe覆盖10/20/30 AOI及原来的7天资料。敏感性family在每个“来源类型×顾客规模”内按名称排序取第一例，选取不读取求解结果。它们是用于机制检查的便利选例，不是新的独立空间样本。

## 时间生成规则

规则和seed在 [配置文件](../config/datasets/model6_uniform_v2.json) 中固定。全部订单在周期开始前已知；默认货物在周期开始可用，分时到货变体也提前给定全部release_time。

- 非机制场景仍为08:00–21:00。预约中心在09:30–17:00之间，按各仓顾客的稳定哈希排序分层布置并加入小幅抖动。两种Zhou原使用情景共用预约中心的哈希标识。
- 三档配送窗围绕同一预约中心展开，宽度为35、90、180分钟。较宽窗口包含较窄窗口，网络、需求、车队、使用时长、费用和K范围保持相同。
- 回收预约由中心、原服务时长、原最短使用时长和独立哈希生成的0/15/35分钟预约延迟确定。回收窗预留声明的15分钟提前量、45分钟迟后量；不同窗宽的回收允许域也嵌套。
- 预约函数不使用候选K、路线、行驶距离或参考可行方案。不会求解后重采样、放宽窗口、扩车或删除订单。越出周期的非法配置明确报错；结构上不可行但格式合法的输入仍保留。
- 默认K范围为1/2/3；`extended_k`单独扩展到1–6。最短阶段1分钟仍是研究假设，结果只对指定整数刻度与K范围成立。

预约中心按仓分层，是显式的时间需求设计假设；不能称为消费者实测回收过程，也不能称完全随机的现实订单流。

## 敏感性与守恒

每个代表family以 `spread_medium` 为配对参照：

| 变体 | 唯一设计维度 |
|---|---|
| `clean_fast` / `clean_slow` | 清洗时长5/60分钟，参照15分钟 |
| `fleet_tight` | 一级车数乘0.5向上取整；每仓二级车数乘0.75向下取整，均至少1辆 |
| `capacity_tight` | 二级车辆重量、体积容量均乘0.75 |
| `pool_low` / `pool_high` | 每箱周期池费1/20，参照5，均为合成单位 |
| `work_high` | 两级车辆占用工时单价乘3 |
| `peak_early` / `peak_late` | 预约时间分位数分别用q²、√q变换，保留同一排序 |
| `release_staggered` | 货物可用时刻为配送窗开始前180分钟，最早为周期开始 |
| `repeat_orders` | 每个原箱量≥2的订单拆成两次访问，中心偏移±75分钟并限制在预约中心区间内 |
| `extended_k` | 同一物理输入，K范围扩展到1–6 |

全部变体逐顾客、逐固定仓核对箱次总量与货重总量；同点多订单按箱数比例拆分重量，每次访问保留原服务时长。因此该变体增加了访问服务工作量，这是明确的业务情景变化，不能解释为原始观测。

费用采用原模型6合成口径，仅有声明的费率变体，不冒充人民币校准。固定需求、全额归还下，清洗单价、追踪单价和按使用次数计的磨损费是各可行方案的共同项；本版把清洗**时间**作为优化敏感性维度。箱体初始购置投入仍单列。

## 同口径对照入口

新入口为 `experiments.runs.run_model6_dataset`，所有对照保持该场景的网络、订单、资源和成本目标相同：

| arm | 允许决策 |
|---|---|
| `fixed_assignment` | K=3、共同分界固定为批长75%，分批固定，优化箱池与路线 |
| `fixed_cutoff` | 在上一项基础上允许订单重新分批 |
| `fixed_k` | 在上一项基础上允许共同分界变化，K仍固定为3 |
| `joint` | 在上一项基础上允许K在配置范围中变化 |
| `full_pool` | 与joint相同，额外固定N=Q，用于箱池决策对照 |

固定分批参照采用固定日历下每单通过时间必要条件的最晚批次；这不是最优分批或整体可行性证书。没有合法批次的订单保留，不能通过删除它使参照“可行”。前三项到joint的允许域依次扩大，有限时间启发式结果不保证成本按这个顺序下降。`full_pool`是joint的另一受限对照。

原机制对照保留不同的源日历，因此只用于joint/full_pool/fixed_k机制验证，不能套入要求同一均匀源日历的fixed_cutoff/fixed_assignment对照。运行器会明确拒绝这种组合。旧M5/M6对比运行器不适用于本版清单。

## 使用与复现

从项目根目录运行。生成器、审计器和实验入口都拒绝覆盖非空输出目录。

```sh
# 已生成数据可直接运行；重新生成应指定新目录
.venv/bin/python -m tools.data.build_model6_uniform_dataset --output /tmp/model6_uniform_v2_rebuild

# 全量输入哈希、需求守恒、语义去重和各K必要条件检查
.venv/bin/python -m tools.audit.audit_model6_uniform_dataset \
  --manifest data/model6/uniform_v2_20261005/manifest.json --output /tmp/model6_v2_audit

# 查看10个规模代表例的三档窗口任务，不启动求解
.venv/bin/python -m experiments.runs.run_model6_dataset \
  --anchors-only --variants spread_narrow spread_medium spread_wide \
  --seeds 42 --time 5 --workers 2 --dry-run --output /tmp/model6_v2_smoke

# 小规模同口径决策对照；精确与ALNS预算分别显式指定
.venv/bin/python -m experiments.runs.run_model6_dataset \
  --families zhou_Set1_7-2-1 --variants spread_medium \
  --arms fixed_assignment fixed_cutoff fixed_k joint full_pool \
  --solvers exact alns --exact-time 15 --time 5 --seeds 42 43 44 \
  --output /tmp/model6_v2_controls

.venv/bin/python -m pytest tests/routing/test_model6_uniform_dataset.py -q
```

清单记录生成配置、源码哈希、每个生成文件及外部输入的哈希、逐例语义指纹和同源分组。运行器在求解前冻结输入及源码，保留全部状态、失败、时限和独立物理审计；不选择对某个模型最有利的种子。敏感性和时间窗变体配对比较，Zhou同源情景与嵌套子集共享来源块；LaDe同城相邻日期亦不作为独立城市样本。

## 验证证据

证据保存在 [验收目录](../output/inspections/model6_uniform_v2_20261005/)：最终输入审计为 `audit_verified/`，跨目录重新生成核验为 `reproduction.json`，自动测试为 `pytest.xml`。核心三档窗口试运行、敏感性试运行与同成本对照分别保存。具体次数、成功/失败和证明状态以各目录JSON为准，不把必要条件通过当作路线可行证书，不把短预算无解当作不可行证明。

全量初次审计覆盖395例、1215个K配置，未发现完全重复的语义输入。中、宽窗的91个非机制场景均有订单可通过第3批配送的必要条件；窄窗仍有1个LaDe、16个Zhou场景无订单可用第3批。分时到货变体保留27个被必要条件拒绝的K配置，其中7个场景的K=1/2/3均被拒绝；它们作为负例保留，均未自动扩K或修改release_time。
