**1．研究目标与本阶段范围**

研究全周期订单及顾客回收时间窗提前已知、配送批次固定的两级系统：在满足顾客要求、前置仓供货和有限车队约束的条件下，通过配送—回收—清洗的衔接，使有限容器能够在多个批次之间再次投入使用。

本轮已确认：

- 先完成静态模型与实验，不启动动态求解。
- 各批次时间安排由数据给定，各笔订单的配送批次也由数据给定。
- 数据集提供每批具体订单，求解器不自行决定哪些订单属于哪一批。
- 容器池有限，跨批连续使用；中间批次不要求所有容器归仓。
- 订单配送批次与容器回运轮次分别记录：前者固定，后者由实际卸回前置仓的时刻和截止规则确定。
- 大周期末按当前闭合规则恢复全部容器清洁归仓、车辆可用的状态。
- 后续再研究订单跨批分配；动态信息揭晓是另一个独立扩展。

沿用当前实现的业务假设：M3 单批次和 M5 多批次均固定分仓、单一规格同质容器、无损耗、每单配送与回收箱数相等、总仓清洗、前置仓库容及并行清洗资源暂不限制。它们是明确的模型范围，不代表所有现实业务都满足这些条件。

**2．单批次、多批次和大周期的定义**

大周期是统一安排和检查系统的时间范围，可以是一天或七天。批次是其中一次集中领箱、装货与发运安排；同一批可以使用多辆车、多条路线。周期末全回收是末态要求，不能据此判断批次数。

| 维度 | 单批次 B=1 | 多批次 B>1 |
| --- | --- | --- |
| 需求信息 | 全部提前已知 | 所有批次的需求全部提前已知 |
| 配送分批 | 全部订单属于唯一一批 | 每笔订单有指定的配送批次 |
| 领箱 | 唯一批次开始时领取全部需求 | 每批开始时领取本批需求 |
| 周期内复用 | 没有下一批再次投放 | 已回收并清洗的箱子可供后续批次使用 |
| 中间批次末态 | 不适用 | 允许顾客、车辆、前置仓和清洗区仍有容器 |
| 大周期末态 | 全池清洁归仓、车辆可用 | 相同 |
| 容器池 | 至少覆盖全部订单箱数 | 至少覆盖单批最大领箱量，但该条件不充分 |
| 研究重点 | 闭环可行性、一次性与循环包装的经济对照 | 供箱衔接、池规模、运输代价和跨批周转 |

七天开始时只发一批、随后七天完成配送回收，是七天单批次；七天每天发一批，是七天七批次。若七批的箱子全部到第七天才回收，则属于多批配送，但该七天内没有形成再次投入使用的周转。

单批次使用同一 `multi_batch_cutoff_v1` 框架的 B=1 情形作为正式机制对照。历史 `single_day_backhaul_v1` 允许某仓局部收齐后取箱，另有车辆趟次和末端处理口径差别，不能直接要求它与新版 B=1 的最优距离、等待时间相同。历史结果保留并单独标注。

**3．统一时间和容器流转规则**

批次日程采用绝对时间：

```text
a_b：第 b 批开始领箱、装货
c_b：配送阶段结束，同时冻结本轮空箱资格
e_b：一级回总仓并卸箱的期限
a_(b+1) = e_b
H：大周期结束，H >= e_B
```

配送阶段长度和回收阶段长度均由输入给定，5 小时＋1 小时只是示例。当前不让求解器自动改变批次数、推迟发运、延长阶段或增加隐藏收尾轮。

一级每车每批最多一趟，先完成配送段，再执行取箱段；允许纯送或纯取。驶向首个取箱站的行程从截止后开始。二级可以多趟、跨批边界执行任务，但同一物理车必须先完成上一趟及必要准备，才能开始下一趟。每个二级趟次最多携带一个配送批次的货物，可以回收之前订单的空箱。

对前置仓 s，第 b 轮必须取走：截止 c_b 前已完成二级卸箱、此前尚未被一级取走的全部空箱。初始仓内空箱为零且每轮全取时：

```text
q(s,1) = Σ[在本仓 u <= c_1 完成卸箱的空箱数量]
q(s,b) = Σ[在本仓 c_(b-1) < u <= c_b 完成卸箱的空箱数量]
```

u 是二级回到前置仓并卸箱完成的时刻，不是顾客交箱时刻或车辆到仓时刻。恰好截止完成卸箱可以计入；截止后入仓不能因一级车晚到而顺带取走。q>0 时同仓本轮由一辆一级车一次取完，q=0 不创建空访问。冻结只改变资格，实际库存到装上一级车时才扣除。

顾客回收时间窗不等于固定回仓时间。某笔回收若最早可行回仓已晚于截止，本轮就一定赶不上；只有在可行安排横跨截止时，调度才可能改变回运归属。不能声称所有迟回都能通过优化提前。

容器领用与释放：每批 a_b 一次领取全部本批需求 D_b。只有总仓卸箱完成再经过清洗的容器才可使用。若 R(t) 表示截至 t 累计完成清洗的回收箱次，则必须满足：

```text
C(a_b^-) = N - Σ[D_h：h<b] + R(a_b) >= D_b
```

同一物理箱可以贡献多次清洗释放，故 R 是累计箱次。清洗恰好在领箱时完成可用；提前知道后续订单不等于提前给后续订单装箱。所有位置数量守恒，脏箱、在途箱和顾客处的箱都不能视作总仓清洁库存。

合法的跨批遗留须保留任务、位置和车辆占用；超过顾客时间窗、漏取截止前库存都属于违规。周期末要求最后带箱二级趟次在 c_B 前卸完、一级在 e_B 前卸完、全部容器在 H 前清洁可用。e_B 到 H 的尾部可以安排清洗与整备，不能隐藏额外取箱。连续两个周期重放时，第二周期继承第一周期实际状态。

**4．数据集设计：先给定批次需求，再求解调度**

每个算例在求解前冻结四类输入，不依据求解结果重新调整订单归属或时间窗。不同批次方案可以在数据构造阶段形成独立变体，必须有确定规则、固定种子和记录；这是外部场景设计，不是模型内分批优化。

| 数据层 | 必要内容 | 当前文件形式 |
| --- | --- | --- |
| 物理网络 | 总仓、前置仓、顾客唯一 ID，位置、分仓关系，距离和行驶时间 | 网络 CSV，可选距离/时间矩阵 |
| 批次与作业 | 批次 ID、各阶段长度、周期起止、装卸/准备/清洗时间、时间精度 | operating policy JSON |
| 订单明细 | 每笔订单的配送批次、顾客、仓、箱数、货重及两个时间窗 | 独立 orders JSON/CSV |
| 资源 | 两级物理车辆数、重量/体积容量、容器规格、固定池 N、二级趟次上限 | fleet 和 policy JSON |

订单表使用现有字段：

```text
order_id, customer_id, satellite_id, delivery_batch_id,
container_count, goods_weight,
delivery_ready, delivery_due, pickup_ready, pickup_due, service_time
可选：min_use_time，pickup_container_count（须与配送箱数相等）
```

每批总需求 D_b、各仓各批需求从订单明细汇总得到，不能只给一列每批总箱数。同一顾客可在不同批次有不同订单，不通过重复物理节点行表达。当前整单配送和回收，不拆分一笔订单数量。

数据中固定 `delivery_batch_id`；不预先填写求解器必须遵守的空箱回运批次或前置仓回收量。后两者是实际时间表的派生结果，允许多个配送批次的空箱合并进入一轮回运。

全部输入时间采用分钟，内部和结果采用显式精度的整数 ticks；跨天时间不能每天归零。窗口约束服务开始，且回收开始不早于配送服务完成加最短使用时间。提前给定的绝对回收窗口不能随着路线变化随意平移。

数据验收要求：ID 和关联有效、箱数为正整数、送取平衡、时间窗合法、单位明确、批次表不越过周期末。参数合法与问题可行分别检查；某订单无法赶上最终回收时，应记录结构性不可行，不能默默删单或放宽窗口。

来源分为真实观测、由真实数据派生、文献/业务参数、人工情景四类。记录来源、转换规则和随机种子。若额外掌握订单可发货时间，必须在适配阶段确认指定批次不早于该时间；当前订单 schema 尚没有独立货物释放字段，不能宣称现有代码已支持。实际配送完成时间不能直接冒充顾客承诺窗。

**5．固定池求解、池规模研究与经济评价分开**

当前直接求解的问题：给定 N 和固定分批，满足全部约束并最小化两级总距离。清洗释放和库存约束影响路线可行性，但当前目标不直接最小化 N，也不直接最小化总费用。

后续池规模对照：固定订单、批次、车队等输入，只改变 N；保留每个 N 的可行性、距离、工时和供箱轨迹。令 Q 为全周期订单箱次，则 N >= max(D_b) 是必要条件；回收与清洗不及时可能要求更多。若路线与末态本身可行，N=Q 可作为不依赖周期内复用的容器供给参考，仍不保证运输、容量和时间窗可行。

必须区分三种数量：

- 当前固定时间表需要的最小池：由事件账本算出，不代表全问题最小 N。
- 已找到可行解的最小测试 N：是当前搜索证据，可能仍有更小可行值。
- 已证明的最小可行 N：需有该 N 的有效解，并排除所有更小 N；同实例下可利用增大 N 不会破坏原可行解的单调性组织证明。

ALNS 未找到解、精确求解超时无解不能写成已证明不可行。精确最优性只针对声明的时间精度、趟次上限和模型规则。

经济评价对每个通过审计的方案核算运输、工作时间、实际启用车辆、清洗箱次和容器投入。初始投资按 N 计算，使用/清洗费用按箱次计算；初始购买、评价期摊销及寿命假设必须一致，不能重复计费。距离最优方案的费用后处理，不等于该 N 下费用最优；跨 N 选出的最低核算费用也不能冒充全局经济最优。

**6．三组实验与比较口径**

| 实验组 | 目的 | 对照与输入 | 核心输出 |
| --- | --- | --- | --- |
| A：单批次经济性 | 检验循环容器在何种条件下具有经济性 | 同需求、分仓、服务标准和评价期；一次性包装与循环容器 | 运输及包装/清洗成本、初始投资、单位配送成本、盈亏平衡条件 |
| B：静态多批次 | 验证有限容器跨批周转，并研究池规模与调度代价 | 固定总订单；外部给定单批/多批变体；各变体内扫描 N 和清洗等参数 | 可行率、池规模证据、距离/工时、逐批清洁库存、各仓冻结与结转量、末态 |
| C：真实数据多批次 | 检验实际需求分布和作业节奏下的适用性 | 真实配送基础＋核实的作业参数；缺失回收信息明确设为情景 | 服务满足、容器供给、车辆安排、周期闭合；声称经济收益时补充同口径费用 |

三组是实验类别，不是只运行三个实例。先形成少量可手算/精确核对的机制例，再扩大小例和真实场景；正式规模、参数组合和预算在数据验收后固定。

单批与多批的可比性要求：

- 保持物理网络、订单总量、顾客服务窗口、车辆资源、容器规格及大周期评价范围一致；分批映射和批次日程作为声明的场景变化。
- 检查单批集中装货的一级容量及每仓不拆分限制。单批不可行时照实记录；不能暗中增车、拆单或放宽时间窗来制造可比结果。
- “全部订单提前知道”不等于“全部货物在第一批前可供发运”；有真实释放约束的数据须先核对适用性。无法保持相同服务条件的变体不能混成纯粹的批次效果。
- 先在同一策略、同一 N 下比较精确求解与 ALNS；再比较不同 N 的资源取舍；不同批次方案单独分析，避免把算法、库存、服务约束变化混在一个结论中。
- 用同一新框架的 B=1 对比 B>1，不直接混用历史单日策略和新版多批次结果。

单批经济评价应区分“一天一个批次、连续运营多个周期”与“容器只使用一次”。可以把完整包装经济对比集中在 A；若 B/C 只证明循环可行，就不扩写经济收益结论；若声称多批更划算，须补实际费用核算。不能由 A 的正收益自动推出所有多批方案盈利，也不能把更低 N 自动解释为更低总成本。

数据来源的当前定位：Zhou 用于机制与算法验证，坐标距离不直接视为真实公里；现行 V2 的 Zhou/LaDe 采用 08:00–21:00 日内短时周转箱情景，279 个配置已通过可行构造与周期审计。LaDe 旧底稿包含跨日及非全额回收假设，现行输入已另行构造同周期全额回收，旧字段只作追溯。容器交回时间、清洗和真实费用仍需补充证据，不能把情景假设当实测。规则与验收见 [数据集 V2 修订](dataset_redesign_v2_20260930.md)。

正式实验不以以上小例预算自动代替统一预算。每个子进程设置求解预算与明确的外层墙钟上限；保存成功、不可行、超时和异常，失败不静默补时或筛除。记录输入/源码快照、种子、实际时间表、上下界及审计结果。Gurobi 需要有效许可证；ALNS 不依赖 Gurobi。代码修改后运行相关回归，数据修改后至少进行输入检查、机制核对和独立审计。

计划完成的验收证据是：每批领箱充足、全部任务按要求完成、冻结量全取、无车辆冲突、容器全过程守恒、全池最终清洁、两个连续周期重放通过，以及比较结果具有可追溯的数据和参数。研究发现可以是不可行或不经济，不以出现正收益作为验收前提。

**9．后续扩展边界与接口原则**

当前先保持固定日程、固定 `delivery_batch_id`。后续有两条独立扩展：

| 扩展 | 新增内容 | 与当前版本的关系 |
| --- | --- | --- |
| 静态订单跨批分配 | 全部需求仍已知；订单可从允许批次集合中选择，受配送/回收窗口和可能的改约代价约束 | 比较固定分批与灵活分批的额外价值 |
| 动态需求与回收信息 | 订单逐批揭晓，回收窗口在配送后揭晓；按新事件更新未执行计划 | 比较全信息计划与仅使用已知信息的决策 |

两者都不在当前实验中启用。当前也不优化批次数和阶段长度，不实现有限清洗/仓容、容器损耗补购或跨大周期有在途库存的稳态模型。

现在保留三类职责：稳定业务数据、带时间的物理事件/状态、求解产生的计划。未来动态版需要独立的信息可见性层、可输入的当前状态、在途车辆和已执行/已承诺动作约束；不能把重跑当前静态求解器称为已经支持动态。

拟议的允许批次集合、订单揭晓时刻、回收窗口揭晓时刻等字段仅在设计中预留。当前 schema 严格校验未知字段，不直接向现有订单 JSON 填入这些新字段；正式扩展时升级 schema 和加载器。业务可发货时间与信息揭晓时间保持独立：提前知道订单不授权提前出货，动态仿真预先保存完整数据也不授权调度器读取未来信息。

本计划后续的第一个具体交付是 S1：在不改变现有求解规则的前提下，形成固定订单分批的单批/多批配对数据及字段来源说明，再进入池规模对照。
