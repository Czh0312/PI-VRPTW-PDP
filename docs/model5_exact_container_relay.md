# Model 5：E2 空容器单次车辆间接力联合精确模型

## 1. 模型定位

Model 5 以 Model 3 为严格基线，保留固定顾客—前置仓分配、E1 配送/回收、E2
配送/延后回收、容量、时间窗及“先配送后回收”等全部约束，只增加一个决策自由度：

> E2 车辆从顾客处取到空容器后，可以携带至同一前置仓服务区内的一个交接点，交给
> 另一辆 E2 车辆，由接收车辆继续携带并最终返回前置仓。

因此 Model 5 不研究自由分仓，也不是把回收任务从顾客位置无成本地改到另一位置。
容器从产生、取走、在途携带、交接到回仓的物理流必须连续。

为保持精确模型可解释且可求，当前采用以下边界：

- 每个空容器不可拆分；
- 每个空容器至多发生一次车辆间交接；
- 携带车与接收车必须不同；
- 两辆车属于同一前置仓，禁止跨前置仓传递；
- 交接点从该前置仓已分配顾客的物理位置中选择；
- 交接后接收车可继续服务其他任务，最后必须回到原前置仓。

## 2. 两种回收模式

对每个回收任务 \(p\)，模型在以下模式中恰选一种。

### 2.1 直接回收

车辆在原顾客 \(o(p)\) 的回收时间窗内取走空容器，并直接随本车路线带回前置仓。
这与 Model 3 完全一致。

### 2.2 单次接力回收

选择交接点 \(h\ne o(p)\) 后形成三个有先后关系的操作：

1. `TP(p,h)`：携带车在原顾客 \(o(p)\) 的回收时间窗内实际取箱；
2. `TD(p,h)`：同一携带车在交接点 \(h\) 卸下该容器；
3. `RP(p,h)`：另一辆接收车在卸下完成后接收该容器。

物理链条为：

```text
原顾客 o(p) → 携带车 a → 交接点 h → 接收车 b → 所属前置仓
```

其中 \(a\ne b\)。`RP` 不是新的顾客回收任务，因此不重复使用原顾客回收时间窗；
它的可用时刻由 `TD` 完成时刻决定。

## 3. 核心决策变量

- \(x_{ijk}\)：E1 车辆 \(k\) 是否行驶弧 \((i,j)\)；
- \(z_{ijv}\)：E2 车辆 \(v\) 是否行驶弧 \((i,j)\)；
- \(y_{ph}\)：回收任务 \(p\) 是否选择位置 \(h\) 作为最终取回模式；
- \(A_{iv}\)：E2 车辆在任务节点 \(i\) 的相对到达时间；
- \(Q_{iv},V_{iv}\)：E2 车辆完成节点 \(i\) 服务后的重量和体积载荷。

当 \(h=o(p)\) 时，\(y_{ph}=1\) 表示直接回收；当 \(h\ne o(p)\) 时，表示启用上述
单次接力链。

## 4. 关键约束

### 4.1 唯一模式与容器守恒

对每个回收任务：

\[
\sum_{h\in H_p} y_{ph}=1.
\]

若选择 \(h\ne o(p)\)，则 `TP(p,h)`、`TD(p,h)`、`RP(p,h)` 各被服务一次；否则
三者均不启用。该结构保证一个容器不会丢失、复制或拆分。

### 4.2 携带车一致与接收车不同

对任意 E2 车辆 \(v\)：

\[
u^{TP}_{phv}=u^{TD}_{phv},\qquad
u^{TP}_{phv}+u^{RP}_{phv}\le 1.
\]

第一式保证取箱和卸箱由同一携带车完成，第二式保证接收车不是携带车。

### 4.3 先配送、后取箱、再交接

必须满足：

\[
t^{TP}_{ph}\ge t^D_p+s^D_p,
\]

\[
t^{TD}_{ph}\ge t^{TP}_{ph}+s^{TP}_{ph}+\tau_{o(p),h},
\]

\[
t^{RP}_{ph}\ge t^{TD}_{ph}+s^{TD}_{ph}.
\]

原顾客的回收时间窗只约束 `TP`；直接回收时则约束原始 pickup 节点。

### 4.4 车辆载荷变化

- 配送顾客：载荷减少配送品及容器；
- 直接回收或 `RP`：接收车辆载荷增加空容器；
- `TP`：携带车载荷增加空容器；
- `TD`：携带车载荷减少同一个空容器。

所有节点后的重量和体积载荷均受 E2 车辆容量限制。因此模型不仅决定交接，还验证
两辆车在交接前后的真实携带能力。

### 4.5 E1–E2 衔接

E2 车辆必须在 E1 配送到达前置仓后才能出发；E1 回收车辆必须等待该仓所有已使用
E2 路线返回。由此保证经过接力的空容器最终进入前置仓，并可由 E1 运回中心仓。

## 5. 退化关系与精确性口径

令所有 \(h\ne o(p)\) 的 \(y_{ph}=0\)，即代码参数 `max_transshipments=0`，Model 5
严格退化为 Model 3。该设置用于回归验证，不作为 Model 5 的实验结果。

规范 Model 5 使用同一前置仓内的完整交接点集合，即
`max_relocation_candidates=None`。只有完整候选范围得到严格的零间隙证明时，结果才
标记 `proven_optimal=True`。证明可来自完整联合 MIP，也可来自下面的有效松弛证书。
限制近邻交接点或限制全局交接数量得到的是受限模型，即使该受限 MIP 求至最优，也
不能证明规范 Model 5 全局最优。

## 6. 零回收载荷精确证书

默认精确入口先求一个无接力可行解，再构造紧凑松弛模型：

- 保留每个原始 delivery/pickup 的访问、物理位置、时间窗和先送后取约束；
- 保留 E1–E2 发车与回收同步；
- 保留配送载荷；
- 只把 E2 pickup 的空容器重量和体积置零。

这是规范 Model 5 的有效下界。对任意 Model 5 可行解，把接力模式的 `TP` 映射回原始
pickup，删除 `TD/RP` 并对路线作捷径化，就得到该松弛的可行解。删除操作不会增加
载荷；在满足三角不等式的距离下，捷径化不会增加里程；等待又可恢复 pickup 时间窗
下界。因此松弛最优值不大于 Model 5 最优值。

若松弛的已证明最优值与无接力可行解目标值相等，则上下界闭合，可以直接认证完整
Model 5；这不是“假设不接力”，也不需要枚举完整接力搜索树。

若证书上下界不相等，求解器对小规模实例启用完备模式分解。对每个 pickup 枚举
“直接回仓/发生一次中转”两种互斥模式；在中转分支内部仍保留该前置仓的全部交接点，
由固定模式 MIP 精确选择。若宽分支超时，再把该分支完备细分为具体交接点组合，同时
删除未选择的 `TP/TD/RP` 节点。每个分支只有返回 `OPTIMAL`、`INFEASIBLE` 或
`CUTOFF` 才算关闭；所有模式全部关闭后才返回 `proven_optimal=True`。因此：

- 分解没有限制全局中转容器数量；
- 每个容器仍由模型结构保证最多中转一次；
- 顶层模式与细分模式的并集恰好等于规范 Model 5 的完整可行域；
- 任一分支超时都会使整体保持 `TIME_LIMIT`，不会把 incumbent 误报为最优解。

模式数超过配置阈值时才回退到完整联合 MIP。限制近邻或人为限制总中转数仍属于受限
模型，不能作为规范 Model 5 的全局证明。

## 7. 完备分解证书字段

当 `info["formulation"] == "exhaustive_pickup_mode_partition"` 时，主要字段为：

- `certificate.total_patterns`：顶层直接/中转模式总数；
- `certificate.closed_patterns`：已严格关闭的顶层模式数；
- `certificate.solved_refined_patterns`：求解过的具体交接点细分数；
- `best_bound == objective` 且 `mip_gap == 0`：完整全局证明闭合。

例如 4 个可中转 pickup 共有 \(2^4=16\) 个顶层模式。具体交接点组合只在宽分支
无法及时闭合时按需展开，因而不改变精确性，只影响求解速度。

当前分解还包含两项不改变可行域的性能增强：

- 同一前置仓的同质 E2 车辆按路线首个操作节点排序，消除交换车辆编号产生的镜像解；
- 单中转模式先用一个宽 MIP 同时选择所有同仓交接点；两个及以上中转的模式直接进入
  完备具体交接分解，避免先在候选链乘积很大的宽模型上消耗固定时间。

## 8. 多前置仓边界

候选交接点按 `e2_tasks_by_sat[sat_id]` 分仓生成。对属于前置仓 (f) 的 pickup (p)：

\[
H_p \subseteq C_f,\qquad o(p)\in C_f,
\]

并且携带车和接收车都从该仓车辆集合 (V_f) 中选择。模型不会创建连接不同前置仓
E2 节点的弧，也不会创建跨仓 `TP/TD/RP` 候选；显式传入其他前置仓的交接顾客会在
建模阶段报错。多个前置仓仍通过 E1 路线和各仓 E2 返回时刻发生上层耦合，但空容器
接力始终只发生在同一个前置仓服务区内部。

## 9. 实现入口

```text
models/routing/variants/model_5/model.py         联合 MIP 构造、容器接力约束和解提取
models/routing/variants/model_5/exact_solver.py  精确求解入口、证明口径和接力明细输出
tests/routing/test_model5_exact.py  退化关系与强制接力回归测试
```

规范精确调用：

```python
solve_exact(
    problem,
    e1_tasks,
    e2_tasks_by_sat,
    vehicles_per_satellite,
    max_relocation_candidates=None,
    max_transshipments=None,
    return_info=True,
)
```

返回的 `info["transshipments"]` 会逐项给出原顾客、交接点、携带车、接收车以及三类
关键时间，便于检查每条容器流是否真实、连续和可解释。
