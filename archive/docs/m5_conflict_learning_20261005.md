改进体现为本组冷证明缓存下的达标稳定性。种子44的旧版更快，不能宣称全面加速；三个种子也不能证明对任意输入普遍有效。

## 实现

主要代码：[multibatch_logic_benders.py](../../models/routing/solvers/exact/multibatch_logic_benders.py)。

1. **缩减时只判断可行性。** 保留原物理模型和成本目标，用 `SolutionLimit=1` 在找到首个可行解时停止。可行解仅用于否决一次删除尝试，不生成成本界，也不充当完整 M5 上界。不可行仍须另一种子独立读取原MPS再次确认。
2. **利用已证明冲突安排查询。** 相同仓的历史冲突交集只生成待检查条件，不能直接生成割。不同数值阈值视为不同条件；只有对应条件已有有效缓存证书，或重新构建原条件子问题并独立复算通过，才接受。
3. **调整删除顺序。** 先考虑条件在历史冲突中的出现频率；任务组再按“任务数量＋未在组内配对的配送/回收关联数”排序。较少出现、任务较少且关联较少的组先尝试删除，保留更有希望解释冲突的组。排序完全由输入结构计算，没有写入实例顾客编号。
4. **减少无效重试。** 已找到可行解的条件可以在本轮直接否决不可行性重试。不再为证明单条件冲突最小而求解无条件仓模型，仍不声称最小冲突。普通删除过程至多对一个未解决候选增加预算，优先处理原求解已完成、独立复算尚未完成的证明。
5. **复用待复算的MPS。** 这类文件只作为本轮待验证材料，复用前检查哈希；只有独立复算完成才写入证书缓存。最终三种子对照中没有实际触发这项复用，因此不把它计为本组收益来源。已知可行条件的复用分别触发2/3/3次。
6. **保护主问题预算并匹配精度。** 给原动态预留设置默认3秒的下限；这个下限在短任务中缩为总预算的10%，且不超过单次主问题上限。主问题 `MIPGap` 取原设置与 `target_gap/4` 的较小值，绝对gap设为0，避免仍有容易完成的主问题证明工作时过早转入分离。全局及物理界的保守余量保持原值。
7. **完善耗时记录。** 未得到可接受证书的调用也保存实际耗时；分别记录原子问题阶段、独立复算和复用情况。最终版本并未减少所有种子的请求总数，其收益来自整个查询顺序、停止规则、精度和预算组合。

数学可行域没有因为排序或预算策略而改变。所有接受的割仍基于原允许路径、真实车辆、原时刻/容量规则下的有效放松；完整方案继续检查一级供货、回收截止和清洗库存。`proven_optimal`、`proven_infeasible` 始终为False。

## 使用与回退对照

公开函数现在默认启用本轮策略：

```python
from models.routing.variants.model_5.exact import logic_benders_certificate

result = logic_benders_certificate(
    problem, initial_result=audited_result, time_limit=60,
    conflict_learning=True, final_master_reserve=3,
    diagnostics_dir="output/m5_logic_benders_current_version",
)
```

`conflict_learning=False, final_master_reserve=0` 恢复旧版查询与预算策略，便于同源对照。默认完整 `solve_exact` 路径未改变。源码版本更新会使旧诊断目录的版本检查拒绝续跑，应新建诊断目录；原有冻结实验和旧证书保留。

复现实验：

```sh
.venv/bin/python tools/audit/benchmark_multibatch_logic_benders.py \
  --output output/experiments/m5_conflict_learning_new_run \
  --cases 20 --seeds 42 43 44 --time-limit 60 \
  --compare-conflict-learning
```

输出目录必须不存在。驱动会固定模型构造的哈希种子，冻结源码与原输入，顺序运行两种策略，再独立复核。

## 保留的负结果

- [第一版](../../output/experiments/m5_conflict_learning_20261005/paired20/summary.json)使用常量目标做可行性查询。三个种子最终下界没有一致改善，种子44略有退步。该轮尚未固定Python哈希种子，作为探索结果保留，不能据此作严格的单因素耗时归因。
- [第二版](../../output/experiments/m5_conflict_learning_20261005/paired20_refined/summary.json)保留成本目标，但过度优先保留跨趟关联组，较早删除S1的大任务组。三个种子都停在约0.150990388% gap，均弱于各自基线。该轮已固定哈希种子。
- 最终版同时考虑组大小和跨趟关联，且跳过已知无效的检查，三个种子均达到目标。各版本的输入、参数、源码、日志、MPS、缓存和完整复核结果分别保存，没有覆盖负结果。

这些是组合策略对照，没有将全部收益归因于某一个单独功能。后续如要作论文层面的因素归因，需要追加独立消融及更多原输入。
