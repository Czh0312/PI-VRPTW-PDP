## 1. 检查结论

**当前四模型基本符合仓库已确认的单批次业务要求，但优化前的算法性能不能满足“大规模、高质量、可证明”的完整研究要求。** 没有在本轮独立小例枚举中发现精确模型改变最优值的反例；这不等于证明原实现对所有输入都没有问题。

确认并修复了一处 ALNS 可行性误判；另有多项会损失求解效率或解质量的实现问题，已经作针对性优化。M2/M4 仍以分仓枚举为精确算法主干，指数复杂度没有消失。ALNS 已加入真实的请求移除与插入修复，但仍需完整实例集、更多种子和更长统一预算的正式评测。

本轮特别区分：

1. 方案可行、已证明距离最优、已证明不可行、限时未找到解，是四种不同结论。
2. 单批次闭环满足容器循环要求，但不存在本周期内向下一批复用；池规模至少覆盖全部箱次。
3. 距离最优不等于工时、车辆数、费用或投资回报最优。
4. 历史基线包含较丰富的算法组件，但其模型规则不能直接代替当前闭环要求。

### 2.1 数学约束核对

记唯一批次开始、截止、一级归仓期限及周期结束为 `a,c,e,H`；订单箱数为 `n_o`、服务时间为 `s_o`、最短使用时间为 `h_o`；仓 s 的箱次为 `D_s=Σ n_o`，总箱次为 `Q=Σ D_s`。

- **一级供货**：每个有需求的仓恰有一次完整配送；不拆分该仓本批一级配送数量。携带配送任务的一级车辆固定在 `a+装货时间` 出发，其车辆占用从 a 开始。每车每批最多一趟，先送后取。驶向首个回收站的路段不能在 c 前开始。
- **二级供货同步**：装有配送货物的二级趟次须在该仓一级卸货完成后准备发车。准备过程也占用物理车辆，不能和上一趟重叠。
- **顾客任务**：每单恰有一次配送；M3/M4 另有一次完整回收。服务开始在对应时间窗内，且 `t_d+s_o≤c`、`t_p≥t_d+s_o+h_o`。
- **容量**：出发载全部本趟配送货物，配送扣减载荷、回收增加空箱载荷，逐段检查重量和体积。一级回收量不可拆给多辆车。
- **车辆复用**：相同仓、相同车辆按趟次序运行；下一趟准备开始不得早于上一趟卸货完成加整备时间。没有通过增加匿名车辆绕开车队上限。
- **回收闭环**：M3/M4 所有空箱都必须由二级在 c 前卸回，由一级在 e 前卸回总仓，并在 H 前完成清洗。
- **库存**：B=1 在 a 一次领走全部 Q 个箱次，故 `N≥Q`。没有未来批次可再次领取本周期回收箱。
- **连通与因果**：一级路径顺序变量、二级全局因果序位排除脱离仓的子环；全零时间情况下，也不能以送取相互依赖的循环冒充可行计划。
- **独立复核**：审计从显式路线重算距离、服务、容量、时间、截止库存、清洗释放和两个周期状态，不直接相信求解器的可行性标志。

这些约束在当前研究范围内相互一致。M1/M3 和 M2/M4 才是包装对照；M1/M2、M3/M4 是分仓对照。自由分仓的最优值包含固定分仓可行方案这一关系，以输入确实按顾客固定到单仓为前提；启发式有限预算结果不保证保持该大小关系。

### 2.2 应继续明确的模型边界

| 边界 | 对结论的影响 |
|---|---|
| 一级不拆仓配送、每车一趟；二级有输入趟次上限 | “不可行/最优”仅针对这些资源和服务限制；不能理解成无限趟次的原始 VRP 结论 |
| 整数时间刻度，行驶/作业时间向上取整，窗口末端向下取整 | 当前模型是声明精度下的模型；改变 tick 可能改变可行域 |
| 单一同质容器、无损耗、总仓无限并行清洗、前置仓无库容限制 | 不具备有限清洗线、损耗补购或多规格箱的经营描述能力 |
| 两种包装正向重量/体积相同 | 包装经济对照的假设，需实际规格校准 |
| 一级和二级距离直接相加 | 不等于具有不同车型费率的运输费用目标 |
| 固定路线采用最早可行时间表 | 统一去除任意松弛，但不优化工时，更不优化所有等距离方案的经济性 |
| 可输入非对称、非度量矩阵 | 不能不加条件使用三角不等式剪枝，也不能一概声称添加回收任务只会增大最优距离 |
| 静态全信息 | 不支持动态订单揭晓、已执行动作冻结或在线重优化 |

## 3. 发现的问题与处理

| 编号 | 严重程度 | 优化前问题 | 本轮处理及剩余限制 |
|---|---|---|---|
| F1 | 高：可行性误判 | ALNS 用尚未加入回收段的临时一级路线，检查最终车辆归仓状态；非度量矩阵下可误拒有效混合路线 | 修复。临时路线只检查已确定的配送部分，最终完整路线仍检查所有期限和车辆可用性 |
| F2 | 高：扩展性 | M2/M4 枚举 `仓数^顾客数` 个组合，无分仓成本下界剪枝 | 加入保守距离下界、剪枝、最近仓优先；指数最坏复杂度仍在 |
| F3 | 中高：预算浪费 | 枚举一遍后即返回，限时未闭合的分仓子问题可能仍有总预算可用 | 加入未闭合子问题再求解及经过审计的 MIP 初始解；保持证明状态诚实 |
| F4 | 中高：限时无解 | 首个固定分仓只得到约总预算 1/8，M4 可能错过 M3 可找到的初始可行解 | 首个分仓最多分配剩余预算 40%，提前证明完可把剩余时间用于其他分仓；并非对任意预算的可行性保证 |
| F5 | 中高：建模开销 | B=1 仍构造多批次回收归属、可变回收数量和库存释放变量 | 对 B=1 用已知回收量与直接截止约束等价替代；多批次仍保留动态归属机制 |
| F6 | 中：建模与搜索开销 | 每个节点反复扫描全部弧建流平衡，构造稠密不可能弧；二级路径同时有局部 rank 和全局因果序位 | 建邻接表，安全删除时间上不可能的弧；保留全局因果序位并去掉重复 rank；加入同质车辆对称性约束 |
| F7 | 中：重复工作 | 每次分仓转换/审计重新验证全部网络并重新进行 Decimal 时间转换，约 O(V²) | 分仓仅重建不可变订单及聚合，复用已校验的静态网络和旅行时间；网络不得在一次求解中被外部并发修改 |

| F9 | 中：无效搜索 | 单批次仍随机延迟到截止后；一次性包装仍有回收相关空操作；无变化提案也获正奖励 | B=1 去掉截止等待算子，一次性去掉回收算子；空操作降权；加入反转邻域和有界评价缓存 |
| F10 | 中：初解不一致 | 容量满时封存的组按送取成对相邻，最后一组却先送后取；可能过早等待回收而错过后续配送 | 所有打包组统一先送后取；保留按订单时间顺序的备选初解 |
| F11 | 中：重复冷启动 | 自由分仓反复遇到相同分仓时，从头搜索 | 有界缓存最近分仓的已审计可行解，作为后续 ALNS 热启动；不会把启发式评价变成证明 |

### 3.1 F1 的可复现反例

构造 D、S、T、A、B，除 `S→D=100` 外，其余不同地点间行驶时间/距离均为 1，同地点为 0。一级配送顺序 `D→T→S`，随后截止时依次在 S、T 取箱后归 D。两个顾客各由所属仓完成送取。

- 临时纯配送路线 `D→T→S→D` 的归仓时刻为 102，超过周期末 65。
- 完整送取路线经 `S→T→D` 归仓，时刻为 32；清洗完成为 37，全部要求满足。
- 独立审计判定有效，总距离为 8。
- 旧解码器却返回 `E1_TERMINAL_VEHICLE`，评分为 1,000,008，排除该方案。

这是**漏掉可行候选**，不是发现旧程序向用户输出了一个审计通过的非法解。证据：[旧反例输出](../../output/experiments/single_batch_audit_20260930/nonmetric_decoder_before.json)；回归：[反例及独立枚举测试](../../tests/routing/test_single_batch_solver_audit.py)。

## 4. 加速为什么不会据此改变业务可行域

### 4.1 B=1 回收量常量化

对任一完整单批循环方案，每笔订单送取数相等，且所有二级空箱必须在唯一截止前卸回所属仓。因此 `q_s=D_s`。一级仍恰有一辆车在该仓一次取完，容量和截止后的首段行驶规则全部保留。

这只是把已由其他约束唯一决定的变量替换为常量。二级含回收任务的趟次直接要求 `return_complete≤c`；并没有强制所有纯配送趟次也在 c 前返回。单批次箱池约束化为 `N≥Q`，清洗和末态约束没有删除。

### 4.2 稀疏弧与对称性

若节点 i 的最早服务开始加服务时间和直接行驶时间已晚于节点 j 的最晚服务开始，则 i→j 不可能出现在合法路线中，删除该弧是安全的。强化后的最早/最晚界使用放松网络最短路，允许更多中转，因此不依赖输入满足三角不等式。

不同物理车辆具有相同容量、起点和可用日程，可交换整个车辆计划的编号，使先编号车辆优先启用。保留趟次顺序和资源复用约束。二级全局因果序位已沿每条选中弧严格增加，局部 rank 对排除子环重复；删除它不删除因果约束。

### 4.3 分仓下界与证书

对每层、每个有任务的基地，求所有必访任务的最小入弧之和再加至少一次归基地弧；同时求最小出弧之和再加至少一次离基地弧，取二者较大值。再对两级求和。此放松忽略若干容量和时间限制，因此不高估合法路线的最优距离。一级仍排除取后送弧。重复地点按不同任务保留，非对称、非度量距离均适用。

使用前对浮点界保守下调。只有该下界不小于现有已审计可行解，才能将分仓记录为 `BOUND_PRUNED`。这说明“该分仓不可能改善当前最优方案”，**不说明该分仓不可行**。只有全部分仓被最优、不可行或安全成本界闭合，才报告全局最优；未访问组合仍使用零下界。

Gurobi 设置相对和绝对 MIP gap 为零，但其数值可行性仍按浮点求解器容差解释，不能称为有理数形式化证明。[Gurobi 参数文档](https://docs.gurobi.com/projects/optimizer/en/current/reference/parameters.html)

### 5.2 固定的诊断实验协议

每个版本 **112 次**：7 个案例 × 4 模型 ×（1 次精确＋3 个 ALNS 种子）。精确预算 5 秒、seed=42；ALNS 预算 1 秒、最多 2,000 次外层迭代，seeds=42/43/44。作业串行运行，每个子进程有“预算＋20 秒”的外层硬超时；不丢弃失败结果。

环境：Python 3.9.6，Gurobi 12.0.3，macOS-27.0-arm64-arm-64bit；Gurobi 单线程。计时采用整个 `solve_routing` 调用墙钟，包含解的规范化与审计；不只使用内部 MILP runtime。求解器预算为协作式限制，构建、提取及审计可带来少量超时开销。

输入先冻结，再运行；**before/verified 输入哈希完全一致**。小例包含两个机制例、两个 Zhou 7 顾客派生例及 LaDe 10 AOI；另含 Zhou 50 顾客派生例与 LaDe 30 AOI。此处不以“30 AOI”代称 100/200 顾客大例，未覆盖的更大规模不作性能保证。

### 5.5 末轮输入规范化补丁

直接 Python API 构造 `Order(count=1.0)` 时，旧验证认为它是合法整数值，但 ALNS 审计要求实际 int，精确解提取又可能把 float 当作 Gurobi 变量读取 `.X`。已在实例构造时统一转成整数；JSON/CSV 加载器原本已做转换。反例记录为 `integral_float_before.json`，8 个模型/算法组合均加入回归。

此补丁在性能运行完成后加入，只影响直接 API 的整数值浮点输入。已将性能运行对应源码保存为 `solver_benchmark_verified.tar.gz`；28 个冻结案例/模型在补丁前后的已加载订单、需求、重量、旅行时间、日程与车队完全一致，且箱数类型均为 int，见 `post_benchmark_input_equivalence.json`。最终全库测试覆盖此补丁，没有把它声称为实测提速来源。


## 6. 是否已经具备加速能力

**具备，而且本轮已有小例与代表例的实测证据；但仍不适合宣称四模型已具有统一的大规模精确求解能力。**

| 方法 | 当前已经具备 | 仍缺少 |
|---|---|---|
| M1/M3 精确 | B=1 专门化、时间界和弧删除、同质车辆对称性消除、减少重复约束、构建阶段预算检查 | 更强 LP 松弛、有效不等式、分解或路线列模型、大例稳定可行初解 |
| M2/M4 精确 | 上述固定分仓能力，加分仓成本界、剪枝、优先候选、重访未闭合分区及 MIP 初始解 | 可扩展的联合分仓模型或带可证明界的分解；逐一分仓仍有指数瓶颈 |
| M1/M3 ALNS | 多请求破坏/贪心修复、原有迁移/拆并/换车、反转、评价缓存、空操作降权 | 后悔插入、自适应可行性惩罚、局部时间/载荷增量传播、系统多启动 |
| M2/M4 ALNS | 上述能力、顾客迁移/交换、重复分仓可行解热启动 | 跨仓联合破坏修复、迁移时保留未受影响路线、根据收益分配内外层预算 |

这里的局部插入评价只用于挑选候选，不能替代全局同步检查。经典 ALNS 以多种竞争子启发式和基于历史表现的选择为核心；当前实现比优化前更接近这一结构，但不能据此声称达到文献中成熟算法的实验水平。[Røpke 与 Pisinger，2006](https://orbit.dtu.dk/en/publications/an-adaptive-large-neighborhood-search-heuristic-for-the-pickup-an/)

## 7. 后续工作的优先级

1. **先做正式、可复现的算法评测**：按当前有效数据清单重新登记实例集合；同预算、多种子，分别报告可行率、最好/均值/离散程度、距最佳已知解的差距及证明 gap。全部失败和超时保留。大例不能用 ALNS 间差距代替到全局最优的 gap。
2. **优先重构 M2/M4 精确分仓层**：比较联合分仓变量的 MILP 和带有效子问题界的分解。不要仅提高枚举时间上限就把指数问题视作解决。中大例以“可行上界＋可信下界”作为阶段目标。
3. **继续改善 ALNS 的有效邻域**：先做本轮各改动的消融，确定缓存、破坏修复、初解和温度策略各自贡献；再增加后悔插入、跨仓联合修复以及局部增量评价。增量代码必须与完整解码器逐例对照。
4. **保持求解器隔离**：ALNS 不依赖 Gurobi，精确算法不自动调用 ALNS。若以后要研究“ALNS 给 MILP 提供初始解”的混合实验，应作为显式实验模式，单独记录启发式预算及总预算。
5. **经营问题另行校准**：如果真正需求是最小总成本，应明确车型距离费、工时费、车辆启用费与包装费的无重复计费关系，再改目标；真实清洗能力、包装规格和损耗不能用当前演示参数代替。

第二个候选版本在 LaDe 30 点的 M3 三种子均值从 174.028 退步到 195.054（约 +12.08%）。分析发现，仅按迭代数降温在修复算子变慢时不能保证限时结束前充分降温。增加双预算降温后，先做三种子诊断，再重跑完整 112 个作业；旧候选结果没有删除。这是探索性调优，仍需要独立留出集检验，不能把同一组实例上的选择当作无偏泛化评测。

统计解释检查覆盖 11/11 类：

| 检查项 | 本轮处理 |
|---|---|
| 辛普森悖论 | 按模型、算法和实例列出结果，不只给跨规模总均值 |
| 生态谬误 | 代表例整体改善不推断每个实例或每个种子都改善 |
| 选择偏差（Berkson） | 实例和预算在运行前登记；明确是诊断选例，不代表完整目标分布 |
| 碰撞变量偏差 | 没有做条件回归；共同可行子集的距离比较同时报告全体可行率 |
| 基率忽略 | 所有计数提供分母，不只展示成功样例 |
| 均值回归 | 不因一次较差种子就做总体改进的统计因果结论 |
| 幸存者偏差 | 失败、限时无解和退步均保留；不能计算距离的行明确列状态 |
| 多重搜索效应 | 无显著性检验，不选择性报告最有利 p 值 |
| 分析选择自由度 | 保留中间候选版本、预算调整原因和全部前后记录；本轮属于探索性优化 |
| 相关不等于因果 | 顺序同机对照支持诊断判断；没有随机交错和多次耗时复测，不给统计显著性结论 |
| 反向因果 | 属工程版本对照，无人群因果方向分析；不据此外推真实经营收益 |

可复现性：固定迭代、相同种子、时间预算充足且迭代进度主导降温的 ALNS 已加入路线一致性测试；限时 ALNS 的迭代数和结果仍可能随机器负载变化。性能表是单次同机诊断观察，尚非重复测量的置信区间。本报告没有把 3 个种子包装成统计充分性，也没有将历史未完成作业当成已完成作业。
