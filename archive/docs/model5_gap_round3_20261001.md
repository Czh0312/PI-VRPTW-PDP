## 已落地的可选接口

1. **批量定价 `batch_pricing=True`。** 每轮保留各配送批次和纯回收类别的候选路线，同时向主问题加入所有负约化成本列。之前只加入一条列，造成反复求解。完整定价域与严格的原距离、载荷、窗口和约化成本重放保持。
2. **分类对偶修正 `dual_repair=True`。** 配送批次的每条路线至少含一个该批次配送任务，纯回收路线至少含一个回收任务。依据每个类别的保守定价下界，降低对应任务对偶价格，使全部路线的修正约化成本非负；同时检查公共车队价格修正的所有分段端点。证书不需要把每个类别的负值都乘以最大总趟数。输出保留修正后的乘子和原始定价见证。
3. **两趟任务重组 `recombinations=True`。** 对同仓两趟的任务并集做限额枚举，寻找更便宜的互补任务集合及顺序。保留原路线，所有选择仍由完整供货、使用时间、清洗库存、物理车辆与时刻主问题决定。部分枚举只提供候选，不提供下界。

对应 [`multibatch_route_cg.py`](../../models/routing/solvers/exact/multibatch_route_cg.py)、[`multibatch_route_pricing.py`](../../models/routing/solvers/exact/multibatch_route_pricing.py)、[`multibatch_route_pool.py`](../../models/routing/solvers/exact/multibatch_route_pool.py)。三个选项默认均关闭；本轮未修改 ALNS 搜索核心。示例仅演示接口，最终数值还包含后述容量割及联合证书阶段：

```python
from models.routing.variants.model_5.exact import (
    reoptimize_route_pool, route_cover_certificate,
)

better = reoptimize_route_pool(
    problem, audited_alns_result, time_limit=120, seed=42,
    exchanges=True, recombinations=True, max_columns=512,
    e1_backend='patterns',
)
certificate = route_cover_certificate(
    problem, initial_result=better, time_limit=600, seed=42,
    e1_time_limit=20, e1_backend='patterns',
    batch_pricing=True, dual_repair=True, pricing_time_limit=8,
)
```

这些选项使用 Gurobi；基础 ALNS 的依赖和默认入口保持原有行为。五仓一级枚举仍需显式启用。

## 容量割与条件供货联合下界

容量割和联合证书的实现保存在冻结实验源码及运行脚本中，未开启默认求解流程。

**容量割。** 整批及客户子集的配送需求若超过单车容量，就至少需要两趟访问相应集合。主问题加入必要的整数趟数下限；定价模型加入“是否访问子集”的精确二元标记，计入新对偶项，仍覆盖全部任务路径。子集由受限 LP 的违反量选出，但受限 LP 目标从不作为下界。

最终逐仓有效二级下界约为：S0 235.38、S1 378.72、S2 89.94、S3 201.89、S4 293.30。S1/S4 的定价与容量割 LP 均收敛。两个箱池的二级松弛系数、窗口、有限总趟数、资源和全部有向距离/时间一致，经过指纹复核才共享这些二级证书。一级库存模型保持箱池各自独立。

**联合证书。** 独立优化一级和二级，可能分别选到不能同时实现的供货时刻。一级最优松弛方案在 `S3/b1` 的供货完成时刻为 **32870 秒**，比当前可行方案晚 **1195 秒**。如果实际供货不早于 32870，重新推导必要的配送和回收最早时刻，再对完整二级路线域定价，可证明该仓二级成本至少 **247.454241**；这个下界只对该条件成立的方案有效。

联合主问题保留完整一级路线枚举和箱池库存条件，给各仓引入二级成本变量 `theta_s`。每个变量至少取其无条件二级下界；若选中的一级路线在 `S3/b1` 的最早供货时刻达到阈值，则 `theta_S3` 至少取上述条件下界。一级路线的最早时刻不晚于真实时刻，所以该条件不会排除原 M5 可行方案。

目标为 **一级原距离加全部二级成本变量**。完整池联合松弛证明下界 **2160.374308**，直接作为全模型 LB，不能再叠加一级下界。紧池联合证书为 2271.768103，略弱于独立分量组合的 2271.768341，因此最终采用后者。

实现与证据：[条件上下文和联合模型脚本](../../output/experiments/model5_gap_round3_20261001/run_joint_conditional.py)、[条件定价见证](../../output/experiments/model5_gap_round3_20261001/joint_conditional/S3_b1.json)、[完整池联合证书](../../output/experiments/model5_gap_round3_20261001/joint_conditional/master_0/certificate.json)。条件定价约 0.99 秒，两个联合主问题分别约 3.00 秒、3.79 秒。提前注册了三个条件候选；首个已满足完整池 5% 停止条件，另外两个未启动。

## 探索预算和无收益结果

| 阶段 | 额度 / 实际情况 |
|---|---|
| 固定对偶价格的原模型 / 连通性模型对照 | 每仓每变体最多 40 秒；均在数秒内最优，连通性没有一致提速，未部署 |
| 批量定价 | S1、S4 各 180 秒；S1 首先得到新有效下界，S4 当时未得到强于已有值的新界 |
| 两趟重组 | 每组最多 120 秒；约 81.51 秒、53.38 秒，均改善可行成本 |
| 冷启动尾部定价 | 每仓每变体最多 40 秒；得到可重放完整域见证 |
| 保留已有列继续 CG | S4 最多 150 秒、S1 最多 120 秒；实际约 134.51 秒、32.38 秒，均收敛 |
| 整批趟数割 | 每仓最多 180 秒；实际约 37.68 秒、78.93 秒，改善很小 |
| 客户子集容量割 | 每仓最多 180 秒；S1 约 96.33 秒、S4 约 47.42 秒，增加有效下界 |
| S0 容量割诊断 | 最多 180 秒，实际约 10.72 秒；无明显改善 |
| CG 路线加入可行解池 | 完整池最多 120 秒，约 120.30 秒；UB 降至 2253.30 |
| 同一候选池优先搜索可行解 | 最多 180 秒，实际约 126.26 秒证明池内最优；UB 不变，原 M5 GAP 当时仍超过 5% |
| 条件供货定价及联合证书 | 首个条件最多 90 秒、联合主问题每组最多 30 秒；首个条件即使完整池达标 |

全部是已有最好解上的追加探索预算，不能当作统一时限的纯 ALNS 对照。初期案例字段读取、验证工具目录和 JSON 任务键归一化问题均已修复，失败日志保留；编译缓存受目录权限限制时改用源码语法解析，未扩大权限。未把无收益探索隐藏为成功改进。

## 方法解释检查

**11/11 已检查**：按规模和箱池分别报告，避免 Simpson 聚合；不将四组配置推广到全部实例，避免生态谬误；这是既有开发样本，记录 Berkson 选择偏差；没有条件回归，collider 不适用；分母明确为四组已观察配置，避免基率忽视；最好解热启动和新增预算不能解释为同预算算法效应，控制均值回归误读；保留无收益方法和失败日志，避免幸存者偏差；记录每阶段而不选择性报告；后续容量割与条件阈值是探索，承认分叉路径；下界、可行成本和单个 ALNS 算子收益不混淆；不作因果、反向因果、显著性或多种子稳定性声明。
