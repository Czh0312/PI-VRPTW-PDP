# 单批次 ALNS：等价评分与解码提速（2026-10-01）

## Material Passport

- Origin Skill：academic-research-suite / experiment-agent。
- Origin Mode：validate，连续执行用户授权的 M1–M4 单批次优化。
- Verification Status：VERIFIED，限于保存的性能对照、独立审计、固定迭代等价性和集成回归。
- 对照基线：已采用末段 20% 局部改进的上一轮版本。

## 结论

**本轮主要收益是减少重复计算；M4 的提速和同时间质量改善最明显。**

CPU 耗时使用两个 100 顾客实例、每次固定 300 次迭代的三次重复中位数。质量使用另一场景的 50/100 顾客实例、统一 5 秒、种子 42/43/44，每模型六对。两列对应不同实验，不能混为同一工作量。

| 模型 | 固定迭代 CPU 耗时下降范围 | 同为 5 秒的平均距离变化 | 改善 / 持平 / 退步 | 最大单次退步 |
|---|---:|---:|---:|---:|
| M1 | 8.0%–9.4% | -0.62% | 2 / 0 / 4 | +1.66% |
| M2 | 4.0%–4.4% | -1.51% | 5 / 0 / 1 | +2.49% |
| M3 | 13.5%–14.0% | -1.78% | 6 / 0 / 0 | +0.00% |
| M4 | 15.1%–19.3% | -4.12% | 5 / 0 / 1 | +1.70% |

每组质量差计算 `(新版距离 / 基线距离 - 1) × 100%` 后等权平均；负数表示改善。**固定迭代实验的路线、分仓和目标值前后完全一致**，48 次运行均审计有效。更快评分没有改变其搜索轨迹。

M1 的均值虽改善，六对中仍有四对退步，不能称为稳定的质量提升。墙钟预算下可以执行更多迭代，同时降温和停止位置会改变，因此固定迭代等价不保证每个固定时间作业更好。

已有 100 顾客来源的 15 秒补充结果：

| 模型 | 配对数 | 平均距离变化 | 改善 / 退步 |
|---|---:|---:|---:|
| M2 | 2 | -1.44% | 2 / 0 |
| M4 | 2 | -11.26% | 2 / 0 |

该部分只有两个种子，且使用已有来源，不是未见实例验证，不将 M4 的大幅均值改善外推为一般结论。

全部 **28/28 个新版结果**通过独立审计和周期重放，基线结果也全部有效。最大实际求解预算超出约 **0.056 秒**，包含收尾审计与规范化。

## 改了什么

1. **单次修复内准备任务属性**：提前保存订单、送取类型、重量、体积、窗口和单批截止时间。局部评分沿用原来的求和与惩罚计算顺序，减少对同一订单的重复解析。B=1 不存在跨批混装，去掉反复构造批次集合的工作。
2. **有界弧缓存**：单次修复内对 `problem.distance` 和 `problem.travel` 各缓存最多 4096 对节点。距离仍通过问题对象的 API 取得，支持有向、非度量输入。缓存不跨修复和问题修改复用；没有全局缓存。
3. **单批求解接入一级回收缓存**：复用已有 `CycleEvaluator`，固定分仓最多 128 项；M4 每个分仓最多 32 项，仍保留原有八个分仓上下文上限。缓存键覆盖一级配送顺序、回收顺序、车辆提示和实际回收数量。返回的路线与事件复制后归调用者持有。
4. **完整检查保留**：二级时序、截止前实际回收量、库存释放、完整调度与独立审计继续逐候选执行；一级缓存不缓存整体可行性结论。每个评价器只属于一个问题/分仓对象。
5. **参考实现保留**：`repair_orders(..., fast_scores=False)` 可使用原局部评分；`cache_scores=False` 和 `screen=False` 仍用于原有评分缓存/筛选对照。

没有改变搜索算子、候选排序、平局处理、模拟退火接受规则、末段改进比例、业务约束或目标。B>1 修复仍走原评分路径，本轮未改动 M5 搜索策略及缓存实现，也未改动精确求解器。

## 可复现协议

- 固定工作量：`zhou_Set2_100-5-1b`、`zhou_Set2_100-10-1`，四模型，seed=42，恰好 300 次迭代，60 秒上限不触发；每版本三次独立进程，前后交错。计时使用进程 CPU 和墙钟，不含数据加载，不含 profiler，也不含外部复核审计。求解器内部审计计入时间。
- 同预算新场景：`zhou_Set2_100-10-2_subset50_scenario02` 与 `zhou_Set2_100-10-2_scenario02`，四模型，5 秒，种子 42/43/44，共 24 对；在观察本轮结果前登记。50 顾客例嵌套于母例，不能视为两个独立来源。
- 较长预算：`zhou_Set2_100-5-3`，M2/M4，15 秒，种子 42/43，共四对；来源此前已观察。
- 质量实验迭代上限 1,000,000；每对交替先运行基线或新版，串行新进程，失败/退步均保留。输入与源码冻结，防止其他聊天的并行修改进入性能对照。
- 机器负载未完全控制，结果是描述统计，不作显著性或严格时间因果推断。未覆盖全部大规模实例，没有 30 秒以上结论，没有全局最优证书或有效最优性 gap。

## 验证

新增 15 个回归用例：12 组精确评分/修复对照，覆盖浮点需求与容量、有向非度量距离、重复订单任务、等待、迟到、超载、空路线和多趟；共检查 **1440 条局部路线评分逐值相等**。另检查跨问题误用拒绝，以及两种固定模型下一级缓存与完整解码器对有效/无效状态的一致性和结果所有权。

原来的评分缓存回归显式使用参考评分，继续检查缓存与不缓存的调用数量和解一致性；新增测试单独检查快速评分，避免旧测试因绕过参考函数而失去意义。

全库回归为 **511 passed，14 条依赖弃用警告，57.46 秒**。另外对四模型、两个 100 顾客实例分别在当前工作区执行 300 次迭代：八组路线、分仓、目标值及迭代数与冻结候选完全一致，均重新审计有效。四个实施文件及依赖的一级缓存/完整解码器与性能快照哈希一致。

统计谬误检查 11/11：模型/预算/来源分层；不把局部均值外推全体；说明来源选择；不作碰撞变量调整；保留全分母与失败；不挑极端种子；不删除退步；不做显著性挑选；预先登记作业并保留完整源码；承认机器负载限制；指定预算不存在所讨论的反向因果问题。
