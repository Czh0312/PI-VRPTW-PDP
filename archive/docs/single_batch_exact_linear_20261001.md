# 单批 M1–M4 第八轮：有界线性连接与载荷求和复用

本轮以等价的有界线性关系表达二级连接，并复用每趟出发载荷的求和。
有限车队、整数时间、每车趟数、准备/周转、送取时间窗、使用时长、容量、截止与距离目标均保留，
`MIPGap=0`、`MIPGapAbs=0` 和独立审计/周期重放不变。该变换不保证所有限时实例更快。

## 数学依据

对二元弧 x 和有界变量，条件 `x=1 => t_j >= t_i+c` 可表达为

`t_j >= t_i+c-max(0, U_i+c-L_j)*(1-x)`。

当 x=1 时保留原约束；当 x=0 时，任何符合原上下界的变量值都满足新行。
系数由每条弧的有效上下界推导，不使用统一的任意大常数。
两个任务的载荷连接 `x=1 => q_j=q_i+delta` 分为两行：

- 下侧系数：`max(0, U_i+delta-L_j)`；
- 上侧系数：`max(0, U_j-L_i-delta)`。

配送 delta 为负，回收为正。时间界沿用安全最短路径与可选分仓窗口；载荷界沿用此前证明的实际载荷界。
自由分仓共享任务的边界弧必须使用**全局任务界**计算失活系数，不能使用另一个未启用仓点的局部窗口。
仓点窗口本身也按全局任务界失活，避免限制在其他仓点执行的任务。

因果序位在 `[0,C]` 内，严格前进的失活系数为 `C+1`。
连续路线归属在 `[1,R]` 内，以两个系数为 `R-1` 的线性行表达选中弧两端属于同一路线。
唯一二元访问仍保证归属值在整数可行解中等于唯一实际路线编号，不新增路线归属整数变量。

单批准备与截止关系按同样方法表达。出发时间下界使用真实供货时间的上界加准备时长失活；
含回收任务的路线仍必须在唯一截止前卸回。相邻趟次的准备约束保留上一趟完整回仓和周转。
准备时长非负，因此含准备的串行约束已蕴含原来的不含准备约束，不再重复加入后者。
任务时间的上界已包含配送截止减服务时长；路线回仓时间上界已包含周期结束减周转。
只删除这些由已有界保证的重复条件，极端周转超过周期的不可行约束仍保留。

每趟新增重量、体积两个连续出发载荷变量，分别等于该趟全部配送访问的载荷总和，变量上界为物理容量。
任一原可行解可以把这两个变量设为原求和值；任一新可行解又可消去它们还原原式。
原来在每条出发弧中反复展开的配送访问求和，现在每种资源只定义一次。

## 默认范围与控制开关

- 使用内部弧压缩的模型：完整二级线性连接，且复用出发载荷求和。
- 固定分仓、含回收、未压缩的 M3：完整二级线性连接，保留原出发载荷表达式。
- 其余未压缩模型：保留原默认指示约束路径。

压缩与否仍沿用此前的10,000条原内部索引弧阈值；这是工程策略，不限制搜索域。
配置按模型结构选择，未逐个案例选取最好运行。
`single_batch_formulation.build_model(..., linear_e2_links=False)` 可还原原连接路径；
`factor_e2_loads=False` 可单独关闭载荷复用。
`linear_e2_links=True` 或 `'complete'` 强制完整版本，`'identity'`、`'internal'`、`'all'` 保留作为组件对照。
结果记录 `single_batch_linear_link_mode`、`e2_departure_load_variables` 和相应结构特征。
单批实现未改动 M5 建模文件；共享求解器中另一个聊天新增的载荷初解兼容、结构统计与 M5 特征均保留。

## 完整流程的24个冻结案例

先完成整套基线，再完成整套最终配置；每例总求解预算10秒、Seed=42、Threads=1，阶段内顺序运行。
两阶段均有24个通过独立审计和两周期重放的方案，无生产实验错误。

退步的30客户 M1，以及未取得原最优证明的10客户 M4、12客户 M2，其主 MILP均未启用本轮新表达。
`unchanged_model_diagnostics.json` 确认这些模型的 Gurobi Fingerprint 完全相同。
它们在同一墙钟预算内完成的 Work分别为16.711→10.194、8.212→7.192、12.385→12.217。
模型指纹相同不保证初解、预算分配或搜索轨迹相同；自由分仓的固定分仓热启动仍可能使用本轮变化。
这些结果表明固定时间对照存在明显吞吐/截止波动，不能将整套运行的退步直接归因于主模型的新表达；
也不能由这个单次对照声称总体提速或统计显著性。所有开发案例均不是留出的泛化测试集。

完整流程中，30客户 M4的距离仍为1074.521、Gap仍为75.85%，根节点瓶颈尚未解决。
