# 单批次模型 1–4：第二轮求解能力与稳定性优化

日期：2026-09-30。基线是上一轮检查报告完成后的实现，不是最初的旧算法。
目标：增加短时预算内得到有效解的机会，减少重复计算，改善自由分仓搜索的质量和种子间波动。
业务约束、距离目标、整数时间刻度、独立审计和精确/ALNS 隔离要求保持相同。

后续已完成 [第三轮联合分仓优化](free_assignment_joint_optimization_20260930.md)。
本报告保留第二轮当时的实现与实验结论；当前 M2/M4 的后端和全局下界以第三轮报告为准。

## 1. 这次为什么选择这些改动

上一轮尚有两处突出问题：较大实例的精确算法 5 秒内无可行解；自由分仓 ALNS 把预算切成许多短段，
换分仓时几乎从头搜索。单纯增加迭代上限，或统一换一个 Gurobi 参数，都不能直接解决这些结构问题。

本轮先登记 8 个实例族、4 个模型，精确法每个作业 5 秒、种子 42；ALNS 每个作业 1 秒、
最多 2,000 次迭代、种子 42/43/44。共 128 个作业/版本，逐作业串行执行、使用新进程，冻结输入并记录哈希。
其中 4 个实例族在本轮候选调优时未使用：Zhou 7-2-2b、Zhou 100-5-2 的 50 点子集、LaDe 0824 的 10/30 AOI。
所有输出都由独立审计器再次检查，并执行周期复放；求解器自报可行不作为唯一依据。

材料范围：当前仓库模型/代码、固定数据和参数、真实执行日志、Gurobi 官方文档。
这是工程诊断对照，不是完整论文实验；车辆、清洗等参数仍有场景假设。

## 2. 已落地的精确算法改动

### 2.1 按唯一任务共享状态与内部弧约束

原模型在每辆二级车、每个趟次重复建立某订单的送货/回收时间、服务后载荷和弧传播约束。
新模型在 B=1 下对每个 `(order_id, kind)` 建立一组时间/载荷；内部相邻任务的约束也只建立一份。
车辆、趟次、出发/返回边界和路线选择仍显式保留，模型 5 继续使用原来的多批结构。

等价性的关键不是假定客户只出现一次，而是**每项订单任务恰好执行一次**：同一客户多个订单仍是不同任务。

1. 旧模型的一个可行整数解中，每个任务只有一个被选择的路线副本，因此其时间和服务后载荷有唯一值。
2. 对内部弧定义 `y(i,j) = sum(x(route,i,j))`。任务恰访一次保证该和为 0 或 1。
3. 时间、载荷和严格因果次序约束改为在 `y=1` 时生效，与原来被选中副本的约束相同。
4. 从新解回到旧解时，把共享值填入唯一被选中的副本，未选副本时间设为 0，即可满足原结构。

距离目标仍按原路线弧计费；载重/容积、时间窗、车辆连续使用、送回先后、截止卸货和清洗末态均未删减。
不要求距离或时间矩阵对称，也不使用三角不等式。
保留 `build_model(..., share_e2=False)` 作为对照建模开关；正式入口默认启用共享。

### 2.2 独立构造可行初解，并在限时退出时保留

新增精确法内部的确定性构造器，先安排一级补货，再用两种时间顺序安排二级任务，尝试合并同一车辆的末趟。
每次合并重新计算该趟的时间、载荷和距离；另保留单订单趟次方案作为构造备选。
只有独立审计通过的完整方案才成为初始可行上界，再提交给完整 MILP 改进和证明。

构造时间受总预算约束，额外构造窗口最多 0.05 秒且最多占指定预算的 5%。构造失败只表示此启发式没找到，
不会报告不可行；构造成功也不会报告最优。该构造器不导入或调用 ALNS。
已有初解与新构造解按实际距离比较，保留较好者。

修复了初解处理的两处稳定性问题：

- 对同质车辆重新编号，压实使用的车辆/趟次索引，使有效初解满足模型的对称性约束与按任务数裁剪的车辆索引。
- 完整 MILP 建模超时、未完成初解处理或没有找到更好解时，返回已审计的 incumbent；状态与证明字段仍说明限时/未证明。

Gurobi 官方说明，部分 MIP start 的补全本身需要子问题搜索，因此“传入 Start”不等于已经保存了可返回的 incumbent。
这也是显式保留输入方案的原因。[官方 MIP start 说明](https://docs.gurobi.com/projects/optimizer/en/current/reference/attributes/variable.html#attrstart)

### 2.3 在同一次求解中复用安全旅行时间下界

必要条件预检查、单批次时间界和自由分仓子问题共享同一次求解计算出的最短路下界。
该上下文不跨独立求解永久缓存，后续编辑旅行时间矩阵会触发重新计算，避免旧下界导致错误剪枝。
卫星仓服务时间换算缓存按原值、类型和时间刻度区分，修改服务时长后不会沿用旧换算值。

## 3. 已落地的 ALNS 改动

### 3.1 减少插入位置的完整评分

固定 300 次迭代的 cProfile 诊断中，原破坏/修复过程占约 60% 总时间。
原先每个候选插入位置都会重新遍历整条路线，计算时间、载荷和距离。

新筛选利用局部评分的结构：`路线距离 + 非负容量惩罚 + 非负迟到惩罚`。
一个插入位置的精确距离增量可用相邻弧计算；若距离部分的保守下界已劣于当前候选，则跳过完整评分。
筛选使用浮点容差；负插入距离增量也允许，因此非度量矩阵仍适用。
这个界只筛选**局部插入评分**，不是全局可行性或最优性证明，最终仍经过完整解码和独立审计。

相同种子、300 次迭代的诊断中，目标值保持 200.4816；完整路线评分调用从 24,569 次减少到 17,125 次，
减少约 30.3%。带 profiler 的总耗时从约 0.638 秒到 0.545 秒，约减少 14.6%；这是单次剖析，不是正式速度置信区间。

### 3.2 跨分仓保留路线，重分配内外层预算

模型 2、4 在迁移客户后保留其他客户的路线顺序；移走该客户的全部订单任务，调整一级仓点覆盖，再插入新仓路线。
投影出的方案只是候选，新补货量和时间可能使原路线失效，因此必须重新解码、审计。
修复过程中达到截止时不会暴露部分任务缺失的方案。

超过 8 个客户时，初始分仓最多使用总时间/迭代预算的 40%，后续子问题每次最多使用约 10%。
每三次尝试定期继续优化当前最好分仓，其他尝试进行近邻分仓、迁移或交换；相同分仓保留有界热启动缓存。
40% 是本轮探索后保留的工程策略，不宣称是所有规模/预算的最优比例。
结果新增首个可行解时间、最好解时间、跨分仓投影次数等诊断字段。

一个中间版本仅增加投影、仍沿用原预算切片时，LaDe 30 点模型 4 的种子 43 退步到 247.9731。
该版本日志完整保留；这促使本轮调整预算和继续优化当前分仓。最终表使用完整重跑的最终版本，未混用最好种子。

## 5. 验证范围与仍未解决的问题

完整回归为 **311 项通过**，含原 287 项与新增 24 项；14 条警告来自既有 matplotlib/pyparsing 弃用提示。
新增验证包括有向非度量矩阵下筛选/未筛选修复一致、同一客户多订单迁仓完整性、保留未迁移任务顺序、
旅行时间/服务时间编辑后的缓存有效性、多车辆多趟次下共享模型与原索引模型最优值一致、初解审计、
稀疏车辆编号重映射、建模超时保留有效方案。既有独立小例穷举、模型 5 回归和双算法隔离测试继续通过。

主要局限：

1. **模型 2、4 精确法仍枚举分仓。** `S^C` 的指数规模没有被这次压缩消除。存在未访问分仓时，全局下界可能仍为 0，
   全局 gap 为 100% 是证明不足的诚实表达，不能用某个固定分仓的局部 gap 冒充全局 gap。
2. **可行率与解质量分开看。** 独立构造器能提供短时兜底，但初始距离可能很大；得到有效解不意味着接近最优。
3. **稳定性不是逐种子保证。** 增加吞吐和改变搜索路径会带来个别退步；只有同一次求解内部保留 incumbent 才有
   “不会丢掉已知更好可行解”的保证，不能保证新版本每次都优于旧版本。
4. **限时可复现性仍有限。** 固定种子不消除机器负载、时间截止和求解器数值搜索路径的影响。时间预算也包含建模/预检查，
   调度与审计有少量收尾开销；外层进程另设超时保护。

下一阶段建议优先级：

- **高优先级：重构自由分仓的精确上层。** 比较联合分仓模型与带可验证下界的分解，重点是提高全局下界和有效分支剪枝，
  而不是简单增加枚举时间。较大实例应报告可行上界、全局下界、gap 与未闭合分区。
- **高优先级：更强的精确构造与有限路线池。** 先在现有独立构造器中改进可行合并，或用受限路线主问题求更好上界。
  若使用有限路线池，只有完整定价/分支证明后才可宣称原问题精确最优，不能把池内最优混为全局最优。
- **中优先级：ALNS 后悔插入与局部时间传播。** 目前仍有大量全路线评分与全局重解码；后悔插入改善紧时间窗任务排序，
  增量传播减少受影响链外的重算，但必须与完整解码器逐例交叉验证。
- **中优先级：正式稳定性评测。** 扩大实例/日期/种子数量，增加 1/5/30 秒预算、到目标质量的耗时曲线与配对重复运行。
  先验证泛化，再把当前经验预算比例升级为可配置或收益驱动的分配策略。
