## 结果

本轮保留固定搜索上下文内的数据复用和完整解码提速。CPU 数据来自两组 100 顾客实例，每版固定 300 次迭代、三个独立进程重复的中位数；质量数据来自另行登记的等时间对照。两者是不同实验。

| 模型 | 固定迭代 CPU 耗时下降范围 | 同为 5 秒的平均距离变化 | 改善 / 持平 / 退步 | 最大单次退步 |
|---|---:|---:|---:|---:|
| M1 | 8.8%–10.2% | +0.30% | 2 / 0 / 4 | +2.81% |
| M2 | 4.2%–6.0% | -1.06% | 1 / 0 / 5 | +4.90% |
| M3 | 6.1%–6.8% | -0.13% | 2 / 0 / 4 | +13.62% |
| M4 | 2.3%–4.9% | -1.91% | 3 / 0 / 3 | +0.95% |

每对距离变化按 `(新版 / 基线 - 1) × 100%` 计算后等权平均，负数表示改善。固定迭代的 **48 次运行全部审计有效，前后最终路线、分仓和目标值逐值一致**。墙钟停止位置及按时间降温会随提速改变，因此同时间结果仍可能退步。

100 顾客、15 秒的补充对照使用已观察的另一来源，每模型两个种子：

| 模型 | 平均距离变化 | 改善 / 持平 / 退步 | 最大单次退步 |
|---|---:|---:|---:|
| M1 | +2.18% | 1 / 0 / 1 | +6.41% |
| M2 | -0.46% | 1 / 0 / 1 | +0.14% |
| M3 | -0.63% | 1 / 0 / 1 | +4.06% |
| M4 | +0.17% | 1 / 0 / 1 | +2.25% |

全部 **32/32 个新版结果**通过独立审计和周期重放，32 个基线结果也全部有效。新版最大实际求解预算超出约 **0.066 秒**，包含求解器收尾审计。

## 实施

1. `SingleBatchCache` 为固定问题持有任务解析、完整评价和局部评分缓存。局部评分器在第一次使用时创建，此后复用任务属性与有界弧缓存；每次评分仍读取当前到货时间、车辆可用时间及主动等待。没有缓存完整局部评分。
2. 完整解码器一次准备订单任务的重量、体积与完整任务集合，避免逐候选重复解析。任务求和及浮点运算顺序保持原样。参考 `evaluate` 仍可直接使用；M5 未启用单批预处理分支。
3. 完整评价内缓存最多 512 项路线距离。键保留层级、二级起讫仓和事件访问顺序，重复访问不合并。距离按参考函数计算后复用；没有近似、对称性或三角不等式假设。时序、车辆复用、送取先后、窗口、容量、截止前回收数量、清洁库存和可行性继续逐候选计算。
4. M2 的迁仓投影与该次分仓子搜索共享上下文。M4 各分仓上下文相互隔离，延续原有八个分仓上下文上限。缓存不跨求解复用；同一问题在两次求解之间修改输入后会重新准备。
5. M1–M3 的末段改进也使用预处理局部评分。算子、候选和平局顺序、接受规则、目标和业务约束保持原定义。一级缓存限额继续为固定分仓 128 项、M4 每分仓 32 项。

## 未采用的试验

先试验了最多 512 项完整局部评分缓存。两组 100 顾客实例的 48 次固定迭代运行同样得到一致结果，但 M3 耗时增加约 1.1%–1.7%，M4 增加约 0.1%–2.1%；维护键和缓存的成本抵消了命中收益。因此删除该实现，没有将其纳入最终版本。源码与全部性能结果保留在 `rejected_score_memo_source` 和 `rejected_score_memo_fixed_work_*`。

## 协议与验证

- 固定工作量：`zhou_Set2_100-5-1b`、`zhou_Set2_100-10-1`，M1–M4，seed=42，300 次迭代，60 秒不触发上限；每版三次重复，前后交错、串行独立进程。CPU 计时不含输入加载、profiler 或外部复核审计。
- 5 秒质量：`zhou_Set2_100-5-2_subset50_scenario02` 与 `zhou_Set2_100-5-2_scenario02`，四模型，种子 42/43/44，共 24 对。这是已见母来源的另一场景，50 顾客例嵌套于 100 顾客例，不能视为独立来源。
- 15 秒质量：`zhou_Set2_100-10-2_scenario02`，四模型，种子 42/43，共八对；来源与场景此前已观察。
- 全部 32 对在查看本轮等时间结果前登记，迭代上限 1,000,000；前后交替顺序，所有失败和退步保留。输入与源码冻结。并行聊天的 M5/精确求解修改保留，其快照差异均有记录；单批所经的公共数据、审计和预检查实现前后相同。
- 新增 13 个回归用例，检查复用评分器读取当前时间输入、连续修复与参考一致、输入不被修改、超时不返回部分状态、新求解重新准备以及跨分仓隔离。完整预处理解码与参考实现对照 720 个随机有效/无效移动状态，并检查缓存上限及返回结果所有权；距离缓存另覆盖层级、仓点、顺序、重复访问和空事件。
- 全库回归：**576 passed，14 条依赖弃用警告，51.88 秒**。当前工作区另执行四模型、两个 100 顾客实例共八组固定迭代检查，最终路线、分仓和目标与冻结候选一致，均重新审计有效。

## 限制

三次 CPU 重复、三个短预算种子与两个长预算种子仅提供描述统计。机器负载未完全控制；来源和场景选择有限，来源内部的大小与场景存在依赖。不宣称每次同时间搜索都会改善，不提供全局最优证书、有效最优性 gap、全数据集或 30 秒以上结论。

统计谬误检查 11/11：模型、预算、来源分层；不外推局部均值；说明来源选择与依赖；不作碰撞变量调整；保留全分母；不挑极端种子；不删退步；不作显著性挑选；预登记并保留源码；说明负载限制；指定预算不存在所讨论的反向因果问题。
