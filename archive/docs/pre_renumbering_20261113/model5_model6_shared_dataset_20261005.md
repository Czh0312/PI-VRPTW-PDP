# 模型五与模型六共享数据集

## 共享范围

M5与M6的主对比入口为 `data/model5_model6/shared_v1_20261005/manifest.json`。395个配对场景来自已生成的 `model6_uniform_suite_v2`：91个Zhou/LaDe来源场景各三档窗口、10个规模代表场景各12个敏感性变体、2个人工机制例。它们保留93个来源family的相关关系，不是395个独立空间样本。

每个场景保存三份模型配置，合计790份M5/M6配置及395份成本对照配置。三份配置指向完全相同的网络、订单、车辆、距离/时间矩阵、运营策略和经济参数文件。逐字段验证原订单，只有批次标签和允许批次标签可适配；箱量、货重、送取窗、释放时刻、使用与服务时间不变。运营策略只改变参考批次日历及说明，周期边界、清洗与其它物理规则保持不变。

| 配置 | 日历、分批与箱池 | 目标 |
|---|---|---|
| `m5_case.json` / `M5_distance` | 固定参照日历、固定订单分批、显式N=Q | 距离 |
| `m6_case.json` / `M6_uniform` | 在声明范围优化均匀K、共同分界、订单分批、箱池与路线 | 成本 |
| `m6_fixed_policy_case.json` / `M6_fixed_policy_cost` | 固定M5日历、分批和N，仅优化路线与时刻 | 成本 |

M5方案通过独立审计后按M6相同费用和评价期重新计价。固定策略成本对照用于观察目标变化的影响；与自由M6的差值再观察联合决策变化。短预算搜索差值也受搜索质量影响，不能当作已证明的机制收益。M5的距离最优证明不等于成本最优证明。

M5预设池N=Q不称为最低需箱量。结果另列M5所得同一路线、同一时间表的最低需箱量及其计价，供保守参考；这也不是联合问题的最小箱池证明。费用沿用合成单位，不解释为企业实际人民币收益。

## 事先确定的固定参照

非机制场景统一使用K=3、每批配送阶段占批长75%的参照日历，周期08:00–21:00，批次开始为08:00、12:20、16:40。M6默认搜索K=1/2/3；`extended_k`为1–6。固定参照确实属于M6允许域，审计逐例检查批次起止、分界及N=Q包含关系。

10组`extended_k`与各自`spread_medium`共享相同物理输入和M5参照，仅改变M6的K范围；这正是配对敏感性设计，不能把M5重复参照计为新增独立样本。

人工机制的周期为190分钟，三等分在其输入时间刻度下不能精确表达，因此预先采用K=2、相同比例的共同分界。该选择依据时间表示精度，不依据求解成败或成本；两例仍有各自M5/M6配对，不能与旧机制日历结果混用。

固定分批按每单满足释放、配送、取箱和末轮卸货必要条件的**最晚批次**确定，不使用M5/M6求解结果。若某单没有合法批次，仍保留并记录阻塞原因。逐单条件不保证所有订单同时满足路线容量和时序，整体求解失败也不触发删单、扩车或放宽窗口。

模型五现在在必要条件、ALNS解码、直接MILP建模及独立审计中一致检查：订单释放时刻不得晚于其批次装货开始；固定批次必须属于订单显式允许批次。缺省旧字段继续兼容。这样分时到货变体在两模型中具有相同物理含义。

## 运行与复现

以下命令从项目根目录运行，输出目录须不存在或为空。配对运行默认包含上述三组，使用同方法、同种子与相同时间预算，先检查共享输入再冻结实际输入和源码。

```sh
# 重新生成全部配对场景；已有数据可直接使用
.venv/bin/python -m tools.data.build_model5_model6_shared_dataset \
  --output /tmp/m5_m6_shared_rebuild

# 检查395例的来源哈希、共享字段与参照允许域
.venv/bin/python -m tools.audit.audit_model5_model6_shared_dataset \
  --output /tmp/m5_m6_shared_audit

# 预览10个规模代表场景的配对任务
.venv/bin/python -m experiments.runs.run_model5_model6_shared \
  --anchors-only --variants spread_medium --seeds 42 43 44 \
  --time 10 --dry-run --output /tmp/m5_m6_paired

# 小例同时运行精确与ALNS
.venv/bin/python -m experiments.runs.run_model5_model6_shared \
  --families zhou_Set1_7-2-1 --variants spread_medium \
  --solvers exact alns --exact-time 30 --time 10 --seeds 42 43 44 \
  --output /tmp/m5_m6_small
```

`rows.json`保留全部成功、失败、超时和证明目标；`cost_pairs.csv`为同方法、同种子配对；`cost_report.md`及`cost_summary.json`列示主对比和最低时间表箱池参考；`control_pairs.json`列示固定策略成本对照。无可行解时成本留空，不作为零成本，也不能把启发式无解当作不可行证明。

输入文件、求解源码和每次运行预算均冻结；`independent_audit.json`重放容器、车辆与两周期闭合，`comparison_cost.json`保留成本分项。敏感性变体应按来源family配对分析，不能把全部运行当作独立样本。
