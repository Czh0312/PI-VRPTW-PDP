成本配置为 `config/cost/cases/truck_tricycle_pool25_truck0p5_clean02_v1.json`。一级距离系数由1降为0.5，其余费用保持：二级0.05647058823529412、箱池25、磨损25/50=0.5、追踪0.1、实际回库清洗0.2。目标为：

`C = 0.5 D1 + 0.05647058823529412 D2 + 25 N + 0.6 U + 0.2 R`。

其中U为累计发箱次数，R为实际回库箱次，N为实体箱池规模。完整回收时U=R=Q，后两项合计0.8Q。工时、车辆固定和趟次费仍为0。

M6、M7、M8的K默认允许所有正整数，不再受原输入日历批数限制。有限周期H及当前显式阶段最短时长m给出必要上界 `K ≤ floor(H/(2m))`。当前六例的H为780分钟、m为1分钟，允许域为1至390；其他路线、窗口、回收、清洗和资源约束继续判定各K的可行性。1分钟仍为可配置场景假设；修改m会重新推导上界。

M6/M7严格均分周期，不能整除原刻度的K也可以求解。每个K独立按 `K/gcd(H_ticks,K)` 细分时钟，已有绝对时刻、服务、路程耗时、清洗与装卸时间按相同比例缩放，物理分钟保持。没有对所有K取巨大公倍数。结果用 `time_tick_subdivision` 保存倍率；分钟等于 `ticks*time_tick_seconds/(60*time_tick_subdivision)`。独立审计重建该K的时钟并核验倍率、路线、两周期箱池和成本。M8继续在原整数时钟上优化不等长批次。

默认省略 `batch_count_candidates` 或设置为 `all_positive_integers`。历史显式K列表仍可复现原实验，CLI `--all-batch-counts` 可覆盖旧输入中的限制。精确法及ALNS继续共享一次调用的时间/迭代预算；扩大允许域不会自动增加预算，限时未运行的K不被宣称不可行，也阻止完整最优证明。

## 实验结果与搜索限制

本轮6例×5模型，ALNS每次预算上限300秒、1000000次迭代上限、seed42、4路进程；约27分钟完成。冻结312份源码和236份输入文件，结束后重新核验全部哈希并从保存路线独立复核。30/30有效，18/18联合求解返回其有效候选中最低费用方案。

M6–M8共18组中，7组返回K>3，10组实际多批并减箱；100-10-1的100点M8返回K=5、实际配送4批、箱池97（Q=161）、费用4155.18。六例中M8在5例费用最低，M3在1例最低；这是本轮有限搜索的结果，不是全局最优排序。

预算分配暴露出限制：初始每K约分得300/390=0.77秒；后续大K快速证明不可行后，剩余预算未回流到前面的K。M6/M7平均仅用54.07/55.34秒（18.0%/18.4%预算），M8约300秒但仍有10至76个K未运行。本轮没有中途修改冻结算法，完整保留这些搜索状态。

上一轮30条路线再次独立审计并按本轮0.5价格重计，本轮3组更低、27组更高。机器、代码和预算分配亦有变化，不能将差异全部归因于某一因素；结果表明目前搜索质量不足以支撑扩域后的模型优劣判断。后续应修正预算分配并另起实验，保留本轮原始结果。
