# 多批次 M5：自动逻辑 Benders 与完整排程恢复

本轮实现了可恢复的自动分解入口。完整整数主问题提出任务分组，物理子问题核验真实车辆串行及回仓时刻，独立复算通过的冲突或成本证书才能生成切割。20顾客冷缓存对照的三个种子均改善下界，其中一个达到原封存最好界；30顾客最终三个种子均自动恢复到原封存完整上界。**这些是自动化和冷启动能力的改进，20/30/50顾客的历史最好证书没有被替换，也未宣称完整 M5 严格最优。**

## 实现与使用

新增实现：[multibatch_logic_benders.py](../../models/routing/solvers/exact/multibatch_logic_benders.py)。M5 专属公开入口通过 `validate_problem` 后调用该模块，默认完整求解器路径不变。

```python
from models.routing.variants.model_5.exact import logic_benders_certificate

certificate = logic_benders_certificate(
    problem,
    initial_result=audited_result,
    time_limit=60,
    seed=42,
    recovery_time_limit=10,
    diagnostics_dir="output/m5_logic_benders_current",
)
# certificate["bound"]：完整域松弛的保守全局下界
# certificate["result"] / ["upper_bound"]：完整周期审计合格的方案及成本
# certificate["target_reached"]：达到数值 gap 目标，不是严格最优性证明
```

仅支持非空、固定仓、可循环箱的多批次 M5。`max_rounds=0` 是同一个完整整数主问题的无物理分解对照。`recovery_time_limit` 默认0，显式开启后尝试当前任务分组的全访问顺序完整排程，包含一级供货、回收、清洗库存和真实车辆；只接纳原业务审计合格且更好的上界。`target_gap` 默认 `1e-6`，使用比例值，即0.0001%。

本轮的主要连接和保护如下：

1. 主问题在内部枚举完整原路线域，所有路线选择整数化。时间和状态上限导致枚举未完成时，不输出新的正下界。`service_envelopes` 保持关闭。
2. 分离时先核验无供货条件的任务组，按任务组数量从少到多检查各仓；必要时再检查原一级供货下界及截止前回仓数量的上下界。这避免把简单车辆冲突绑在过于具体的供货条件上。
3. 物理子问题保留每组全部原允许访问顺序、未分组任务的原路径域、真实车辆及原整数时刻规则；一级路径和局部箱池只在下界子问题中放松，完整上界仍使用原业务规则。
4. 不可行冲突先删除供货/回收数量条件，再尝试删除任务组。每次删除必须重新证明不可行；限时未知保留上一份证明，不声称最小冲突。未完成的子问题不产生不可行割。
5. 条件成本割约束实际仓成本变量 theta，theta 同时支配压缩覆盖成本。不会把可执行日程成本强加到因成本支配而保留的便宜代表路线成本上。
6. 新物理证书导出 MPS 后由另一种子独立读取求解，只有再次确认不可行或支持完成的成本证书才接受；所有新切割另检查已审计完整方案的投影。全局界保留 `1e-7 * max(1, abs(raw_bound))` 的数值余量，物理界也保留相应余量。
7. 在耗费多个局部 oracle 前先尝试完整排程恢复。同一任务分组每次运行只恢复一次；已有审计上界和保守下界达到目标就停止。两个完整 M5 证明标志始终为 False。

缓存绑定有效业务输入、全部路由 Python 源码和 Gurobi 版本，记录条件、MPS 哈希、证书和独立复算结果。校验失败的记录拒绝使用；诊断目录与缓存都有排他锁。相同版本重跑恢复已经验证的切割，保存新的运行子目录，**不表示恢复 Gurobi 搜索树**。源码或输入改变后应使用新的诊断目录；独立缓存路径中的不同版本会自动隔离。

总预算计入枚举、建模、主问题、oracle、独立复算、冲突缩减与完整恢复，分离阶段给最后一次主问题保留余量。I/O 和求解器构建不能保证硬实时截止，结果同时报告实际耗时及超时量。

## 无收益尝试与修复

- 第一版直接核验具体供货/回收条件，20顾客三种子都接受了有效割，但60秒下界仍为1426.6489799399046，没有证书收益。结果保存在 [20_cold_v2/summary.json](../../output/experiments/m5_logic_benders_20261005/20_cold_v2/summary.json)，未删除负结果。
- 任务组优先版对30顾客仅做局部条件核验，三个种子均无新下界或上界；对应 `group_first` 的30顾客记录。
- 在局部核验后用5秒恢复，30顾客种子43/44达到封存最好上界，种子42未改善，出现更差但可审计的1942.1081606502935候选，未接纳。该次只剩约3.69秒恢复时间；结果保存在 [repair30/summary.json](../../output/experiments/m5_logic_benders_20261005/repair30/summary.json)。最终版将恢复提前并分配10秒，三个种子都成功；两个版本的快照分别保留。
- Gurobi12.0.3在本机 Darwin 对约290字符路径进行原生压缩 MPS 写出时触发 exit133。新模块改为短临时路径的原生未压缩 MPS I/O，再用 Python gzip 存储；长路径读写回归通过。
- 新切割投影保护最初读取尚未刷新的 Gurobi Start 值，已加 `model.update()`，并拒绝未定义的大值。
- 初版独立下界验证器使用默认相对 MIPGap，会提前停止而无法确认更强的报告界；复核器改为 `MIPGap=MIPGapAbs=0`。原失败日志和冻结驱动保留，`group_first` 由单独的 `qa_v2` 完成最终复核。
- 独立驱动最初缺少项目根目录的导入路径；失败的 `20_cold` 目录保留，修复后在新目录重做。
- 收尾哈希检查最初错误地把停止记录 manifest 当作所有历史阶段的 manifest；改用本轮开始哈希、对应阶段 manifest、完整上界引用哈希和停止记录分别核验。未改变任何历史证书。

## 可恢复材料与后续限制

实验根目录：[m5_logic_benders_20261005](../../output/experiments/m5_logic_benders_20261005)。每组有原输入和初解副本、参数、冻结源码、顺序工作日志、结果、主问题MPS、物理证明缓存、完整固定投影、检查点和哈希 manifest。总检查点：[checkpoint.json](../../output/experiments/m5_logic_benders_20261005/checkpoint.json)；最终自己的新增源码和测试另存 `source_snapshot_final`。

可重复运行审计驱动：

```sh
.venv/bin/python tools/audit/benchmark_multibatch_logic_benders.py \
  --output output/experiments/m5_logic_benders_new_run \
  --cases 30 --seeds 42 43 44 --time-limit 60 --recovery-time 10
```

输出目录必须不存在，避免覆盖旧证据。该命令会从原封存输入取同初解，先顺序测量控制/处理，再独立验证；验证耗时额外计入实际工作量，不混入60秒求解预算。

本轮只证明这两个原冻结输入的自动流程有效，不能据此宣称任意50顾客或更大实例都能在60秒收敛。20顾客仍有种子差异，枚举和大物理子问题也可能耗尽预算。下一步适合在不同原输入上测稳定性，依据失败分组把预算分配给困难仓；更大任务域再接入严格有效的定价机制。严格数学最优性需要进一步的数值/数学证书，不能取消余量获得。
