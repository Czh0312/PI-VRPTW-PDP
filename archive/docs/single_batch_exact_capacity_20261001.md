# 单批 M1–M4 第七轮：根节点容量割

本轮保持有限车队、每车趟数、整数时间、业务时间窗、全部配送/回收任务、距离目标与零 MIPGap。
新增约束是完整模型的有效不等式，不改变整数可行域，也不以初解构造范围代替精确搜索范围。

## 数学依据

对任意二级任务子集 U，分别求其中配送任务的总重量/体积 Dw、Dv，以及回收任务的总重量/体积 Pw、Pv。
每趟配送货物在出发时全部装车，每趟回收箱在回仓时仍在车上，因此与 U 相交的路线数至少为

`r(U) = max(1, ceil(Dw/Qw), ceil(Dv/Qv), ceil(Pw/Qw), ceil(Pv/Qv))`。

配送与回收必须分别取界，不能将两者需求相加再取整。一条路线允许配送后利用腾出的空间回收。
计算时将容量略微放宽 `max(1e-6, |Q|*1e-12)` 后取整，避免浮点边界导致过强的取整。

每条与 U 相交的非空路线至少有一次进入 U。全部任务的入度为1，因此

`sum(x[a,b] for a,b in U) <= |U| - r(U)`。

路线多次进出 U 只会使内弧数更少；证明不要求对称距离、三角不等式或正行驶时间。
配送与回收可以分属不同趟次。自由分仓下，每项任务仍有唯一执行路线，故同一证明成立。
在共享内部弧与原索引弧模型中，分别使用全局二元弧和原索引弧的二元合计变量。

## 实现与默认范围

`models/routing/solvers/exact/single_batch_cuts.py` 生成有界的候选集合：整个订单集合、固定分仓的各仓集合、
小集合的订单对、若干邻近订单集合和按截止时间排列的连续集合。候选选择影响强化程度，不影响有效性。
回调只在根节点完成的 LP 松弛上提交被违反的割，每次最多20条；后续树节点不进行 Python 候选扫描。
候选生成受原建模截止控制，回调异常沿用 `CAPACITY_CUT_ERROR`，不得报告最优/不可行证明。
`capacity_cut_candidates` 与 `capacity_cuts_added` 分别记录候选数量和已提交数量；提交不保证求解器始终保留该割。

最终默认只对**已经使用内部弧压缩的含回收模型**启用完整订单配送/回收任务对的容量割。
小型索引模型和纯配送模型保留原默认路径。`single_batch_formulation.build_model(..., capacity_cuts=False)` 可关闭；
`True`/`'all'`、`'tasks'`、`'pairs'` 用于显式对照。默认 `None` 按上述结构选择 `'pairs'` 或关闭。

没有根据单个案例的结果逐行挑选求解器。采用完整候选配置做对照，再按既有“索引/压缩”模型结构选择默认范围。

## 独立验证

新增回归测试覆盖：

- 6项任务的720种排列与每种排列的32种分趟方式，共23,040种组合；直接计算每趟出发与沿途载荷，
  所有容量可行的组合必须满足每条候选割。这个检查不使用 MILP、初解构造、距离界或割的取整函数来判断路线可行性。
- M1–M4、零行驶时间和有向非度量网络、紧容量案例，分别强制索引/压缩模型与容量割，最优值与独立小实例枚举一致。
- 已审计的跨趟配送/回收初解，在把全部候选作为静态约束加入模型后仍可扩展成可行 MILP 解。
- 配送/回收需求分别取整、零箱重/体积、浮点容量边界、默认启用范围、根节点之外不扫描、建模截止与回调异常。

共享的 `solver.py` / `formulation.py` 在本轮期间另有 M5聊天更新：增加结构统计和多批弧压缩。
本轮未编辑这两个文件；B=1 分发与求解行为相同，实验原始代码快照保留这一区别。

## 完整流程：24个案例、每例10秒

基线与最终默认配置均运行整套24个冻结输入，Seed=42、Threads=1、总求解预算10秒，阶段内顺序运行；
先完成基线，再运行最终配置，不挑选单个案例的最好运行。每个工作进程另有20秒启动/输出保护。

两阶段均有24个已审计可行解、24个通过两周期重放的方案、16个最优性证明，生产对照无错误。
24个案例的距离均相同，没有距离退步，也没有损失最优证明。
